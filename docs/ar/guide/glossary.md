# المصطلحات الأساسية بكلمات بسيطة

كل مصطلح مستخدم في هذا التوثيق، مشروحًا دون لغة متخصّصة، مع رابط إلى الصفحة التي تفصّله. المصطلحات مجمّعة حسب الموضوع؛ استخدم مربع البحث (<kbd>/</kbd>) للانتقال مباشرةً إلى أحدها.

## الأساسيات {#the-basics}

| المصطلح | بكلمات بسيطة |
| --- | --- |
| **حزمة تطوير البرمجيات (SDK)** | صندوق أدوات للمطوّرين: شيفرة تضيفها إلى تطبيقك بدل أن تكتب كل شيء بنفسك. هذه الحزمة مكتوبة بلغة TypeScript؛ وهي غير منشورة على npm بعد وتُثبَّت من GitHub (انظر [البدء](./getting-started)). |
| **النموذج اللغوي (LLM)** | الذكاء الاصطناعي الذي يقرأ النص ويكتبه (GPT-4o، Claude…). هنا هو مكوّن من بين مكوّنات أخرى: هو يقترح، وحزمة SDK تتحقّق وتقرّر ما هو مسموح به. |
| **الموجّه (Prompt)** | التعليمات النصية المُرسَلة إلى النموذج اللغوي مع كل طلب. |
| **الرمز (Token)** | جزء من كلمة. يحاسب مزوّدو النماذج على كل رمز يُقرأ ويُكتب، ولهذا تُحسَب [التكاليف](./costs) بالرموز. |
| **الوكيل (Agent)** | برنامج يستخدم نموذجًا لغويًا لبلوغ هدف، خطوة بخطوة. في حزمة SDK نوعان: [الوكلاء الخاضعون للحوكمة](./governed-agents) الذين يتصرّفون بالأدوات، و[الوكلاء المعرفيون](./cognitive-agents) الذين يستدلّون قبل أن يستنتجوا. |
| **التشغيل (Run)** | تنفيذ واحد لوكيل على مشكلة واحدة، من البداية إلى النهاية. له معرّف (`runId`) تستخدمه لقراءته أو إعادة تشغيله أو حساب تكلفته. |
| **الأداة (Tool)** | دالة تعطيها شيفرتك لوكيل (قراءة قاعدة بيانات، إرسال بريد إلكتروني…). لا يستطيع الوكيل استخدام إلا الأدوات التي أُعطيت له صراحةً. انظر [المفاهيم الأساسية](./concepts#_2-tool). |
| **القدرة (Capability)** | مجموعة مُسمّاة من الأدوات يمكنك إعطاؤها لعدة وكلاء دفعة واحدة. |
| **السياسة (Policy)** | قاعدة تُفحَص **قبل** كل إجراء: ميزانية، أو مهلة زمنية، أو قائمة بالأدوات المسموح بها، أو فحص خاص بك. |
| **الموافقة (Approval)** | توقّف قبل إجراء محفوف بالمخاطر إلى أن يقول إنسان نعم. يمكن أن تطلبها سياسة، أو الأداة نفسها (`requiresApproval`)؛ وإذا تخلّى المستدعي أولًا، فلن يُنفَّذ الإجراء أبدًا. |
| **النيّة (Intention)** | ما *يريد* نموذج الوكيل الخاضع للحوكمة أن يفعله (استدعاء أداة، الإجابة…)، مكتوبًا لكن غير منفَّذ: تتحقّق منه حزمة SDK أولًا. |
| **المخطط (Schema، Zod)** | وصف دقيق للشكل الذي يجب أن تكون عليه البيانات. تُفحَص استدعاءات الأدوات والردود المهيكلة لخطوات الاستدلال مقابل مخطط؛ ويُرفَض الرد الذي لا يطابقه. |
| **JSON** | صيغة نصية بسيطة للبيانات المهيكلة. الملفات الشخصية والأحداث وردود النماذج كلها بصيغة JSON. |

## التتبّع {#traceability}

| المصطلح | بكلمات بسيطة |
| --- | --- |
| **الحدث (Event)** | سطر في سجل اليوميات: «هذا حدث، في هذا الوقت». كل خطوة من كل تشغيل تُسجَّل حدثًا. انظر [فهرس الأحداث](../reference/events). |
| **مخزن الأحداث (Event store)** | المكان الذي يُحفَظ فيه سجل اليوميات: مجلد ملفات، أو SQLite، أو PostgreSQL. |
| **الاستناد إلى الأحداث (Event sourcing)** | القاعدة التي تجعل سجل اليوميات هو الحقيقة: حالة التشغيل، بما فيها حالته الذهنية، يُعاد بناؤها بإعادة قراءة أحداثه، ولا تُخزَّن منفصلة أبدًا. هذا ما يجعل كل تشغيل قابلًا للتدقيق بعد أشهر. ملف المفكّر هو الاستثناء: لا تسجّل الأحداث إلا معرّفه وإصداره، فاحفظ الملف نفسه. |
| **الأثر (Trace)** | جميع أحداث تشغيل واحد، بالترتيب. |
| **إعادة التشغيل (Replay)** | إعادة تنفيذ تشغيل مُسجَّل انطلاقًا من أحداثه: تُنفَّذ الإجراءات التي قرّرها من جديد، عبر السياسات نفسها، دون سؤال النموذج اللغوي مرة أخرى. مفيدة لتدقيق تشغيل أو لاختبار «ماذا لو» بعد تغيير سياسة. انظر [التتبّع وإعادة التشغيل](./observability). |
| **الأثر المرجعي (Golden trace)** | تشغيل جيّد تحتفظ به مرجعًا؛ تُفحَص عمليات التشغيل الجديدة مقابله، فيُكتشَف تغيّر السلوك كما يُكتشَف اختبار فاشل. |

## كيف يستدل الوكيل المعرفي {#how-a-cognitive-agent-reasons}

| المصطلح | بكلمات بسيطة |
| --- | --- |
| **الحالة الذهنية (Mental state)** | كل ما «يدور في ذهن» الوكيل حاليًا بشأن المشكلة، مكتوبًا في صورة بيانات: ما لاحظه، وما يعرفه، وما يفترضه، وما لا يعرفه، والخيارات التي يدرسها. انظر [الحالة الذهنية](./cognitive-agents#the-mental-state). |
| **الملاحظة (Observation)** (`O1`…) | شيء شوهد: قياس أو مستند قدّمته مع المشكلة، أو نتيجة أداة، أو نتيجة اختبار. |
| **الحقيقة (Fact)** (`F1`…) | عبارة يعدّها الوكيل صحيحة، مع مصدرها. لا تُحذَف الحقيقة أبدًا: بل *تُسحَب* (retracted) أو *تُستبدَل* (superseded)، مع ذكر السبب. |
| **الافتراض (Assumption)** (`A1`…) | شيء يسلّم به الاستدلال دون برهان. |
| **القيد (Constraint)** (`K1`…) | شيء يجب أن تحترمه أي إجابة («قبل الربع الرابع»، «أقل من 10 آلاف يورو»). |
| **المجهول (Unknown)** (`U1`…) | سؤال مفتوح. يمكن أن *يُحَلّ* (resolved، أي تُعرَف إجابته) أو أن *يُسقَط* (dropped، إذ لا سبيل إلى الإجابة عنه). |
| **الفرضية (Hypothesis)** (`H1`…) | خيار قيد الدراسة. وهي من أحد ثلاثة أنواع: **مقترح** (proposal، اختيار إجراء: «رفض المهمة»)، أو **قاعدة** (rule، انتظام: «زمن التدحرج لا يعتمد على الكتلة»)، أو **تفسير** (explanation، سبب). |
| **الاستقراء، والاستدلال بأفضل تفسير، والاستنباط (Induction، abduction، deduction)** | ثلاث طرق للوصول إلى فرضية: من حالات متكرّرة إلى قاعدة؛ ومن مفاجأة إلى سببها الأرجح؛ ومن قاعدة إلى ما يجب أن يترتّب عليها. التسمية مُعلَنة، ولا تجعل الادعاء صحيحًا. |
| **العملية (Operation)** | حركة استدلال واحدة: تمثيل المشكلة، ووضع فرضية، والمحاكاة، والنقد، والمقارنة، والقرار… وهي عشر عمليات. انظر [العمليات](./cognitive-agents#the-operations). |
| **المتحكّم (Controller)** | ما يختار العملية التالية. المتحكّم **الإرشادي** (heuristic) يتبع ترتيبًا ثابتًا، مجانيًا ومتوقَّعًا؛ والمتحكّم **المُنمَّط** (typed) يسأل Jev عند كل خطوة. |
| **رقعة التفكير (Thought patch)** | ما غيّرته عملية واحدة في الحالة الذهنية، مُسجَّلًا حدثًا واحدًا. الحالة الذهنية هي كل الرقع مطبّقة بالترتيب. |
| **المحاكاة (Simulation)** | تخيّل ما سيحدث لو كانت الفرضية صحيحة: الآثار المباشرة، ثم غير المباشرة. |
| **النقد (Critique)** | مهاجمة الوكيل لخياره نفسه: أقوى سبب قد يجعله يفشل. النقد **القاتل** (fatal) الذي لا جواب عنه يرفض الخيار. |
| **التناقض (Contradiction)** (`C1`…) | أمران لا يمكن أن يكونا صحيحين معًا. يبقى مفتوحًا إلى أن يُحسَم بالاستشهاد بالملاحظات أو الحقائق التي تحسمه. |
| **الصيغة المعدّلة (Variant)** | نسخة مصحَّحة من فرضية ناقضتها الأدلة، بنطاق أضيق أو بشرط مضاف، مع جملة تقول ما الذي تغيّر. |
| **الحدود (Limits)** | ميزانية التشغيل: عدد الخطوات، والوقت، واستدعاءات الأدوات، والاختبارات، وعتبات الاستنتاج. انظر [الحدود](./cognitive-agents#limits). |

## الأدلة والاستنتاجات {#evidence-and-conclusions}

| المصطلح | بكلمات بسيطة |
| --- | --- |
| **المنشأ (Provenance)** | من أين يأتي الدليل: قدّمته أنت، أو أعادته أداة، أو قاسه اختبار، مع الحدث الذي يحتفظ بالأصل. |
| **مجموعة المنشأ (Origin group)** (`originGroup`) | وسم يعني «المصدر نفسه». ملاحظتان من المنشأ نفسه ليستا تأكيدين مستقلين. |
| **المكرَّر (Duplicate)** | المحتوى نفسه من المنشأ نفسه، شوهد مرة أخرى. لا يضيف أي وزن. |
| **التنبؤ (Prediction)** (`P1`…) | ما يجب أن يُلاحَظ إذا كانت الفرضية صحيحة، مُسجَّلًا **قبل** اختبارها. |
| **المُفنِّد (Falsifier)** | الملاحظة التي ستثبت خطأ الفرضية. الادعاء الذي لا يمكن إثبات خطئه لا يمكن اختباره. |
| **المعرفة (Knowledge)** (`M1`…) | ما أثبتته عمليات تشغيل سابقة باختبارات حقيقية، ويُستدعى في بداية التشغيل: *مُتحقَّق منها* (verified)، أو *مدحوضة* (refuted)، أو *متنازَع عليها* (contested) حين تختلف الاختبارات. انظر [الذاكرة عبر عمليات التشغيل](./memory). |
| **النطاق (Scope)** | حدود الذاكرة: لا تتشارك عمليات التشغيل ما تعلّمته إلا داخل النطاق نفسه، مثل منصة اختبار واحدة أو منتج واحد. |
| **مقيِّم النتائج (Outcome evaluator)** | شيفرتك التي تواجه التنبؤ بالواقع (قياس، أو محاكٍ، أو مجموعة اختبارات) وتجيب بـ *مؤكَّد* (confirmed) أو *مدحوض* (refuted) أو *غير حاسم* (inconclusive). لا يقيّم النموذج اللغوي تنبؤاته بنفسه أبدًا. انظر [التنبؤات](./evidence-and-verification#predictions-and-the-outcome-evaluator). |
| **الدعم (Support)** | مدى قوة الأدلة في تأييد فرضية، من 0 (مدحوضة) إلى 1 (ثابتة). إنه حكم تقديري، لا احتمال مَقيس. لا تخلط الشيفرة التفضيلات به أبدًا؛ ومع حَكَم من نموذج لغوي، يعتمد ذلك على تعليماته (انظر [الأدلة ليست تفضيلات](./evidence-and-verification#evidence-is-not-preference)). |
| **ملاءمة التفضيلات (Preference fit)** (`preferenceFit`) | مدى ملاءمة اختيار إجراءٍ للمفكّر، من 0 (يستوفي أحد معايير الرفض لديه) إلى 1 (مثالي). لا تحصل عليها إلا اختيارات الإجراءات. |
| **الترتيب (Ranking)** | ترتيب الخيارات. تُرتَّب الادعاءات بالدعم وحده؛ وتُرتَّب اختيارات الإجراءات بنسبة 60% للدعم و40% لملاءمة التفضيلات، افتراضيًا. |
| **المتقادم (Stale)** | تقييم أُجري قبل آخر تغيّر في الأدلة. يجب إعادته قبل الاستنتاج. |
| **حارس الاستنتاج (Conclusion guard)** | الفحوص المكتوبة بالشيفرة التي يجب أن تجتازها الإجابة لتُعتمَد: أن تكون قد نُقدت، وقُيِّمت منذ آخر دليل جديد، وألا يكون هناك تناقض مفتوح يخصّها، وألا يبقى تنبؤ دون اختبار ما دامت الميزانية تسمح باختبارات، وأن يكون الدعم كافيًا. انظر [حارس الاستنتاج](./evidence-and-verification#the-conclusion-guard). |
| **عتبة القرار (Decision threshold)** | الدعم الذي تحتاجه الإجابة الحاسمة: 0.75 افتراضيًا، أي «مدعومة بقوة». واختيار الإجراء الذي يفضّله المفكّر بوضوح لا يحتاج إلا إلى 0.35. |
| **المُعتمَدة (Committed)** | إجابة حاسمة اجتازت حارس الاستنتاج. |
| **المؤقّتة (Provisional)** | أفضل إجابة متاحة حين نفدت الميزانية، مع قائمة ما لم يثبت بعد (`missing`). |
| **الامتناع (Abstain)** | «لا أستطيع الاستنتاج»، مع الأسباب. نتيجة صالحة، لا خطأ. |
| **الثقة (Confidence)** | مدى يقين القرار، ولا تكون أبدًا أعلى من دعم الأدلة للخيار المختار. |

## محاكاة استدلال شخص ما {#imitating-a-person-s-reasoning}

| المصطلح | بكلمات بسيطة |
| --- | --- |
| **ملف المفكّر (Thinker profile)** | وصف **لكيفية** استدلال شخص معيّن: الترتيب الذي ينظر به إلى المشكلة، وأولوياته، وردود أفعاله، ومعايير الرفض لديه، وميله إلى المخاطرة. يُكتَب في تعليمات كل خطوة استدلال، وبهذه الطريقة يحاكي الوكيل استدلال ذلك الشخص. انظر [ملفات المفكّرين](./thinker-profiles). |
| **العيّنة (Sample)** | موضوع واحد شرحه الشخص بكلماته الخاصة: الموضوع، وكيف استدل، وإلى ماذا خلص. |
| **الاستخلاص (Distill)** | استخراج ملف من العيّنات: إيجاد ما يتكرّر في طريقة استدلال الشخص عبر المواضيع. |
| **ترتيب الانتباه (Order of attention)** (`reasoningSequence`) | الخطوات التي يمرّ بها الشخص، بالترتيب. |
| **القاعدة الإرشادية (Heuristic)** | ردّ فعل، يُكتَب بصيغة «عندما …، فإن …». |
| **معيار الرفض (Rejection criterion)** | سبب يجعل الشخص يتخلّى عن فكرة. |
| **الحُكم (Verdict)** | حكم الشخص على تشغيل: `match` (استدل مثلي)، أو `partial` (جزئيًا)، أو `mismatch` (لا يطابق). |
| **الاتفاق (Agreement)** | القدر الذي يتفق معه الشخص من التشغيل، من 0 إلى 1: القيمة `0.8` تعني «صحيح بنسبة 80%». بها تقيس مدى اقتراب المحاكاة. |
| **مثال المعايرة (Calibration example)** | تشغيل صادق عليه الشخص، يُعرَض على النموذج بوصفه إجابة نموذجية. |
| **التصحيح (Correction)** | درس من تشغيل لم يتفق معه الشخص، يُعرَض على النموذج بوصفه أولويته القصوى. |

## الدراسات {#studies}

| المصطلح | بكلمات بسيطة |
| --- | --- |
| **الدراسة (Study)** | باحث من الذكاء الاصطناعي (`sdk.createStudy`): يفهم موضوعًا، ثم يقترح كيف يُعاد تصميمه بمعارف اليوم وتقنياته، ويصمّم التجارب التي من شأنها أن تحسم. لا يبني شيئًا ولا يقيس شيئًا. انظر [الدراسات](./studies). |
| **المرحلة (Passage)** | واحدة من المراحل السبع للدراسة: الملاحظة، والتفكيك، وفهم خيارات زمنها، وفحص ما تغيّر، ومقاطعة الماضي بالحاضر، والتصميم، والمواجهة. ويمكن لمرحلة أن تعيد فتح مرحلة سابقة. |
| **الميثاق (Charter)** | إطار الدراسة: الموضوع، والسؤال الموجِّه، والهدف، والاحتياجات، وخيوطك، وما هو خارج النطاق. يُجمَّد عند إنشاء الدراسة، ويبدأ به كل موجّه. |
| **الخيط (Lead)** | فكرة تعطيها للدراسة لتبحث فيها. إنه مثال يجب التحقّق منه، لا حقيقة: تقول الدراسة ما إذا كان ذا صلة، مع الأسباب، وتبحث فيما يتجاوزه. |
| **حالة الادعاء (Claim status)** | قيمة عبارة من عبارات الدراسة: **مُثبَت** (established، يسنده مصدر عثرت عليه الدراسة فعلًا)، أو **فرضية** (hypothesis، معقولة وغير موثّقة)، أو **جِدّة** (novelty، فكرة جديدة يجب التحقّق منها مقابل الأعمال القائمة). الشيفرة هي التي تتحقّق منها، لا النموذج. انظر [مُثبَت، فرضية، جِدّة](./studies#established-hypothesis-novelty). |
| **الأعمال السابقة (Prior art)** | العمل الموجود الأقرب إلى فكرة مقدَّمة على أنها جديدة. تبقى الجِدّة «للتحقّق» إلى أن تبحث عنها الدراسة. |
| **الحارس (Guardian)** | فحص منفصل بعد كل مرحلة من مراحل الدراسة: لا يرى إلا الميثاق وما أنتجته المرحلة، ويحذف ما يشرد عن الهدف. انظر [الحارس](./studies#the-guardian). |
| **الانحراف، سجلّ الانحراف (Drift، drift log)** | الانحراف هو ابتعاد النموذج عن موضوعه شيئًا فشيئًا. ويسرد سجلّ الانحراف كل ما حذفته الدراسة لهذا السبب، ولماذا. |
| **التعديل (Amendment)** | تعليمة تُضاف إلى الدراسة بعد إنشائها. لا يُقبَل إلا إذا كان يدقّق الهدف؛ أما التعديل الذي يناقض الميثاق أو يغيّر الهدف فيُرفَض. |
| **القدرة الجديدة (New capability)** | شيء يصير ممكنًا، وهو اليوم صعب أو مستحيل، بفضل تغيير في المبدأ — في مقابل **التحسين** (improvement)، الذي لا يفعل سوى جعل شيء أسرع أو أرخص. |
| **الاختراق بالتركيب (Breakthrough by assembly)** | اختراق مصنوع من تقنيات كانت موجودة من قبل، جُمعت بطريقة جديدة. Bitcoin مثال على ذلك: التواقيع، وسلاسل التجزئة، وإثبات العمل، وشبكة الند للند، كانت كلها معروفة من قبل. |
| **بطاقة الآلية (Mechanism card)** | أحد عشر سؤالًا عن آلية واحدة، من الذي لوحظ إلى الذي استُنتج. تجيب الدراسة عن التسعة الأولى؛ وتجيب أنت عن الأخيرين بعد أن تُجري التجربة. |

## القرارات المُنمَّطة والموصِّلات {#typed-decisions-and-connectors}

| المصطلح | بكلمات بسيطة |
| --- | --- |
| **Jev** | نموذج من TypeSafe يجيب عن الأسئلة الضيقة (نعم/لا، اختيار، تقييم) باحتمالات يمكن لشيفرتك استخدامها، بسرعة وبتكلفة منخفضة. انظر [القرارات المُنمَّطة](./typed-decisions). |
| **Noul، Choice، Score** | أنواع أسئلة Jev الثلاثة: نعم أو لا؛ خيار واحد من قائمة؛ مستوى على مقياس. اختيار عدة خيارات يطرح سؤال نعم/لا لكل خيار. |
| **المعايَر (Calibrated)** | احتمال يطابق الواقع في المتوسط: من بين الإجابات المعطاة بثقة 80%، نحو 80% منها صحيحة. |
| **AI Gateway** | خدمة من Vercel تتيح الوصول إلى عدة نماذج، ومنها Jev، بمفتاح واحد. |
| **MCP** | بروتوكول سياق النموذج (Model Context Protocol): «مقبس» قياسي واحد بين تطبيقات الذكاء الاصطناعي (Claude Desktop، وClaude Code، ومساعدات بيئات التطوير، والوكلاء) وأنظمتك. تستطيع حزمة SDK تحويل دالة، أو واجهة API على الويب، أو مجلد، أو قاعدة بيانات، أو وكيل إلى خادم MCP، واستخدام أدوات أي خادم MCP. انظر [MCP بكلمات بسيطة](./mcp). |
| **خادم MCP (MCP server)** | برنامج صغير أمام أحد أنظمتك يخبر تطبيقات الذكاء الاصطناعي بما يقدّمه وينفّذ العمل عند الطلب. انظر [أول خادم MCP لك](./mcp-first-server). |
| **عميل MCP، المضيف (MCP client، host)** | المضيف هو تطبيق الذكاء الاصطناعي الذي يتحدّث إليه المستخدم؛ وفي داخله، يحتفظ عميل MCP بالاتصال بخادم واحد. |
| **المورد (Resource)** | مستند يعرضه خادم MCP للقراءة، مثل ملف في مجلد مشترك. بخلاف الأداة، يختاره المستخدم أو التطبيق، لا النموذج. |
| **وسيلة النقل (Transport)** | الطريقة التي يتبادل بها تطبيق MCP والخادم الرسائل: **stdio** (يشغّل التطبيق الخادم برنامجًا على الحاسوب نفسه ويتحدّث معه عبر مدخلاته ومخرجاته) أو **Streamable HTTP** (الخادم خدمة ويب). انظر [stdio أم HTTP؟](./mcp-deploy#stdio-or-http). |
| **OpenAPI** | وصف قياسي قابل للقراءة آليًا لواجهة API على الويب: عناوينها ومعاملاتها وإجاباتها، يُنشَر غالبًا بالاسم `openapi.json`. انطلاقًا منه، تصنع حزمة SDK أداة لكل عملية. انظر [واجهة API على الويب](./mcp-recipes#a-web-api-from-its-openapi-description). |
| **JSON Schema** | وصف لشكل بيانات ما — هنا، معاملات أداة — تقرؤه النماذج وتطبيقات MCP لاستدعاء الأداة استدعاءً صحيحًا. تكتبه حزمة SDK انطلاقًا من مخطط Zod الخاص بك أو من وصف OpenAPI. |
| **للقراءة فقط (Read-only)** | يمكنه الاطلاع، ولا يمكنه التغيير. مصدرا المجلد وقاعدة البيانات للقراءة فقط بحكم بنائهما؛ وواجهات API على الويب للقراءة فقط افتراضيًا (عمليات `GET` فقط). |
| **مصدر الأدوات (Tool source)** | دالة تبني أدوات جاهزة من نظام ما: `openApiTools`، و`folderTools`، و`databaseTools`، و`webTools`، و`governedAgentTool`، و`cognitiveAgentTool`، و`connectMcpServer` لأدوات أي خادم MCP. قدّمها عبر MCP في سطر واحد، أو أعطها لوكلائك. انظر [الأدوات](./tools)، و[خادم MCP لأيّ شيء](./mcp-recipes)، و[البحث على الويب](./web-research). |
