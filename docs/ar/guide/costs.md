# تكاليف API

تسجّل حزمة SDK استهلاك الرموز (tokens) لكل استدعاء للنموذج **في التشغيل الذي أجراه** — اختيار الأدوات، والأفكار المعرفية، والقرارات المُنمَّطة — وتسعّره لكل نموذج. ويُحتسَب الاستدعاء بمجرّد أن يجيب عنه المورّد، حتى لو أفشلت حزمة SDK الخطوة بعد ذلك بسبب تلك الإجابة (انظر [الاستدعاءات الفاشلة](#failed-calls)).

```ts
const cost = await sdk.getRunCost(runId);
```

## الأسعار {#prices}

تتغيّر أسعار النماذج اللغوية كثيرًا وتعتمد على عقدك، لذا فهي **إعدادات، لا شيفرة**. لا تُوزَّع قيمًا افتراضيةً إلا الأسعار التي تم التحقّق منها مقابل توثيق المورّدين — واليوم، سعر Jev (0.042 دولار لكل مليون رمز مُدخَل، والمُخرَجات مجانية، تم التحقّق في 2026-09-23)، سواء تحت معرّفاته في TypeSafe (`jev-*`) أو عبر Vercel AI Gateway (`typesafe-ai/jev`).

```ts
const sdk = createSDK({
  apiKey,
  pricing: {
    // Illustrative values: use your provider's current prices or your contract.
    'gpt-4o': { inputPerMillion: 2.5, outputPerMillion: 10 },
    'gpt-4o-mini': { inputPerMillion: 0.15, outputPerMillion: 0.6 },
  },
});
```

المفاتيح معرّفات نماذج دقيقة أو بادئات تنتهي بـ `*`. كثيرًا ما يجيب المزوّدون بمعرّف ذي إصدار (`gpt-4o-2024-08-06`) بينما طلبت `gpt-4o`: تسجّل حزمة SDK الاثنين وتبحث أولًا عن المعرّف المُعاد، ثم عن الاسم المطلوب — المفاتيح الدقيقة قبل البادئات، والبادئة الأطول هي التي تفوز. انتبه للبادئات: `gpt-4o*` يطابق أيضًا `gpt-4o-mini` ما لم يوجد `gpt-4o-mini*`.

## التكاليف المجهولة {#unknown-costs}

لا تخترع حزمة SDK سعرًا أبدًا، ولا عددًا من الرموز. تكون كلفة الاستدعاء مجهولة في حالتين، ويصرّح التقرير بذلك:

- **لا سعر لنموذجه**: تظل استدعاءاته ورموزه محسوبة، ويُدرَج النموذج في `unpricedModels`، وتلك الاستدعاءات في `unpricedCalls`، ولا يحمل سطره `costUsd`؛
- **لم يُبلِغ عن أي عدد من الرموز** — لا رموز الإدخال ولا رموز الإخراج، كما مع مزوّد لا يُعيد الاستهلاك أو يُعيد مجموعًا فقط: يُحتسَب في `unmeteredCalls` (وفي `unmeteredCalls` الخاص بسطره)، ونموذجه في `unmeteredModels`. ولا يُعَدّ أبدًا استدعاءً بصفر رموز.

يُعَدّ الاستدعاء الذي لا عدد لرموزه غير مَقيس حتى لو كان لنموذجه سعر، كما تحتسبه الميزانيات. وما إن تصبح كلفة أي استدعاء مجهولة حتى يُوسَم التقرير بـ `complete: false`، ولا يجمع `totalUsd` إلا الاستدعاءات المعروفة الكلفة: فهو حدّ أدنى، لا كلفة التشغيل.

## الاستدعاءات الفاشلة {#failed-calls}

الاستدعاء الذي أجاب عنه المورّد تُدفَع كلفته، أيًّا كان ما تفعله حزمة SDK بالإجابة بعد ذلك. ويُسجَّل ويُحتسَب — في أحداث التشغيل، وفي `getRunCost`، ولدى الوكلاء الخاضعين للحوكمة في الميزانيات لكل فترة وفي `maxTokens` الخاص بالتشغيل — حتى حين تفشل الخطوة بسببه:

- استدعاء أداة لدى وكيل خاضع للحوكمة وسائطه ليست JSON صالحًا: يُسجَّل `intention.generated` قبل قراءة الإجابة؛
- فكرة معرفية لا تجتاز إجابتُها التحقّق، بما في ذلك الإصلاحات، وعملية قطعها `stop()` أو المهلة الزمنية للتشغيل بعد محاولات مدفوعة (`cognition.operation_failed` مع `usage` الخاص بها، و`decision.evaluated` لطلبات القرارات المُنمَّطة التي تلقّت إجابتها)؛
- قرار مُنمَّط لا تطابق إجابتُه أسئلته (اختيار ليس من الخيارات، أو إجابة ناقصة أو من نوع خاطئ): `decision.evaluated` مع `error` و`answers` فارغة، ثم تُطلِق `sdk.decisions` الخطأ، ويلجأ الوكيل المعرفي إلى البديل كما من قبل؛
- إجابة يتجاهلها المزوّد: إجابة من OpenAI بلا أي خيار، تُفشِل الاستدعاء أو تجعل مزوّدًا احتياطيًا يتولّى الأمر (`provider.answer_discarded`).

المحاولة التي فشلت دون إجابة — خطأ HTTP، أو انتهاء المهلة، أو انقطاع الاتصال، أي ما تعالجه إعادة المحاولة والتحويل إلى البديل — لا تُبلِغ عن أي استهلاك ولا تُحتسَب. والإجابة التي تعذّر استخدامها كليًّا (المُتجاهَلة، أو التي ليست متنَ قرار صالحًا) لا تُحتسَب إلا إذا أبلغ المورّد عن استهلاكها.

## من أين يأتي الاستهلاك {#where-usage-comes-from}

| الحدث | المصدر | الحقول |
| --- | --- | --- |
| `intention.generated` | الاستدلال الأصيل، واختيار الأدوات | `model`، `requestedModel`، `usage.promptTokens`، `usage.completionTokens` |
| `provider.answer_discarded` | إجابة لم يستطع المزوّد استخدامها | `provider`، `model`، `usage` |
| `cognition.thought` | العمليات المعرفية، بما فيها الإصلاحات والمحاولات الفاشلة | `model`، `requestedModel`، `usage.calls`، `usage.unmeteredCalls` |
| `cognition.operation_failed` | عملية قطعها إيقاف أو انتهاء مهلة بعد محاولات مدفوعة | `model`، `requestedModel`، `usage` |
| `decision.evaluated` | Jev وغيره من الواجهات الخلفية للقرارات المُنمَّطة، بما فيها الإجابات المرفوضة | `model`، `usage.inputTokens`، `usage.outputTokens` |

وتُسجَّل الإجابة النهائية لتشغيل معرفي أيضًا حدثًا من نوع `intention.generated` (`source: 'cognition'`): فهي ليست استدعاءً للنموذج ولا تُحتسَب.

لأن الاستهلاك موجود في الأحداث، يمكنك أيضًا حساب التكاليف بنفسك بـ `computeRunCost(runId, events, pricing)`، وتجميعها لكل وكيل أو لكل يوم، أو تغذية نظام الفوترة لديك بها.

## الميزانيات {#budgets}

التكلفة جانب واحد فقط؛ إذ يمكن للسياسات أيضًا وضع سقف لـ **الخطوات والرموز واستدعاءات الأدوات** لكل وكيل وأداة وفترة — انظر [الوكلاء الخاضعون للحوكمة](./governed-agents). وللوكلاء المعرفيين حدودهم الخاصة (`maxSteps`، `maxToolCalls`، `timeoutMs`). يرفض `budgetLimit` مع `maxCost` استدعاءات الأدوات لدى وكيل خاضع للحوكمة بمجرّد أن تتجاوز كلفة استدعاءاته للنموذج الحدَّ خلال الفترة، وفق الأسعار أعلاه: لا يُرفض استدعاء النموذج نفسه أبدًا، ومع `toolName` لا تُرفض إلا تلك الأداة. وإذا لم يكن لنموذجٍ سعر، أو لم يُبلغ استدعاءٌ عن عدد رموزه، تعذّر فحص الحدّ فتُرفض استدعاءات الأدوات. ويُرفَض `maxCost` الذي ليس عددًا منتهيًا ≥ 0 (سلسلة نصية مثل `'0.5'` مقروءة من ملف إعدادات، أو `NaN`، أو مبلغ سالب، أو `Infinity`، أو `null`) عند تطبيق السياسة، بخطأ `ValidationError`. والحدّ الذي يحدّد `agentId` يحتسب استدعاءات النموذج لدى ذلك الوكيل، أمّا الحدّ الذي لا يحدّده فيحتسب استدعاءات جميع الوكلاء الخاضعين للحوكمة. وتحتسب هذه الميزانيات أيضًا [الاستدعاءات الفاشلة](#failed-calls) لدى الوكلاء الخاضعين للحوكمة.
