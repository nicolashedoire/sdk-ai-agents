# المفاهيم الأساسية

## نظرة عامة {#overview}

SDK AI Agents بنية تحتية للحوكمة لوكلاء الذكاء الاصطناعي، تفصل الاستدلال عن الفعل وتوفّر استنادًا أصيلًا إلى الأحداث (event sourcing) لإعادة التشغيل والتدقيق. وفوقها، يضيف [الوكلاء المعرفيون](./cognitive-agents) طبقة استدلال صريحة، وتضيف [القرارات المُنمَّطة](./typed-decisions) إجابات معايَرة ومهيكلة.

::: info تتناول هذه الصفحة الأسس
الوكلاء، والأدوات، والقدرات، والسياسات، والنوايا، ومخزن الأحداث، والآثار، وإعادة التشغيل. وهي تنطبق على الوكلاء الخاضعين للحوكمة والوكلاء المعرفيين على حدّ سواء.
:::

## المفاهيم الأساسية {#fundamental-concepts}

### 1. الوكيل {#_1-agent}

**الوكيل** (Agent) نظام لاتخاذ القرار خاضع للحوكمة، يستخدم نموذجًا لغويًا لتوليد النوايا، لكن جميع الإجراءات تمرّ عبر محرّك إجراءات (Action Engine) مضبوط.

**الخصائص:**
- إعداد بالحدّ الأدنى (الاسم، والنموذج اللغوي)
- أدوات مُصرَّح بها صراحةً
- سياسات للحوكمة
- إصدارات للتتبّع
- قدرات لتنظيم الأدوات

**مثال:**
```typescript
const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-5.4',
  tools: [calculatorTool],
  version: '1.0.0',
  capabilities: ['math']
})
```

### 2. الأداة {#_2-tool}

**الأداة** (Tool) قدرة مُصرَّح بها صراحةً يستطيع الوكيل استخدامها. يجب تسجيل جميع الأدوات قبل استخدامها (الرفض افتراضيًا، deny-by-default).

**الخصائص:**
- مخطط تحقّق Zod إلزامي
- معالج غير متزامن
- إصدارات
- ارتباط بقدرة (اختياري)

**مثال:**
```typescript
const calculatorTool = sdk.defineTool({
  name: 'calculator',
  description: 'Performs basic arithmetic',
  schema: z.object({
    operation: z.enum(['add', 'subtract', 'multiply', 'divide']),
    a: z.number(),
    b: z.number()
  }),
  handler: async ({ operation, a, b }) => {
    // Implementation
  },
  version: '1.0.0',
  capability: 'math'
})
```

الأدوات الجاهزة (مجلد، أو قاعدة بيانات، أو واجهة API على الويب، أو الويب، أو وكيل آخر، أو خادم MCP)، وكيف يخضع كل استدعاء للحوكمة: انظر [الأدوات](./tools).

### 3. القدرة {#_3-capability}

**القدرة** (Capability) مجموعة منطقية من الأدوات يمكن إعادة استخدامها عبر عدة وكلاء.

**الخصائص:**
- الاسم والوصف
- قائمة الأدوات المرتبطة
- إصدارات
- بيانات وصفية اختيارية

**مثال (بأسماء الأدوات):**
```typescript
const calculatorTool = sdk.defineTool({ /* ... */ });
const scientificTool = sdk.defineTool({ /* ... */ });

const mathCapability = sdk.defineCapability({
  name: 'math',
  description: 'Mathematical operations',
  tools: ['calculator', 'scientific-calculator'],
  version: '1.0.0'
})

const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-5.4',
  capabilities: ['math']
})
```

**مثال (بكائنات Tool مباشرةً):**
```typescript
const calculatorTool = defineTool({ /* ... */ });
const scientificTool = defineTool({ /* ... */ });

const mathCapability = sdk.defineCapability({
  name: 'math',
  description: 'Mathematical operations',
  tools: [calculatorTool, scientificTool],
  version: '1.0.0'
})

const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-5.4',
  capabilities: ['math']
})
```

### 4. السياسة {#_4-policy}

**السياسة** (Policy) تحدّد قواعد الحوكمة المطبَّقة قبل كل إجراء.

**أنواع السياسات:**
- **الميزانية** (Budget): حدّ لعدد الخطوات، أو الرموز (tokens)، أو استدعاءات الأدوات، أو للكلفة (لكل تشغيل، أو لكل وكيل وأداة وفترة)
- **المهلة الزمنية** (Timeout): أقصى مدة للتنفيذ
- **قائمة السماح** (Allowlist): قائمة الأدوات المأذون بها
- **مخصّصة** (Custom): أداة تحقّق مخصّصة

**مثال:**
```typescript
sdk.defineGlobalPolicy({
  id: 'max-steps',
  type: 'budget',
  rules: [{
    condition: 'maxSteps',
    action: 'deny',
    metadata: { value: 10 }
  }],
  scope: 'global',
  enabled: true
})
```

### 5. النيّة {#_5-intention}

**النيّة** (Intention) بنية يولّدها النموذج اللغوي تصف ما يريد الوكيل فعله، دون تنفيذه مباشرةً.

**الأنواع:**
- `tool_call`: استدعاء أداة محدّدة
- `final_answer`: الإجابة النهائية للمستخدم
- `continue`: مواصلة الاستدلال

**الأمان:**
- يتحقّق محرّك السياسات (Policy Engine) من جميع النوايا
- لا إجراء مباشر من النموذج اللغوي
- تتبّع كامل

### 6. مخزن الأحداث {#_6-event-store}

**مخزن الأحداث** (Event Store) هو مصدر الحقيقة الوحيد لجميع عمليات التنفيذ.

**الخصائص:**
- حفظ تلقائي (ملفات JSON افتراضيًا)
- تجميع الكتابات في دفعات (batching) من أجل الأداء
- تصدير كامل
- التصفية حسب النوع، والتاريخ، وغير ذلك

**الأحداث الرئيسية:**
- `run.started`: بدء التنفيذ
- `intention.generated`: نيّة ولّدها النموذج اللغوي
- `policy.checked`: فحص سياسة
- `action.executed`: إجراء منفَّذ
- `tool.called`: أداة مستدعاة
- `run.completed`: اكتمل التنفيذ
- `run.failed`: فشل التنفيذ
- `run.cancelled`: أُلغي التنفيذ

### 7. الأثر {#_7-trace}

**الأثر** (Trace) هو التمثيل المقروء للبشر لتنفيذ كامل.

**المحتوى:**
- الخط الزمني للأحداث
- ملخّص إحصائي
- الحالة النهائية
- بيانات وصفية

**مثال:**
```typescript
const trace = await sdk.getTrace(runId)
console.log(trace.summary)
// {
//   totalEvents: 15,
//   duration: 1234,
//   intentionsGenerated: 3,
//   actionsExecuted: 2,
//   policiesChecked: 2,
//   toolsCalled: 2
// }
```

### 8. إعادة التشغيل {#_8-replay}

**إعادة التشغيل** (Replay) تتيح لك إعادة تشغيل تنفيذ كامل دون الاتصال بالنموذج اللغوي مجددًا.

**الخصائص:**
- حتمية (تسلسل الإجراءات نفسه)
- التعديلات ممكنة (المُدخَل، والسياسات، والأدوات)
- تصحيح أخطاء الحوادث
- اختبارات عدم التراجع

**مثال:**
```typescript
const replay = await sdk.replay(runId, {
  input: { message: 'Modified input' }
})
```

## المبادئ المعمارية {#architectural-principles}

### 1. فصل الاستدلال عن الفعل {#_1-reasoning-action-separation}

يولّد النموذج اللغوي النوايا، ولا يولّد أبدًا إجراءات مباشرة. جميع الإجراءات تمرّ عبر محرّك الإجراءات.

### 2. الرفض افتراضيًا {#_2-deny-by-default}

لا شيء مأذون به افتراضيًا. يجب التصريح بجميع الأدوات صراحةً (تسجيلها) قبل أن يتمكّن أي شيء من تشغيلها.

::: info نطاق الوكيل الخاضع للحوكمة
لا يشغّل الوكيل الخاضع للحوكمة إلا **أدواته هو**: أدوات `tools` الخاصة به وأدوات قدراته `capabilities`. وإذا ذكر النموذج أي أداة أخرى، حتى لو كانت مسجَّلة في حزمة SDK لوكيل آخر، يُرفَض الاستدعاء قبل التنفيذ (`policy.violated`، `allowed-tools`). ويُقيَّد الوكلاء المعرفيون والدراسات وخوادم MCP بقائمة أدواتهم بالطريقة نفسها. وتضيّق سياسة `allowlist` هذه القائمة أكثر، لوكيل واحد أو للجميع.
:::

### 3. استناد أصيل إلى الأحداث {#_3-native-event-sourcing}

كل تنفيذ قابل للتتبّع ولإعادة التشغيل بفضل الاستناد إلى الأحداث (event sourcing).

### 4. حوكمة مدمجة {#_4-built-in-governance}

تُطبَّق السياسات بنيويًا، لا بوصفها خيارًا.

### 5. إصدارات كاملة {#_5-full-versioning}

للوكلاء والأدوات والقدرات إصدارات من أجل التتبّع وإمكانية التعقّب.

## سير العمل النموذجي {#typical-workflow}

1. **التهيئة**: أنشئ حزمة SDK بمفتاح API
2. **التعريف**: عرّف الأدوات والقدرات
3. **الإعداد**: أنشئ الوكيل بالأدوات والسياسات
4. **التنفيذ**: شغّل الوكيل بمُدخَل
5. **المراقبة**: راجع أثر التنفيذ
6. **إعادة التشغيل**: أعِد التشغيل لتصحيح الأخطاء أو للاختبار

## أفضل الممارسات {#best-practices}

### الأدوات {#tools}
- استخدم مخططات Zod صارمة
- وثّق كل أداة بوضوح
- أصدِر نسخة جديدة من الأداة حين تتغيّر

### السياسات {#policies}
- طبّق ميزانيات معقولة
- استخدم قوائم سماح صارمة
- اختبر السياسات قبل بيئة الإنتاج

### القدرات {#capabilities}
- جمّع الأدوات تجميعًا منطقيًا
- أعِد استخدام القدرات عبر الوكلاء
- وثّق القدرات
- **سير العمل الموصى به:** يمكنك تمرير أسماء الأدوات (سلاسل نصية) أو كائنات Tool مباشرةً إلى `defineCapability()`. إذا مرّرت كائنات Tool، فستُسجَّل تلقائيًا.

### الإصدارات {#versioning}
- استخدم الترقيم الدلالي للإصدارات (semantic versioning)
- وثّق تغييرات الإصدارات
- تتبّع الإصدارات في الأحداث

## الأمان {#security}

- **الرفض افتراضيًا**: لا يمكن تنفيذ أي أداة غير مُصرَّح بها
- **التحقّق**: يُتحقَّق من جميع المُدخَلات بـ Zod
- **السياسات**: تُفحَص قبل كل إجراء
- **التتبّع**: جميع الإجراءات مُتتبَّعة
- **التدقيق**: إعادة التشغيل متاحة لتدقيق كامل
