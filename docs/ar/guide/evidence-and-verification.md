# الأدلة والتحقّق

ينبغي للوكيل المعرفي أن يؤمن بما يستطيع تبريره، وأن يختبر ما يتنبأ به، وأن يغيّر قواعده حين يخالفه العالم. لذلك تتتبّع الحلقة المعرفية **من أين يأتي كل دليل**، وتُبقي **الأدلة والتفضيلات منفصلة**، وتواجه التنبؤات **باختبارات حقيقية**، ولا **تعتمد** إلا إجابة تجتاز فحص جاهزية مكتوبًا بالشيفرة.

::: tip بكلمات بسيطة
فكّر في محقّق دقيق. إنه يدوّن **من أين يأتي كل خيط**، ولا يحسب الإشاعة نفسها مرتين. ومن عدة حالات يستخلص **قاعدة**، ثم يقول مسبقًا **ما ينبغي أن يراه** إن كانت القاعدة صحيحة، و**ما الذي سيثبت خطأها**. ثم يتحقّق، بقياس حقيقي لا برأيه الخاص. وحين يفشل التحقّق، لا يتظاهر: بل **يصحّح القاعدة** ويقول ما الذي تغيّر. ولا يعطي **إجابة حاسمة** إلا حين تصمد؛ وإلا فإنه يقول «لست متأكدًا بعد، وهذا ما ينقص»، أو «لا أستطيع الاستنتاج». كل مصطلح مستخدم أدناه مشروح في [المصطلحات الأساسية بكلمات بسيطة](./glossary#evidence-and-conclusions).
:::

## أعطِه ما لاحظته {#give-it-what-you-observed}

مرّر القياسات أو الحالات أو المستندات التي لديك بالفعل مع المشكلة. يصبح كل منها **ملاحظة** لها معرّف (`O1`، `O2`…) يستطيع الاستدلال الاستشهاد به.

```ts
const result = await agent.think({
  problem: 'Does the rolling time on our plane depend on the ball?',
  observations: [
    {
      content: { material: 'steel', massKg: 0.1, seconds: 1.07 },
      summary: 'Steel ball, 100 g: 1.07 s',
      originGroup: 'bench',
    },
    {
      content: { material: 'steel', massKg: 0.4, seconds: 1.07 },
      summary: 'Steel ball, 400 g: 1.07 s',
      originGroup: 'bench',
    },
  ],
});
```

تصبح نتائج الأدوات ونتائج الاختبارات ملاحظات أيضًا. ويكتب المحرّك منشأها، لا النموذج أبدًا:

| الحقل | المعنى |
| --- | --- |
| `sourceKind` | `input` (قُدِّم مع المشكلة)، أو `tool` (استدعاء أداة خاضعة للحوكمة)، أو `evaluation` (اختبار تنبؤ) |
| `source`، `sourceEventId` | الأداة أو المقيِّم، والحدث الذي يحتفظ بالحمولة الكاملة (`action.executed`، `cognition.evaluated`) |
| `observedAt`، `context` | متى لوحظ، وفي أي موقف |
| `summary` | نص محدود الطول يُعرَض على النموذج |
| `fingerprint` | بصمة (hash) للمحتوى الكامل |
| `originGroup` | الملاحظات ذات المنشأ نفسه **ليست** تأكيدات مستقلة |
| `duplicateOf` | يُعيَّن حين يكون المحتوى نفسه من المنشأ نفسه قد لوحظ من قبل |

تستشهد الحقائق بالملاحظات التي قُرئت منها (`observationRefs`)؛ والحقيقة المستخرجة من نتيجة أداة تُربَط بها تلقائيًا، والحقيقة المعروفة من قبل لا تُضاف مرتين — بل يُضاف إليها المصدر الجديد تعزيزًا. ويُوجَّه النموذج إلى قراءة المصدر الذي يؤكّد X على أنه *المصدر يؤكّد X*، لا على أنه دليل على X. وتضمن الشيفرة أن تكرار الدليل نفسه لا يضيف أي وزن: فالمكرَّر لا يُحسَب تغيّرًا في الأدلة، والحقائق أو الاختبارات التي تكرّر ملاحظة سابقة تشير إلى الأصل.

## مقارنة الملاحظات {#compare-observations}

تربط `compare_observations` الملاحظات (والحقائق) بعضها ببعض. وهي تُعرَض حين توجد ملاحظتان قابلتان للمقارنة على الأقل — قُدِّمتا مع المشكلة أو أعادتهما أدوات، باستثناء المكرَّرات ونتائج الاختبارات — وتكون ملاحظات جديدة قد وصلت منذ آخر مقارنة.

| العلاقة | المعنى | ما تفعله الشيفرة |
| --- | --- | --- |
| `similarity` | القيمة أو السلوك نفسه في جانب ما | تُسجَّل — التشابه ليس سببًا |
| `difference` | اختلاف يفسّره السياق | تُسجَّل |
| `evolution` | تغيّر عبر الزمن | تُسجَّل |
| `incompatibility` | لا يمكن أن تصحّا معًا | تفتح تناقضًا (`source_disagreement` بين منشأين مختلفين)، مرة واحدة |
| `counterexample` | حالة تنقض فرضية | تُحفَظ دليلًا مضادًا لتلك الفرضية، وتفتح تناقضًا، مرة واحدة |

## القواعد والتفسيرات والمقترحات {#rules-explanations-and-proposals}

تصرّح الفرضية بنوع الادعاء الذي تمثّله، وكيف استُدلّ عليه، وعلامَ يستند:

```json
{
  "statement": "Rolling time on this plane does not depend on the ball",
  "kind": "rule",
  "inference": "induction",
  "premiseRefs": ["O1", "O2"],
  "scope": "balls on this plane"
}
```

قيمة `kind` هي `proposal` (إجراء أو اختيار يجب اتخاذه، وهي القيمة الافتراضية)، أو `rule` (انتظام)، أو `explanation` (سبب). العبارة عمّا هو صحيح أو كان صحيحًا ليست مقترحًا أبدًا: ويُقال ذلك للنموذج، لأن [حارس الاستنتاج](#the-conclusion-guard) يسمح لتفضيلات المفكّر بأن تساعد اختيارًا، لا ادعاءً أبدًا. وقيمة `inference` هي `induction` أو `abduction` أو `deduction`؛ والتسمية لا تجعل الادعاء صحيحًا أبدًا.

## التنبؤات ومقيِّم النتائج {#predictions-and-the-outcome-evaluator}

تستنبط `simulate` **تنبؤات** قد تفشل: ما ينبغي أن يُلاحَظ (`expected`)، وأي ملاحظة ستثبت خطأ الفرضية (`falsifier`)، وفي أي `context`، ومعاملات `test` المهيكلة التي يحتاجها المقيِّم. يُسجَّل التنبؤ **قبل** اختباره، ويُختبَر مرة واحدة. ويرى النموذج التجارب التي أُجريت بالفعل ونتائجها (`experiments` في عرض الحالة)، ويُطلَب منه ألا يكرّر إحداها، بل أن يختار اختبارًا تختلف عليه الفرضيات المطروحة.

يواجه `OutcomeEvaluator` التنبؤ بالعالم — محاكٍ، أو قياس، أو مجموعة اختبارات، أو استعلام:

```ts
import type { OutcomeEvaluator } from '@sdk-ai-agents/core';

const bench: OutcomeEvaluator = {
  id: 'inclined-plane-bench',
  version: '1.0.0',
  async evaluate({ prediction }) {
    const run = await rollOnTheBench(prediction.test); // your measurement
    if (!run) return { verdict: 'inconclusive', reason: 'the bench is busy' };
    const refuted = Math.abs(run.seconds - run.expectedSeconds) / run.expectedSeconds > 0.1;
    return {
      verdict: refuted ? 'refuted' : 'confirmed',
      observed: run,
      summary: `${run.material} ball: ${run.seconds} s`,
      metrics: { seconds: run.seconds },
      ...(refuted ? { causeCandidates: ['material deforms', 'surface grip'] } : {}),
    };
  },
};

const agent = sdk.createCognitiveAgent({ name: 'physicist', model: 'gpt-4o', evaluator: bench });
```

مع وجود مقيِّم، تصبح `test_prediction` متاحة. وهي تستدعي **مقيِّمك، لا النموذج اللغوي**، وتسجّل التقرير الكامل حدثًا من نوع `cognition.evaluated`، وتضيف ما لوحظ ملاحظةً من نوع `evaluation` تشير إلى ذلك الحدث.

| الحكم | النتيجة المترتّبة |
| --- | --- |
| `confirmed` | تُضاف الملاحظة إلى `evidenceRefs` الخاصة بالفرضية |
| `refuted` | لوحظ المُفنِّد: **تُرفَض** الفرضية، وتُحفَظ الملاحظة دليلًا مضادًا، ويُسجَّل الدحض تناقضًا محلولًا من نوع `refuted_prediction` |
| `inconclusive` | يُسجَّل؛ وما لاحظه، إن وُجد، دليل جديد؛ ولا يتغيّر شيء آخر |

يستهلك كل اختبار واحدًا من `limits.maxPredictionTests`. المقيِّم الذي يرمي استثناءً أو يعيد تقريرًا غير صالح يعطي `inconclusive`، وكذلك التقرير `refuted` الذي لا يقول ما الذي لوحظ — فالقياس الفاشل لا يدحض شيئًا أبدًا. لا تستخدم نموذجًا يحكم على استدلاله الخاص مقيِّمًا: النقد الذاتي يمكنه تحضير اختبار، لكنه لا يستطيع أن يحلّ محله.

## المراجعة {#revision}

حين تناقض الأدلة فرضية، تطلب `revise` **صيغة معدّلة**: فرضية جديدة لها `parentId`، ونطاق `scope` أضيق أو متغيّر مضاف، و`difference` الذي تُحدثه — وتُرفَض الصيغة المعدّلة التي لا تصرّح بالفرق. يحتفظ الأصل بمعرّفه، وسبب رفضه، ومثاله المضاد؛ وتُرفَض إعادة صياغة فرضية سبق النظر فيها، مرفوضة كانت أم لا. في اختبار المستوى المائل، تصبح القاعدة المدحوضة *«زمن التدحرج لا يعتمد على الكرة»* هي *«بالنسبة إلى الكرات الصلبة، زمن التدحرج لا يعتمد على الكتلة»*، وهو ما يؤكّده اختبار ثانٍ.

## الأدلة ليست تفضيلات {#evidence-is-not-preference}

| الدرجة | السؤال | من يرى ملف المفكّر؟ |
| --- | --- | --- |
| `support` | إلى أي حدّ تدعمها الملاحظات والحقائق والتنبؤات والانتقادات؟ | مع Jev: لا أحد — تُرسَل أسئلة الأدلة دون الملف. مع النموذج اللغوي: يُوجَّه النموذج إلى تجاهل التفضيلات |
| `preferenceFit` | إلى أي حدّ يلائم هذا المقترح المفكّر؟ (للمقترحات فقط) | نعم، فهذا هو الغرض منها |

لا تخلط الشيفرة الدرجتين أبدًا. تُرتَّب الفرضيات بـ `support` وحدها بالنسبة إلى القواعد والتفسيرات؛ وتُرتَّب المقترحات بالصيغة `(1 − w) · support + w · preferenceFit`، حيث `w = limits.preferenceWeight` (0.4 افتراضيًا). لذلك يمكن لتغيير الملف أن يغيّر **الإجراء الذي يُختار**، وأن يحدّد ما إذا كان اختيار يفضّله المفكّر بوضوح يمكن اعتماده بناءً على أدلة معقولة (انظر [حارس الاستنتاج](#the-conclusion-guard))؛ أما مع Jev فلا يستطيع أن يغيّر **مدى مصداقية ادعاء ما**، ومع حَكَم من نموذج لغوي يعتمد هذا الفصل على تعليماته. تتبع `confidence` الخاصة بالحالة دعمَ الأدلة للفرضية الأعلى ترتيبًا: وتُتجاهَل `confidence` التي يكتبها النموذج في فكرة.

`support` حكم تقديري من نموذج، لا احتمال معايَر. أما ما يُقاس فهو السجل الفعلي: أي التنبؤات تأكّدت وأيها دُحضت.

## التقييمات المتقادمة {#stale-assessments}

تحتفظ الحالة بعدّاد `evidenceRevision`. ويزداد حين تصل ملاحظة جديدة (غير مكرَّرة)، أو حقيقة جديدة، أو مراجعة لحقيقة، أو تناقض، أو مثال مضاد، أو نتيجة اختبار حاسمة. والتقييمات التي أُجريت قبل ذلك **متقادمة**: تُعرَض `compare` مجددًا، ولا يمكن اعتماد فرضية متقادمة. يجب أن تعيد المقارنة تقييم **كل** فرضية مطروحة — يُطلَب من النموذج إصلاح المقارنة التي تتخطّى فرضية، والمقارنة التي لا تزال تتخطّى فرضية، أو تفشل، لا تُحسَب منجزة.

## التناقضات ومراجعات الحقائق {#contradictions-and-fact-revisions}

تحمل التناقضات فئة `category`: `source_disagreement`، أو `temporal_change`، أو `context_difference`، أو `logical_incompatibility`، أو `refuted_prediction`. يُحَلّ التناقض **مرة واحدة**، ولا يُحَلّ إلا حين **يستشهد الحلّ بملاحظات أو حقائق** تحسمه (`basisRefs` — ويُبلَّغ عن الإشارات الأخرى وتُتجاهَل)؛ ويمكنه أن يقول ما الذي فُعل (`retracted`، أو `restricted`، أو `replaced`، أو `explained` افتراضيًا). ويُحفَظ الحلّ مع التناقض. ولا تُحذَف الحقائق أبدًا: بل تكون `retracted` (مسحوبة) أو `superseded` (مستبدَلة) ببديل، مع ذكر السبب.

## حارس الاستنتاج {#the-conclusion-guard}

لا يجوز **اعتماد** إجابة إلا حين تكون فرضيتها:

- قد نُقدت؛
- قد قُيِّمت منذ آخر تغيّر في الأدلة؛
- غير معنيّة بتناقض غير محلول (والتناقض الذي لا يسمّي شيئًا يعني كل شيء)؛
- بلا تنبؤ غير مُختبَر ما دامت ميزانية الاختبارات تسمح باختباره؛
- ذات `support` من الأدلة لا يقل عن `limits.decisionThreshold` — أو، بالنسبة إلى **المقترح** (اختيار إجراء)، أن تكون بوضوح اختيار المفكّر (`preferenceFit` لا يقل عن `limits.decisionThreshold`) مع بلوغ دعم أدلتها `limits.minProposalSupport` (0.35 افتراضيًا).

يوجد المسار الثاني لأن سؤالًا مثل *«هل كنت ستقبل هذه الوظيفة؟»* ليس فيه إلا القليل من الأدلة لوزنها: يقرّره الشخص بأولوياته، بشرط ألا تتعارض الوقائع مع الاختيار، أي بشرط أن يبقى دعم أدلته عند الحدّ الأدنى أو فوقه. ولا تسلك القواعد والتفسيرات هذا المسار أبدًا: التفضيلات لا تجعل الادعاء صحيحًا أبدًا. تعرض صفحة [الاستدلال على طريقة شخص معيّن](./thinker-profiles#how-a-choice-is-ranked-and-committed) مثالًا بالأرقام. لا يجوز أن تتجاوز `minProposalSupport` قيمة `decisionThreshold`؛ اجعلها مساوية لـ `decisionThreshold` لإيقاف هذا المسار.

لا تُعرَض `decide` إلا حين تجتاز فرضيةٌ الحارس. القرار الذي يختار فرضية أخرى، أو لا يختار أيًا منها، **يُؤجَّل** ما دامت الميزانية قائمة؛ ويُحسَب التأجيل محاولة فاشلة، ولا تُعرَض `decide` بعد تأجيلين متتاليين. وفي الخطوة الأخيرة، أو حين لا يكون أي شيء آخر ممكنًا، يظل المحرّك يطلب قرارًا، ويحسمه:

| `decision.status` | متى | `decision.missing` |
| --- | --- | --- |
| `committed` | ينجح فحص الجاهزية | `[]` |
| `provisional` | نفدت الميزانية على فرضية لا تزال قائمة | ما لم يثبت بعد |
| `abstain` | لم تُختَر أي فرضية، أو رُفضت الفرضية المختارة، أو لم يستطع النموذج إنتاج قرار أصلًا | السبب — للامتناع ثقة 0، ويكتب المحرّك إجابته (ويُحتفَظ بما كتبه النموذج في `rationale`) |

```ts
const { decision } = await agent.think({ problem, observations });
if (decision?.status !== 'committed') {
  console.log('Not established yet:', decision?.missing);
}
```

تبقى حالة التشغيل `completed`: الامتناع الصريح نتيجة صالحة. وثقة القرار مسقوفة بدعم الأدلة لفرضيته.

## ميزانية لا تُهدَر {#a-budget-that-is-not-wasted}

الخطوة التي لم تغيّر شيئًا مما كان يُفترَض أن تغيّره — لا فرضية جديدة (رُفضت كل المقترحات)، ولا شيء جديد مُحاكى أو منقود، ولا مقارنة مُسجَّلة — والمقارنة التي تتخطّى فرضية، والقرار المؤجَّل، كلها تُحسَب محاولات فاشلة لعمليتها. حين تفشل `compare_observations` أو `hypothesize` أو `simulate` أو `revise` أو `critique` أو `compare` أو `decide` مرتين متتاليتين، لا تعود معروضة **إلى أن تأتي خطوة أخرى بأدلة جديدة** — خطوة نجحت، أو نتيجة أداة أو اختبار سجّلها المحرّك؛ أما ما كتبته الخطوات الفاشلة بنفسها فلا يُحسَب — فيمضي التشغيل قُدُمًا بدل أن يكرّر نفسه. أما `seek_information` فتعمل لكل سؤال مفتوح على حدة: السؤال الذي لا تستطيع أي أداة متاحة الإجابة عنه يُسقَط فورًا (مع السبب)، واستدعاء الأداة الفاشل يُحسَب من المحاولتين المتاحتين لكل سؤال، فتنال الأسئلة الأخرى دورها. وتتقيّد `test_prediction` بميزانية اختباراتها.

تعدّ `limits.maxConsecutiveFailures` إخفاقات النموذج أو أدواته، بما فيها المقارنة التي لا تزال تتخطّى فرضية بعد الإصلاح. أما القرارات المؤجَّلة والخطوات التي لم تغيّر شيئًا فتُسجَّل خطوات فاشلة لكنها لا تُحسَب منها أبدًا. تتلقّى المكوّنات (مولّد الأفكار، والمقيِّم التقديري، ومقيِّم النتائج) نسخة من الحالة: فلا تستطيع تغيير ما سُجِّل، والفكرة غير الصالحة الصادرة عن مكوّن مخصّص تُسجَّل عملية فاشلة بدل أن توقف التشغيل.

## الاختبارات هي مواصفاتك {#tests-are-your-specification}

يشغّل `src/__tests__/rule-discovery.test.ts` الحلقة كاملة بنموذج مُبرمَج السيناريو ومنصة فيزياء حتمية — الاستقراء، والتنبؤ، والدحض، والمراجعة، والتحقّق، والاعتماد — ويفحص كل حدث. ويفحص `src/__tests__/epistemic-state.test.ts` و`epistemic-guards.test.ts` و`epistemic-liveness.test.ts` كل قاعدة مما سبق على حدة، ويفحص أثرٌ سجّله الإصدار السابق أن عمليات التشغيل الأقدم يُعاد بناؤها دون تغيير.

## عمليات التشغيل الأقدم {#older-runs}

تسجّل عمليات التشغيل إصدار هذه القواعد (`schemaVersion: 2` في `cognition.started`). أما عمليات التشغيل المُسجَّلة قبل ذلك فليس لها إصدار: يعيد `getMentalState` بناءها بقواعدها الأصلية، وتكون مجموعاتها الجديدة فارغة.

## ما لم يتحقّق بعد {#not-there-yet}

- **الذاكرة الدلالية.** تستدعي [الذاكرة عبر عمليات التشغيل](./memory) ما أثبتته الاختبارات السابقة بمطابقة الكلمات؛ وقد تفوتها قواعد ذات صلة صيغت بطريقة مختلفة.
- **التقادم الموجَّه.** الدليل الجديد يجعل كل تقييم متقادمًا، لا التقييمات التي تعنيه فقط — وهذا نهج متحفّظ، وبسيط التدقيق.
- **اختيار ما يُستكشَف.** تختار المتحكّمات عملية؛ أما الهدف (أي مجهول، أي تنبؤ) فهو أول هدف مؤهّل.
- **المعايرة.** لا توجد بعد ثقة تنبؤية معايَرة: `support` حكم تقديري، والسجل الفعلي للتنبؤات هو ما يُقاس.
- **الاستدلال المُتحقَّق منه.** تسمية الاستدلال (استقراء، استدلال بأفضل تفسير، استنباط) مُعلَنة، ولا يتحقّق منها مُتحقِّق صوري.
- **الأنواع المُعلَنة.** يعلن النموذج ما إذا كانت الفرضية ادعاءً أم اختيار إجراء حين يقترحها، والفرضية التي لا نوع لها مقترح. يمنع الموجّه تسمية عبارة عن العالم مقترحًا، لكن لا شيء يتحقّق من ذلك: فقد يُعتمَد ادعاء موسوم خطأً بناءً على تفضيل المفكّر.
- **اختبار الأسباب وراء اختيار ما.** حين يسأل الهدف عمّا يجب فعله، تكون الفرضيات مسارات عمل ولا تحصل على تنبؤات إلا القواعد والتفسيرات، فلا يُستخدَم مقيِّم النتائج في مثل هذه الأهداف.
- **الفحوص المهيكلة.** القيود نص حر ولا يفحصها حارس الاستنتاج؛ ولا تُكتشَف التعارضات بقواعد على بيانات مهيكلة؛ وإجراء الحلّ لا يغيّر الحقائق أو الفرضيات بنفسه.
