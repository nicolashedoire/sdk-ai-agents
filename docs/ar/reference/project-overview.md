# نظرة عامة على المشروع

**النوع:** مكتبة (حزمة SDK بلغة TypeScript)
**البنية المعمارية:** الاستناد إلى الأحداث (Event-Sourcing) مع فصل المسؤوليات

## الملخّص التنفيذي {#executive-summary}

SDK_AI_Agents بنية تحتية لحوكمة وكلاء الذكاء الاصطناعي، مع استناد أصيل إلى الأحداث، وإعادة تشغيل، وأمان من التصميم. تحوّل حزمة SDK وكلاء الذكاء الاصطناعي من أدوات تجريبية إلى أنظمة لاتخاذ القرار قابلة للحوكمة، وقابلة للتفسير، وجاهزة لبيئة الإنتاج.

## تصنيف المشروع {#project-classification}

- **نوع المستودع:** مستودع موحّد (Monolith، قاعدة شيفرة واحدة متماسكة)
- **نوع المشروع:** مكتبة (حزمة SDK بلغة TypeScript)
- **اللغة الأساسية:** TypeScript 5.x
- **النمط المعماري:** الاستناد إلى الأحداث مع فصل المسؤوليات (محرّك الاستدلال ≠ محرّك الإجراءات)

## الميزات الرئيسية {#key-features}

### القدرات الأساسية {#core-capabilities}

1. **استناد أصيل إلى الأحداث**
   - تُحفَظ جميع الأحداث في مخزن أحداث
   - إعادة تشغيل حتمية دون استدعاء نموذج لغوي
   - تتبّع كامل لكل قرار

2. **فصل الاستدلال عن الفعل**
   - محرّك الاستدلال: يولّد النوايا (دون آثار جانبية)
   - محرّك الإجراءات: ينفّذ النوايا بعد التحقّق منها
   - أمان من التصميم: لا يسبّب النموذج اللغوي أبدًا أثرًا جانبيًا مباشرًا

3. **حوكمة مدمجة**
   - محرّك السياسات: يتحقّق من النوايا قبل التنفيذ
   - متتبّع الميزانية: يتتبّع التكاليف والاستهلاك لكل وكيل/أداة/فترة
   - مدير الموافقات: سير عمل الموافقة البشرية للإجراءات الحرجة
   - سجل التدقيق: تتبّع كامل لقرارات السياسات

4. **نماذج لغوية متعددة المزوّدين**
   - تجريد LLMProvider لـ OpenAI وAnthropic
   - تحويل تلقائي إلى البديل بين المزوّدين
   - إعدادات لكل مزوّد (temperature، maxTokens)

5. **الرصد المعرفي**
   - الرسم البياني للاستدلال: تصوير عملية الاستدلال
   - تحليل البدائل: البدائل التي نظر فيها الوكيل
   - أنماط القرار: أنماط القرار عبر عمليات تشغيل متعددة
   - تصوير الأثر: تحضير الأثر للتصوير

6. **الاختبار وضمان الجودة**
   - الآثار المرجعية (Golden Traces): آثار مرجعية للاختبار
   - اكتشاف التراجعات: اكتشاف تلقائي للتراجعات
   - التوكيدات: توكيدات سلوكية على الآثار
   - التكامل مع CI/CD: تصدير نتائج الاختبارات (JUnit XML، JSON)

7. **رصد متقدّم**
   - مقارنة عمليات التشغيل: مقارنة تنفيذين
   - تحليل التأثير: تحليل تأثير النشر قبله وبعده
   - تصفية متقدّمة للأحداث: تصفية متقدّمة للأحداث بمسارات JSON

## أبرز جوانب البنية المعمارية {#architecture-highlights}

### تجريد مخزن الأحداث {#event-store-abstraction}

- **IEventStore**: واجهة مشتركة لجميع مخازن الأحداث
- **FileEventStore**: تنفيذ قائم على الملفات (MVP)
- **SQLEventStore**: تنفيذ SQL عام
- **SQLiteEventStore**: تنفيذ لـ SQLite
- **PostgreSQLEventStore**: تنفيذ لـ PostgreSQL مع JSONB

### بنية المحرّكات {#engine-architecture}

- **ReasoningEngine**: يولّد النوايا من النموذج اللغوي
- **ActionEngine**: ينفّذ النوايا بعد التحقّق منها
- **PolicyEngine**: يتحقّق من النوايا مقابل السياسات
- **ReplayEngine**: يعيد تشغيل عمليات التنفيذ انطلاقًا من الأحداث

### نظام السجلات (Registry) {#registry-system}

- **ToolRegistry**: يدير الأدوات المتاحة
- **CapabilityRegistry**: يدير القدرات (مجموعات الأدوات)

### نظام المديرين {#manager-system}

- **ApprovalManager**: إدارة الموافقات البشرية
- **BudgetTracker**: تتبّع الميزانية والاستهلاك
- **GoldenTraceManager**: إدارة الآثار المرجعية
- **RegressionTestManager**: إدارة مجموعات اختبار التراجعات
- **AssertionManager**: إدارة التوكيدات السلوكية
- **ImpactAnalysisManager**: إدارة تحليل التأثير

## نظرة عامة على التطوير {#development-overview}

### المتطلبات المسبقة {#prerequisites}

- Node.js 20.0.0+ (LTS)
- npm أو ما يعادله
- TypeScript 5.3.2+ (مثبّت محليًا)

### البدء {#getting-started}

```bash
# Installation
npm install

# Build
npm run build

# Tests
npm test

# Watch mode
npm run dev
```

### الأوامر الرئيسية {#key-commands}

- **التثبيت:** `npm install`
- **البناء:** `npm run build`
- **التطوير:** `npm run dev` (وضع المراقبة)
- **الاختبار:** `npm test`
- **الاختبار مع المراقبة:** `npm run test:watch`
- **تغطية الاختبارات:** `npm run test:coverage`
- **التدقيق:** `npm run lint`
- **التنسيق:** `npm run format`
- **الفحص:** `npm run check` (التدقيق + التنسيق)
