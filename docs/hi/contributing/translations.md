# दस्तावेज़ों का अनुवाद

दस्तावेज़ अंग्रेज़ी में लिखे गए हैं और दस भाषाओं में अनुवादित हैं: फ़्रेंच, स्पैनिश, जर्मन, सरलीकृत चीनी, ब्राज़ीलियाई पुर्तगाली, जापानी, कोरियाई, रूसी, अरबी और हिन्दी। हर पेज के ऊपर का भाषा मेनू इनके बीच बदलता है।

::: tip आसान भाषा में
अंग्रेज़ी संदर्भ है। हर दूसरी भाषा अंग्रेज़ी पेजों की एक प्रति है, जिसमें टेक्स्ट का अनुवाद किया गया है और बाकी सब कुछ एक जैसा रखा गया है: कोड, links, टेबलें और शीर्षकों के anchors। CI द्वारा चलाई जाने वाली एक जाँच ऐसे बदलाव को ठुकरा देती है जो किसी अनुवाद को पीछे छोड़ दे।
:::

## चीज़ें कहाँ हैं {#where-things-are}

| क्या | कहाँ |
| --- | --- |
| अंग्रेज़ी पेज | `docs/guide/`, `docs/reference/`, `docs/contributing/`, `docs/index.md` |
| एक अनुवाद | `docs/<code>/` के नीचे वही फ़ाइलें, जैसे `docs/fr/guide/memory.md` |
| मेनू, बटन, खोज के टेक्स्ट | `docs/.vitepress/i18n/<code>.ts`, `i18n/en.ts` से अनुवादित |
| भाषाएँ और साइडबार | `docs/.vitepress/i18n/structure.ts` |
| जाँच | `docs/.vitepress/check-translations.ts`, `npm run docs:check` से चलाई जाती है |

## अनुवाद के नियम {#the-rules-of-a-translation}

1. **टेक्स्ट का अनुवाद करें, बाकी वैसा ही रखें।** कोड ब्लॉक अंग्रेज़ी जैसे ही रहते हैं, comments सहित, ताकि पाठक भाषा चाहे जो हो, वही कोड कॉपी कर सके। विकल्पों के नाम, फ़ंक्शन के नाम, इवेंट के टाइप और `committed` जैसे मानों का कभी अनुवाद नहीं होता।
2. **हर शीर्षक का अंग्रेज़ी anchor बनाए रखें।** दूसरे पेज सेक्शनों से उनके anchor (`./memory#statuses`) के ज़रिए जुड़ते हैं। अनुवादित शीर्षक अंग्रेज़ी anchor पर खत्म होता है:

   ```md
   ## Statuts {#statuses}
   ```

3. **links बनाए रखें।** वही links, उन्हीं पेजों तक, उसी फ़ोल्डर में। होम पेज पर, front matter के links को भाषा का prefix मिलता है (`/fr/guide/introduction`)।
4. **संरचना बनाए रखें।** टेबलों और टेबल की पंक्तियों की संख्या वही, वही callout बॉक्स (`::: tip`), वही चित्र।
5. **आरेखों (diagrams) का अनुवाद किया जा सकता है।** Mermaid आरेख में, सिर्फ़ लेबलों का अनुवाद करें; nodes के नाम और तीर वैसे ही रखें। जब किसी लेबल में कोष्ठक, comma या दूसरे विराम-चिह्न हों, तो उसे quotes में रखें: `A["Tests (réels)"]`।
6. **हर चीज़ समझाएँ।** अनुवाद ऐसे व्यक्ति के लिए लिखा जाता है जो विषय नहीं जानता: पहले आसान शब्द, अंग्रेज़ी पेज जैसी ही व्याख्याएँ।

## अनुवाद की जाँच करें {#check-a-translation}

```sh
npm run docs:check          # every language
npm run docs:check -- fr    # one language
npm run docs:build          # then build the site
```

`docs:check` हर भाषा और पेज के लिए बताता है: गायब या अतिरिक्त पेज, अंग्रेज़ी से अलग कोड, सही anchor के बिना शीर्षक, गायब या अतिरिक्त link, किसी ऐसे पेज का link जो मौजूद नहीं है, कोई अलग टेबल या callout बॉक्स, ऐसा आरेख जो मान्य Mermaid नहीं है, और ऐसा टेक्स्ट या इंटरफ़ेस टेक्स्ट जो अब भी अंग्रेज़ी में है। CI हर pull request पर इसे चलाता है।

## जब आप कोई अंग्रेज़ी पेज बदलें {#when-you-change-an-english-page}

जब तक हर भाषा साथ न आ जाए, CI विफल होता रहता है। शब्दों के बदलाव के लिए, हर भाषा में वही हिस्सा अपडेट करें। नए कोड, नए शीर्षक या नए link के लिए, जाँच आपको बताती है कि कौन-से पेज और कौन-सी लाइनें अपडेट करनी हैं।

## एक भाषा जोड़ें {#add-a-language}

1. इसे `docs/.vitepress/i18n/structure.ts` में `LANGUAGES` में जोड़ें: इसका कोड, इसका [BCP 47](https://www.rfc-editor.org/info/bcp47) टैग, इसकी अपनी भाषा में इसका नाम, और दाएँ से बाएँ लिखी जाने वाली भाषा के लिए `dir: 'rtl'`।
2. `i18n/en.ts` को `i18n/<code>.ts` में कॉपी करें, टेक्स्ट का अनुवाद करें, और इसे `docs/.vitepress/config.mts` में import करें।
3. हर पेज का `docs/<code>/` में अनुवाद करें, फिर `npm run docs:check -- <code>` चलाएँ।

## सीमाएँ {#limits}

- **चित्र** (SVG images) हर भाषा में अंग्रेज़ी में हैं।
- **खोज** हर भाषा को अलग-अलग index करती है; चीनी और जापानी में, शब्दों के बीच खाली जगह वाली भाषाओं की तुलना में खोज पूरे शब्दों का मिलान कम अच्छी तरह करती है।
- **गुणवत्ता।** अनुवाद एक AI मॉडल ने लिखे हैं और CI ने उन्हें अंग्रेज़ी संरचना के सामने जाँचा है, हर भाषा के मूल वक्ताओं ने प्रूफ़रीड नहीं किया है। सुधारों का स्वागत है: हर पेज के नीचे "इस पेज को GitHub पर संपादित करें" इस्तेमाल करें।
