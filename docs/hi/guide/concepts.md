# मुख्य अवधारणाएँ

## एक नज़र में {#overview}

SDK AI Agents, AI एजेंटों के लिए नियंत्रण (governance) का एक बुनियादी ढाँचा है, जो तर्क को कार्रवाई से अलग रखता है और रीप्ले व ऑडिट के लिए मूल रूप से इवेंट सोर्सिंग देता है। इसके ऊपर, [संज्ञानात्मक एजेंट](./cognitive-agents) तर्क की एक स्पष्ट परत जोड़ते हैं, और [टाइप्ड निर्णय](./typed-decisions) कैलिब्रेटेड, संरचित उत्तर जोड़ते हैं।

::: info यह पेज बुनियादी बातें समझाता है
एजेंट, टूल, क्षमताएँ, नीतियाँ, इरादे, इवेंट स्टोर, ट्रेस और रीप्ले। ये नियंत्रित और संज्ञानात्मक, दोनों तरह के एजेंटों पर समान रूप से लागू होते हैं।
:::

## बुनियादी अवधारणाएँ {#fundamental-concepts}

### 1. एजेंट {#_1-agent}

**एजेंट** निर्णय लेने वाला एक नियंत्रित सिस्टम है, जो इरादे बनाने के लिए LLM का इस्तेमाल करता है, लेकिन उसकी सभी कार्रवाइयाँ एक नियंत्रित एक्शन इंजन (Action Engine) से होकर गुज़रती हैं।

**विशेषताएँ:**
- न्यूनतम कॉन्फ़िगरेशन (नाम, LLM मॉडल)
- स्पष्ट रूप से घोषित टूल
- नियंत्रण के लिए नीतियाँ
- ट्रैकिंग के लिए वर्ज़निंग
- टूल को व्यवस्थित करने के लिए क्षमताएँ

**उदाहरण:**
```typescript
const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-5.4',
  tools: [calculatorTool],
  version: '1.0.0',
  capabilities: ['math']
})
```

### 2. टूल {#_2-tool}

**टूल** एक स्पष्ट रूप से घोषित क्षमता है जिसे एजेंट इस्तेमाल कर सकता है। सभी टूल इस्तेमाल से पहले रजिस्टर होने चाहिए (deny-by-default, यानी डिफ़ॉल्ट रूप से मना)।

**विशेषताएँ:**
- अनिवार्य Zod सत्यापन स्कीमा
- एसिंक्रोनस handler
- वर्ज़निंग
- किसी क्षमता से जुड़ाव (वैकल्पिक)

**उदाहरण:**
```typescript
const calculatorTool = sdk.defineTool({
  name: 'calculator',
  description: 'Performs basic arithmetic',
  schema: z.object({
    operation: z.enum(['add', 'subtract', 'multiply', 'divide']),
    a: z.number(),
    b: z.number()
  }),
  handler: async ({ operation, a, b }) => {
    // Implementation
  },
  version: '1.0.0',
  capability: 'math'
})
```

पहले से तैयार टूल (एक फ़ोल्डर, एक डेटाबेस, एक वेब API, वेब, कोई दूसरा एजेंट, एक MCP सर्वर) और हर कॉल कैसे नियंत्रित होती है: देखें [टूल](./tools)।

### 3. क्षमता (Capability) {#_3-capability}

**क्षमता** टूल का एक तार्किक समूह है जिसे कई एजेंटों में दोबारा इस्तेमाल किया जा सकता है।

**विशेषताएँ:**
- नाम और विवरण
- जुड़े हुए टूल की सूची
- वर्ज़निंग
- वैकल्पिक मेटाडेटा

**उदाहरण (टूल के नामों के साथ):**
```typescript
const calculatorTool = sdk.defineTool({ /* ... */ });
const scientificTool = sdk.defineTool({ /* ... */ });

const mathCapability = sdk.defineCapability({
  name: 'math',
  description: 'Mathematical operations',
  tools: ['calculator', 'scientific-calculator'],
  version: '1.0.0'
})

const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-5.4',
  capabilities: ['math']
})
```

**उदाहरण (सीधे Tool ऑब्जेक्ट के साथ):**
```typescript
const calculatorTool = defineTool({ /* ... */ });
const scientificTool = defineTool({ /* ... */ });

const mathCapability = sdk.defineCapability({
  name: 'math',
  description: 'Mathematical operations',
  tools: [calculatorTool, scientificTool],
  version: '1.0.0'
})

const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-5.4',
  capabilities: ['math']
})
```

### 4. नीति (Policy) {#_4-policy}

**नीति** नियंत्रण के वे नियम तय करती है जो हर कार्रवाई से पहले लागू होते हैं।

**नीतियों के प्रकार:**
- **Budget (बजट)**: कदमों, tokens, टूल कॉल या लागत की सीमा (हर run के लिए, या हर एजेंट, टूल और अवधि के लिए)
- **Timeout (समय-सीमा)**: चलने की अधिकतम अवधि
- **Allowlist (अनुमति-सूची)**: अनुमति वाले टूल की सूची
- **Custom (अपनी)**: आपका अपना सत्यापनकर्ता

**उदाहरण:**
```typescript
sdk.defineGlobalPolicy({
  id: 'max-steps',
  type: 'budget',
  rules: [{
    condition: 'maxSteps',
    action: 'deny',
    metadata: { value: 10 }
  }],
  scope: 'global',
  enabled: true
})
```

### 5. इरादा (Intention) {#_5-intention}

**इरादा** LLM द्वारा बनाई गई एक संरचना है जो बताती है कि एजेंट क्या करना चाहता है, बिना उसे सीधे लागू किए।

**प्रकार:**
- `tool_call`: किसी खास टूल को कॉल
- `final_answer`: उपयोगकर्ता को अंतिम उत्तर
- `continue`: तर्क जारी रखना

**सुरक्षा:**
- सभी इरादों को Policy Engine सत्यापित करता है
- LLM की ओर से कोई सीधी कार्रवाई नहीं
- पूरी ट्रेसबिलिटी

### 6. इवेंट स्टोर {#_6-event-store}

**इवेंट स्टोर** सभी executions के लिए सच का एकमात्र स्रोत है।

**विशेषताएँ:**
- अपने-आप सहेजना (डिफ़ॉल्ट रूप से JSON फ़ाइलें)
- प्रदर्शन के लिए बैचिंग
- पूरा एक्सपोर्ट
- प्रकार, तारीख आदि के हिसाब से फ़िल्टर

**मुख्य इवेंट:**
- `run.started`: execution की शुरुआत
- `intention.generated`: LLM द्वारा बनाया गया इरादा
- `policy.checked`: नीति की जाँच
- `action.executed`: कार्रवाई लागू की गई
- `tool.called`: टूल कॉल किया गया
- `run.completed`: execution पूरा हुआ
- `run.failed`: execution विफल हुआ
- `run.cancelled`: execution रद्द हुआ

### 7. ट्रेस {#_7-trace}

**ट्रेस** एक पूरे execution का ऐसा रूप है जिसे इंसान पढ़ सके।

**सामग्री:**
- इवेंट्स की समय-रेखा
- आँकड़ों का सारांश
- अंतिम स्थिति
- मेटाडेटा

**उदाहरण:**
```typescript
const trace = await sdk.getTrace(runId)
console.log(trace.summary)
// {
//   totalEvents: 15,
//   duration: 1234,
//   intentionsGenerated: 3,
//   actionsExecuted: 2,
//   policiesChecked: 2,
//   toolsCalled: 2
// }
```

### 8. रीप्ले {#_8-replay}

**रीप्ले** से आप LLM से दोबारा संपर्क किए बिना पूरे execution को फिर से चला सकते हैं।

**विशेषताएँ:**
- नियतात्मक (कार्रवाइयों का वही क्रम)
- बदलाव संभव (इनपुट, नीतियाँ, टूल)
- घटनाओं (incidents) की डीबगिंग
- नॉन-रिग्रेशन टेस्ट

**उदाहरण:**
```typescript
const replay = await sdk.replay(runId, {
  input: { message: 'Modified input' }
})
```

## आर्किटेक्चर के सिद्धांत {#architectural-principles}

### 1. तर्क और कार्रवाई का अलगाव {#_1-reasoning-action-separation}

LLM इरादे बनाता है, कभी सीधी कार्रवाइयाँ नहीं। सभी कार्रवाइयाँ एक्शन इंजन से होकर गुज़रती हैं।

### 2. डिफ़ॉल्ट रूप से मना (Deny-by-Default) {#_2-deny-by-default}

डिफ़ॉल्ट रूप से किसी भी चीज़ की अनुमति नहीं है। किसी टूल को कोई चला सके, इससे पहले उसे स्पष्ट रूप से घोषित (रजिस्टर) करना ज़रूरी है।

::: info नियंत्रित एजेंट का दायरा
एक नियंत्रित एजेंट **सिर्फ़ अपने टूल** चलाता है: उसके `tools` के और उसकी `capabilities` के टूल। अगर मॉडल किसी दूसरे टूल का नाम ले, भले ही वह SDK में किसी दूसरे एजेंट के लिए रजिस्टर किया गया हो, तो कॉल चलने से पहले ही ठुकरा दी जाती है (`policy.violated`, `allowed-tools`)। संज्ञानात्मक एजेंट, अध्ययन और MCP सर्वर भी इसी तरह अपनी टूल-सूची तक सीमित रहते हैं। एक `allowlist` नीति इसे और सीमित करती है, किसी एक एजेंट के लिए या सभी के लिए।
:::

### 3. मूल रूप से इवेंट सोर्सिंग {#_3-native-event-sourcing}

इवेंट सोर्सिंग की वजह से हर execution को ट्रेस और रीप्ले किया जा सकता है।

### 4. भीतर से बना नियंत्रण {#_4-built-in-governance}

नीतियाँ ढाँचे के स्तर पर लागू होती हैं, किसी विकल्प के रूप में नहीं।

### 5. पूरी वर्ज़निंग {#_5-full-versioning}

ट्रैकिंग और ट्रेसबिलिटी के लिए एजेंट, टूल और क्षमताओं के वर्ज़न रखे जाते हैं।

## आम कार्य-प्रवाह {#typical-workflow}

1. **शुरुआत**: API key के साथ SDK बनाएँ
2. **परिभाषा**: टूल और क्षमताएँ परिभाषित करें
3. **कॉन्फ़िगरेशन**: टूल और नीतियों के साथ एजेंट बनाएँ
4. **Execution**: किसी इनपुट के साथ एजेंट चलाएँ
5. **अवलोकन**: execution का ट्रेस देखें
6. **रीप्ले**: डीबगिंग या टेस्टिंग के लिए रीप्ले करें

## अच्छे तरीके {#best-practices}

### टूल {#tools}
- सख़्त Zod स्कीमा इस्तेमाल करें
- हर टूल को साफ़-साफ़ डॉक्यूमेंट करें
- टूल बदलने पर उनका वर्ज़न बदलें

### नीतियाँ {#policies}
- उचित बजट लागू करें
- सख़्त अनुमति-सूचियाँ इस्तेमाल करें
- production से पहले नीतियों को टेस्ट करें

### क्षमताएँ {#capabilities}
- टूल को तार्किक रूप से समूहों में रखें
- क्षमताओं को कई एजेंटों में दोबारा इस्तेमाल करें
- क्षमताओं को डॉक्यूमेंट करें
- **सुझाया गया तरीका:** आप `defineCapability()` को टूल के नाम (strings) या सीधे Tool ऑब्जेक्ट, दोनों में से कुछ भी दे सकते हैं। अगर आप Tool ऑब्जेक्ट देते हैं, तो वे अपने-आप रजिस्टर हो जाएँगे।

### वर्ज़निंग {#versioning}
- सिमेंटिक वर्ज़निंग इस्तेमाल करें
- वर्ज़न के बदलावों को डॉक्यूमेंट करें
- इवेंट्स में वर्ज़न ट्रैक करें

## सुरक्षा {#security}

- **डिफ़ॉल्ट रूप से मना**: कोई भी अघोषित टूल चलाया नहीं जा सकता
- **सत्यापन**: सभी इनपुट Zod से सत्यापित होते हैं
- **नीतियाँ**: हर कार्रवाई से पहले जाँची जाती हैं
- **ट्रेसबिलिटी**: सभी कार्रवाइयाँ ट्रेस होती हैं
- **ऑडिट**: पूरे ऑडिट के लिए रीप्ले उपलब्ध है
