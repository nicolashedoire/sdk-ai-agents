# मुख्य शब्द, आसान भाषा में

इन दस्तावेज़ों में इस्तेमाल हुआ हर शब्द, बिना भारी-भरकम भाषा के समझाया गया, साथ में उस पेज का link जहाँ उसका विस्तार है। शब्द विषय के हिसाब से समूहों में हैं; किसी शब्द पर सीधे जाने के लिए खोज बॉक्स (<kbd>/</kbd>) इस्तेमाल करें।

## बुनियादी बातें {#the-basics}

| शब्द | आसान भाषा में |
| --- | --- |
| **SDK** | डेवलपरों के लिए एक टूलबॉक्स: ऐसा कोड जिसे आप सब कुछ खुद लिखने की बजाय अपने एप्लिकेशन में जोड़ते हैं। यह TypeScript में लिखा गया है; यह अभी npm पर नहीं है और GitHub से इंस्टॉल होता है (देखें [शुरुआत करें](./getting-started))। |
| **भाषा मॉडल (Language model, LLM)** | वह AI जो टेक्स्ट पढ़ता और लिखता है (GPT-4o, Claude…)। यहाँ यह कई घटकों में से एक है: यह प्रस्ताव रखता है, SDK जाँचता है और तय करता है कि किस चीज़ की अनुमति है। |
| **Prompt** | हर अनुरोध के साथ भाषा मॉडल को भेजे जाने वाले टेक्स्ट निर्देश। |
| **Token** | किसी शब्द का एक टुकड़ा। मॉडल प्रदाता पढ़े और लिखे गए हर token का बिल बनाते हैं, इसीलिए [लागत](./costs) tokens में गिनी जाती है। |
| **एजेंट (Agent)** | एक प्रोग्राम जो कदम-दर-कदम किसी लक्ष्य तक पहुँचने के लिए भाषा मॉडल का इस्तेमाल करता है। SDK में दो तरह के एजेंट हैं: [नियंत्रित एजेंट](./governed-agents) जो टूल के साथ कार्रवाई करते हैं, और [संज्ञानात्मक एजेंट](./cognitive-agents) जो निष्कर्ष निकालने से पहले तर्क करते हैं। |
| **Run** | किसी एक समस्या पर एजेंट का एक बार शुरू से अंत तक चलना। इसका एक id (`runId`) होता है जिससे आप इसे पढ़ते, रीप्ले करते या इसकी लागत निकालते हैं। |
| **टूल (Tool)** | एक फ़ंक्शन जो आपका कोड एजेंट को देता है (डेटाबेस पढ़ना, ईमेल भेजना…)। एजेंट सिर्फ़ वही टूल इस्तेमाल कर सकता है जो उसे स्पष्ट रूप से दिए गए हों। देखें [मुख्य अवधारणाएँ](./concepts#_2-tool)। |
| **क्षमता (Capability)** | टूल का एक नाम वाला समूह, जिसे आप एक साथ कई एजेंटों को दे सकते हैं। |
| **नीति (Policy)** | हर कार्रवाई से **पहले** जाँचा जाने वाला नियम: एक बजट, एक समय-सीमा, अनुमति वाले टूल की सूची, या आपकी अपनी जाँच। |
| **मंज़ूरी (Approval)** | किसी जोखिम भरी कार्रवाई से पहले का विराम, जब तक कोई इंसान हाँ न कहे। कोई नीति इसकी माँग कर सकती है, या खुद टूल (`requiresApproval`); अगर कॉल करने वाला पहले ही हार मान ले, तो कार्रवाई कभी नहीं चलती। |
| **इरादा (Intention)** | नियंत्रित एजेंट का मॉडल जो *करना चाहता है* (कोई टूल कॉल करना, जवाब देना…), लिखा हुआ पर लागू नहीं किया गया: SDK पहले उसे सत्यापित करता है। |
| **स्कीमा (Schema, Zod)** | उस आकार का सटीक विवरण जो डेटा का होना चाहिए। टूल कॉल और तर्क के कदमों के संरचित जवाब एक स्कीमा के सामने जाँचे जाते हैं; जो जवाब उसमें फ़िट न हो, वह ठुकरा दिया जाता है। |
| **JSON** | संरचित डेटा के लिए एक सादा टेक्स्ट फ़ॉर्मेट। प्रोफ़ाइल, इवेंट और मॉडल के जवाब JSON होते हैं। |

## ट्रेसबिलिटी {#traceability}

| शब्द | आसान भाषा में |
| --- | --- |
| **इवेंट (Event)** | लॉगबुक की एक लाइन: "यह हुआ, इस समय"। हर run का हर कदम एक इवेंट के रूप में दर्ज होता है। देखें [इवेंट सूची](../reference/events)। |
| **इवेंट स्टोर (Event store)** | जहाँ लॉगबुक रखी जाती है: फ़ाइलों का एक फ़ोल्डर, SQLite या PostgreSQL। |
| **इवेंट सोर्सिंग (Event sourcing)** | यह नियम कि लॉगबुक ही सच है: किसी run की स्थिति, उसकी मानसिक स्थिति सहित, उसके इवेंट्स दोबारा पढ़कर बनाई जाती है, कभी अलग से सहेजी नहीं जाती। यही हर run को महीनों बाद भी ऑडिट करने योग्य बनाता है। विचारक प्रोफ़ाइल अपवाद है: इवेंट सिर्फ़ उसका id और वर्ज़न दर्ज करते हैं, इसलिए प्रोफ़ाइल को खुद सहेजें। |
| **ट्रेस (Trace)** | किसी एक run के सभी इवेंट, क्रम से। |
| **रीप्ले (Replay)** | दर्ज किए गए run को उसके इवेंट्स से दोबारा चलाना: उसने जो कार्रवाइयाँ तय की थीं वे फिर से लागू होती हैं, उन्हीं नीतियों से होकर, भाषा मॉडल से दोबारा पूछे बिना। किसी run का ऑडिट करने या किसी नीति को बदलने के बाद "अगर ऐसा होता तो?" परखने के लिए उपयोगी। देखें [ट्रेसबिलिटी और रीप्ले](./observability)। |
| **गोल्डन ट्रेस (Golden trace)** | एक अच्छा run जिसे आप संदर्भ के रूप में रखते हैं; नए runs उसके सामने जाँचे जाते हैं, ताकि व्यवहार में बदलाव किसी विफल टेस्ट की तरह पकड़ा जाए। |

## संज्ञानात्मक एजेंट कैसे तर्क करता है {#how-a-cognitive-agent-reasons}

| शब्द | आसान भाषा में |
| --- | --- |
| **मानसिक स्थिति (Mental state)** | समस्या के बारे में एजेंट के "मन में" इस समय जो कुछ है, वह सब डेटा के रूप में लिखा हुआ: उसने क्या देखा, क्या जानता है, क्या मानकर चल रहा है, क्या नहीं जानता, और किन विकल्पों पर विचार कर रहा है। देखें [मानसिक स्थिति](./cognitive-agents#the-mental-state)। |
| **अवलोकन (Observation)** (`O1`…) | कोई देखी गई चीज़: समस्या के साथ दिया गया कोई माप या दस्तावेज़, किसी टूल का परिणाम, या किसी परीक्षण का परिणाम। |
| **तथ्य (Fact)** (`F1`…) | ऐसा कथन जिसे एजेंट सच मानता है, साथ में यह कि वह कहाँ से आया। तथ्य कभी मिटाया नहीं जाता: उसे कारण के साथ *वापस लिया* (retracted) या *बदला* (superseded) जाता है। |
| **धारणा (Assumption)** (`A1`…) | ऐसी बात जिसे तर्क बिना सबूत मानकर चलता है। |
| **बाध्यता (Constraint)** (`K1`…) | ऐसी बात जिसका हर उत्तर को पालन करना होगा ("Q4 से पहले", "10k EUR से कम")। |
| **अज्ञात (Unknown)** (`U1`…) | एक खुला सवाल। इसे *सुलझाया* (resolved, जवाब मिल गया) या *छोड़ा* (dropped, जवाब पाने का कोई रास्ता नहीं) जा सकता है। |
| **परिकल्पना (Hypothesis)** (`H1`…) | विचाराधीन एक विकल्प। यह तीन में से एक प्रकार की होती है: **प्रस्ताव** (proposal, कार्रवाई का चुनाव: "नौकरी को मना करना"), **नियम** (rule, एक नियमितता: "लुढ़कने का समय द्रव्यमान पर निर्भर नहीं करता") या **व्याख्या** (explanation, एक कारण)। |
| **आगमन, व्याख्यात्मक अनुमान, निगमन (Induction, abduction, deduction)** | किसी परिकल्पना तक पहुँचने के तीन तरीके: बार-बार के मामलों से एक नियम तक; किसी अचरज से उसके सबसे संभावित कारण तक; किसी नियम से उस तक जो ज़रूर होना चाहिए। यह लेबल घोषित किया जाता है, इससे दावा सच नहीं हो जाता। |
| **ऑपरेशन (Operation)** | तर्क की एक चाल: समस्या को दर्शाना, परिकल्पना बनाना, सिमुलेशन, आलोचना, तुलना, निर्णय… कुल दस हैं। देखें [ऑपरेशन](./cognitive-agents#the-operations)। |
| **कंट्रोलर (Controller)** | जो अगला ऑपरेशन चुनता है। **ह्यूरिस्टिक** (heuristic) कंट्रोलर एक तय क्रम का पालन करता है, मुफ़्त और अनुमान लगाने योग्य; **टाइप्ड** (typed) कंट्रोलर हर कदम पर Jev से पूछता है। |
| **विचार-पैच (Thought patch)** | किसी एक ऑपरेशन ने मानसिक स्थिति में जो बदला, वह एक इवेंट के रूप में दर्ज। मानसिक स्थिति सभी पैचों को क्रम से लागू करने का नतीजा है। |
| **सिमुलेशन (Simulation)** | कल्पना करना कि अगर कोई परिकल्पना सच होती तो क्या होता: पहले सीधे असर, फिर अप्रत्यक्ष असर। |
| **आलोचना (Critique)** | एजेंट का अपने ही विकल्प पर हमला: वह सबसे मज़बूत कारण जिससे वह विफल हो सकता है। बिना जवाब की **घातक** (fatal) आलोचना विकल्प को अस्वीकार कर देती है। |
| **विरोधाभास (Contradiction)** (`C1`…) | दो बातें जो एक साथ सच नहीं हो सकतीं। यह तब तक खुला रहता है जब तक उसे सुलझाने वाले अवलोकनों या तथ्यों का हवाला देकर सुलझाया न जाए। |
| **वेरिएंट (Variant)** | किसी ऐसी परिकल्पना का सुधरा हुआ रूप जिसका साक्ष्य ने खंडन किया, संकरे दायरे या जोड़ी गई शर्त के साथ, और एक वाक्य जो बताए कि क्या बदला। |
| **सीमाएँ (Limits)** | किसी run का बजट: कदमों की संख्या, समय, टूल कॉल, परीक्षण, और निष्कर्ष निकालने के सीमा-मान। देखें [सीमाएँ](./cognitive-agents#limits)। |

## साक्ष्य और निष्कर्ष {#evidence-and-conclusions}

| शब्द | आसान भाषा में |
| --- | --- |
| **उद्गम (Provenance)** | साक्ष्य का कोई टुकड़ा कहाँ से आता है: आपके द्वारा दिया गया, किसी टूल द्वारा लौटाया गया, या किसी परीक्षण द्वारा मापा गया, साथ में वह इवेंट जिसमें मूल सामग्री है। |
| **मूल-समूह (Origin group)** (`originGroup`) | "एक ही स्रोत" का लेबल। एक ही मूल से आए दो अवलोकन दो स्वतंत्र पुष्टियाँ नहीं हैं। |
| **डुप्लिकेट (Duplicate)** | उसी मूल से वही सामग्री, दोबारा देखी गई। इससे कोई वज़न नहीं बढ़ता। |
| **पूर्वानुमान (Prediction)** (`P1`…) | अगर कोई परिकल्पना सही है तो क्या दिखना चाहिए, यह उसे परखने से **पहले** दर्ज किया जाता है। |
| **खंडक (Falsifier)** | वह अवलोकन जो परिकल्पना को गलत साबित कर देगा। जिस दावे को गलत साबित ही न किया जा सके, उसे परखा नहीं जा सकता। |
| **ज्ञान (Knowledge)** (`M1`…) | पहले के runs ने असली परीक्षणों से जो स्थापित किया, वह run की शुरुआत में याद किया जाता है: *verified* (सत्यापित), *refuted* (खंडित), या *contested* (विवादित) जब परीक्षण असहमत हों। देखें [runs के बीच स्मृति](./memory)। |
| **दायरा (Scope)** | किसी स्मृति की सीमा: runs जो सीखते हैं वह सिर्फ़ एक ही दायरे के भीतर साझा करते हैं, जैसे एक टेस्ट बेंच या एक प्रोडक्ट। |
| **परिणाम मूल्यांकनकर्ता (Outcome evaluator)** | आपका कोड जो किसी पूर्वानुमान को दुनिया के सामने रखता है (एक माप, एक सिम्युलेटर, एक टेस्ट सूट) और *confirmed* (पुष्ट), *refuted* (खंडित) या *inconclusive* (अनिर्णायक) उत्तर देता है। भाषा मॉडल कभी अपने ही पूर्वानुमानों को अंक नहीं देता। देखें [पूर्वानुमान](./evidence-and-verification#predictions-and-the-outcome-evaluator)। |
| **समर्थन (Support)** | साक्ष्य किसी परिकल्पना का कितना अच्छा समर्थन करते हैं, 0 (खंडित) से 1 (स्थापित) तक। यह एक आकलन है, मापी गई संभावना नहीं। कोड कभी इसमें पसंद नहीं मिलाता; भाषा-मॉडल जज के साथ, यह उसके निर्देशों पर निर्भर करता है (देखें [साक्ष्य पसंद नहीं है](./evidence-and-verification#evidence-is-not-preference))। |
| **पसंद से मेल (Preference fit)** (`preferenceFit`) | कार्रवाई का कोई चुनाव विचारक के कितना अनुकूल है, 0 (उसके किसी अस्वीकृति मानदंड पर खरा उतरता है) से 1 (आदर्श) तक। यह सिर्फ़ कार्रवाई के चुनावों को मिलता है। |
| **रैंकिंग (Ranking)** | विकल्पों का क्रम। दावों की रैंकिंग सिर्फ़ समर्थन से होती है; कार्रवाई के चुनावों की, डिफ़ॉल्ट रूप से, 60% समर्थन और 40% पसंद से मेल से। |
| **पुराना पड़ चुका (Stale)** | ऐसा आकलन जो साक्ष्य में पिछले बदलाव से पहले किया गया था। निष्कर्ष निकालने से पहले इसे दोबारा करना होगा। |
| **निष्कर्ष गार्ड (Conclusion guard)** | कोड में लिखी वे जाँचें जिन्हें किसी उत्तर को पक्का होने के लिए पार करना होता है: आलोचना हुई हो, पिछले नए साक्ष्य के बाद आकलन हुआ हो, उससे जुड़ा कोई खुला विरोधाभास न हो, बजट में परीक्षण बचे रहते हुए कोई पूर्वानुमान बिना परखा न रहा हो, और पर्याप्त समर्थन हो। देखें [निष्कर्ष गार्ड](./evidence-and-verification#the-conclusion-guard)। |
| **निर्णय सीमा-मान (Decision threshold)** | पक्के उत्तर के लिए ज़रूरी समर्थन: डिफ़ॉल्ट रूप से 0.75, "मज़बूत समर्थन"। कार्रवाई का जो चुनाव विचारक को साफ़ तौर पर पसंद हो, उसे सिर्फ़ 0.35 चाहिए। |
| **पक्का (Committed)** | ऐसा दृढ़ उत्तर जिसने निष्कर्ष गार्ड पार कर लिया। |
| **अस्थायी (Provisional)** | बजट खत्म होने पर उपलब्ध सबसे अच्छा उत्तर, साथ में उन बातों की सूची जो अभी स्थापित नहीं हुईं (`missing`)। |
| **परहेज़ (Abstain)** | "मैं निष्कर्ष नहीं निकाल सकता", कारणों के साथ। एक मान्य परिणाम, कोई error नहीं। |
| **विश्वास स्तर (Confidence)** | निर्णय कितना पक्का है, जो कभी चुने गए विकल्प के साक्ष्य-समर्थन से ऊँचा नहीं होता। |

## किसी व्यक्ति के तर्क की नकल {#imitating-a-person-s-reasoning}

| शब्द | आसान भाषा में |
| --- | --- |
| **विचारक प्रोफ़ाइल (Thinker profile)** | इस बात का विवरण कि कोई खास व्यक्ति **कैसे** तर्क करता है: वह क्रम जिसमें वह किसी समस्या को देखता है, उसकी प्राथमिकताएँ, सहज प्रतिक्रियाएँ, अस्वीकृति मानदंड और जोखिम लेने की रुचि। यह तर्क के हर कदम के निर्देशों में लिखी जाती है, और इसी तरह एजेंट उस व्यक्ति के तर्क की नकल करता है। देखें [विचारक प्रोफ़ाइल](./thinker-profiles)। |
| **नमूना (Sample)** | कोई एक विषय जिसे व्यक्ति ने अपने शब्दों में समझाया: विषय, उसने कैसे तर्क किया, उसने क्या निष्कर्ष निकाला। |
| **सार निकालना (Distill)** | नमूनों से एक प्रोफ़ाइल निकालना: यह पता लगाना कि अलग-अलग विषयों पर व्यक्ति के तर्क करने के तरीके में क्या दोहराया जाता है। |
| **ध्यान का क्रम (Order of attention)** (`reasoningSequence`) | वे कदम जिनसे व्यक्ति गुज़रता है, क्रम से। |
| **ह्यूरिस्टिक (Heuristic)** | एक सहज प्रतिक्रिया, "जब …, तब …" के रूप में लिखी हुई। |
| **अस्वीकृति मानदंड (Rejection criterion)** | कोई कारण जिससे व्यक्ति किसी विचार को छोड़ देता है। |
| **फ़ैसला (Verdict)** | किसी run पर व्यक्ति का निर्णय: `match` (मेरी तरह तर्क किया), `partial`, या `mismatch`। |
| **सहमति (Agreement)** | व्यक्ति किसी run के कितने हिस्से से सहमत है, 0 से 1 तक: `0.8` का मतलब है "80% सही"। इसी से आप मापते हैं कि नकल कितनी करीब पहुँचती है। |
| **कैलिब्रेशन उदाहरण (Calibration example)** | ऐसा run जिसे व्यक्ति ने मान्य किया, और जो मॉडल को आदर्श उत्तर के रूप में दिखाया जाता है। |
| **सुधार (Correction)** | ऐसे run का सबक जिससे व्यक्ति असहमत था, जो मॉडल को उसकी सबसे ऊँची प्राथमिकता के रूप में दिखाया जाता है। |

## अध्ययन {#studies}

| शब्द | आसान भाषा में |
| --- | --- |
| **अध्ययन (Study)** | एक AI शोधकर्ता (`sdk.createStudy`): यह किसी वस्तु को समझता है, फिर आज के ज्ञान और तकनीकों से उसे नए सिरे से डिज़ाइन करने का प्रस्ताव रखता है, और वे प्रयोग डिज़ाइन करता है जो फ़ैसला करेंगे। यह कुछ नहीं बनाता और कुछ नहीं मापता। देखें [अध्ययन](./studies)। |
| **चरण (Passage)** | अध्ययन के सात पड़ावों में से एक: देखना, पुर्ज़े अलग करना, अपने समय के चुनावों को समझना, जो बदला उसकी जाँच करना, अतीत और वर्तमान को मिलाना, डिज़ाइन करना, आमना-सामना कराना। कोई चरण पहले के किसी चरण को दोबारा खोल सकता है। |
| **चार्टर (Charter)** | अध्ययन का ढाँचा: वस्तु, मार्गदर्शक सवाल, उद्देश्य, ज़रूरतें, आपके सुराग, और क्या दायरे से बाहर है। अध्ययन बनते ही इसे फ़्रीज़ कर दिया जाता है, और हर prompt इसी से शुरू होता है। |
| **सुराग (Lead)** | एक विचार जिसे आप अध्ययन को जाँचने के लिए देते हैं। यह जाँचा जाने वाला उदाहरण है, सच नहीं: अध्ययन कारणों के साथ बताता है कि यह प्रासंगिक है या नहीं, और इससे आगे भी देखता है। |
| **दावे की स्थिति (Claim status)** | अध्ययन के किसी कथन का कितना वज़न है: **स्थापित** (established, ऐसे स्रोत से समर्थित जो अध्ययन को सचमुच मिला), **परिकल्पना** (hypothesis, संभावित, पर दस्तावेज़ों से पुष्ट नहीं) या **नवीनता** (novelty, एक नया विचार, जिसे पहले से मौजूद काम के सामने जाँचना है)। इसे कोड जाँचता है, मॉडल नहीं। देखें [स्थापित, परिकल्पना, नवीनता](./studies#established-hypothesis-novelty)। |
| **पूर्व कार्य (Prior art)** | नए बताए गए किसी विचार के सबसे नज़दीक का मौजूदा काम। नवीनता तब तक "जाँच बाकी" रहती है जब तक अध्ययन उसका पूर्व कार्य खोज न ले। |
| **संरक्षक (Guardian)** | अध्ययन के हर चरण के बाद एक अलग जाँच: यह सिर्फ़ चार्टर और चरण के बनाए आइटम देखता है, और जो उद्देश्य से भटकता है उसे हटा देता है। देखें [संरक्षक](./studies#the-guardian)। |
| **भटकाव, भटकाव लॉग (Drift, drift log)** | भटकाव यानी मॉडल का धीरे-धीरे अपने विषय से दूर जाना। भटकाव लॉग उन सब चीज़ों की सूची है जिन्हें अध्ययन ने इस वजह से हटाया, और क्यों। |
| **संशोधन (Amendment)** | अध्ययन बनने के बाद उसमें जोड़ा गया निर्देश। यह सिर्फ़ तब स्वीकार होता है जब यह उद्देश्य को और सटीक बनाता है; जो चार्टर का खंडन करे या उद्देश्य बदले, वह ठुकरा दिया जाता है। |
| **नई क्षमता (New capability)** | कुछ ऐसा जो आज कठिन या असंभव है और सिद्धांत में बदलाव के ज़रिए संभव हो जाता है — **बेहतरी** (improvement) के उलट, जो सिर्फ़ किसी चीज़ को तेज़ या सस्ता बनाती है। |
| **संयोजन से बनी सफलता (Breakthrough by assembly)** | पहले से मौजूद तकनीकों से बनी बड़ी सफलता, जिन्हें एक नए तरीके से जोड़ा गया। Bitcoin ऐसी ही एक सफलता है: हस्ताक्षर, hash chains, proof of work और peer-to-peer नेटवर्क, सब पहले से ज्ञात थे। |
| **तंत्र कार्ड (Mechanism card)** | किसी एक तंत्र के बारे में ग्यारह सवाल, जो देखा गया उससे लेकर जो निष्कर्ष निकला उस तक। अध्ययन पहले नौ के जवाब देता है; आख़िरी दो के जवाब आप प्रयोग चलाने के बाद देते हैं। |

## टाइप्ड निर्णय और कनेक्टर {#typed-decisions-and-connectors}

| शब्द | आसान भाषा में |
| --- | --- |
| **Jev** | TypeSafe का एक मॉडल जो सीमित सवालों (हाँ/ना, एक चुनाव, एक रेटिंग) के जवाब ऐसी संभावनाओं के साथ देता है जिन्हें आपका कोड इस्तेमाल कर सके, तेज़ी से और सस्ते में। देखें [टाइप्ड निर्णय](./typed-decisions)। |
| **Noul, Choice, Score** | Jev के तीन तरह के सवाल: हाँ या ना; एक सूची में से एक विकल्प; किसी पैमाने पर एक स्तर। कई विकल्प चुनने के लिए हर विकल्प पर एक हाँ/ना सवाल पूछा जाता है। |
| **कैलिब्रेटेड (Calibrated)** | ऐसी संभावना जो औसतन हकीकत से मेल खाती है: 80% विश्वास के साथ दिए गए उत्तरों में से लगभग 80% सही होते हैं। |
| **AI Gateway** | Vercel की एक सेवा जो एक ही key से कई मॉडलों तक पहुँच देती है, Jev सहित। |
| **MCP** | Model Context Protocol: AI एप्लिकेशन (Claude Desktop, Claude Code, IDE सहायक, एजेंट) और आपके सिस्टम के बीच एक मानक "प्लग"। SDK किसी फ़ंक्शन, वेब API, फ़ोल्डर, डेटाबेस या एजेंट को MCP सर्वर में बदल सकता है, और किसी भी MCP सर्वर के टूल इस्तेमाल कर सकता है। देखें [MCP आसान भाषा में](./mcp)। |
| **MCP सर्वर (MCP server)** | आपके किसी सिस्टम के सामने एक छोटा प्रोग्राम जो AI एप्लिकेशन को बताता है कि वह क्या देता है, और माँगे जाने पर काम करता है। देखें [आपका पहला MCP सर्वर](./mcp-first-server)। |
| **MCP क्लाइंट, host (MCP client, host)** | host वह AI एप्लिकेशन है जिससे उपयोगकर्ता बात करता है; उसके अंदर, एक MCP क्लाइंट किसी एक सर्वर से कनेक्शन रखता है। |
| **रिसोर्स (Resource)** | एक दस्तावेज़ जिसे MCP सर्वर पढ़ने के लिए देता है, जैसे किसी साझा फ़ोल्डर की फ़ाइल। टूल के उलट, इसे मॉडल नहीं, बल्कि उपयोगकर्ता या एप्लिकेशन चुनता है। |
| **ट्रांसपोर्ट (Transport)** | MCP एप्लिकेशन और सर्वर आपस में संदेश कैसे भेजते हैं: **stdio** (एप्लिकेशन सर्वर को उसी कंप्यूटर पर एक प्रोग्राम के रूप में शुरू करता है और उसके input और output के ज़रिए बात करता है) या **Streamable HTTP** (सर्वर एक वेब सेवा है)। देखें [stdio या HTTP?](./mcp-deploy#stdio-or-http)। |
| **OpenAPI** | किसी वेब API का मानक, मशीन द्वारा पढ़ा जा सकने वाला विवरण: उसके पते, पैरामीटर और उत्तर, अक्सर `openapi.json` के रूप में प्रकाशित। इससे SDK हर operation के लिए एक टूल बनाता है। देखें [एक वेब API](./mcp-recipes#a-web-api-from-its-openapi-description)। |
| **JSON Schema** | किसी डेटा के आकार का विवरण — यहाँ, किसी टूल के arguments का — जिसे मॉडल और MCP एप्लिकेशन टूल को सही तरह कॉल करने के लिए पढ़ते हैं। SDK इसे आपके Zod स्कीमा या OpenAPI विवरण से लिखता है। |
| **केवल-पढ़ने-योग्य (Read-only)** | देख सकता है, बदल नहीं सकता। फ़ोल्डर और डेटाबेस स्रोत बनावट से ही केवल-पढ़ने-योग्य हैं; वेब API डिफ़ॉल्ट रूप से केवल-पढ़ने-योग्य हैं (सिर्फ़ `GET` operations)। |
| **टूल स्रोत (Tool source)** | एक फ़ंक्शन जो किसी सिस्टम से पहले से तैयार टूल बनाता है: `openApiTools`, `folderTools`, `databaseTools`, `webTools`, `governedAgentTool`, `cognitiveAgentTool`, और किसी भी MCP सर्वर के टूल के लिए `connectMcpServer`। इन्हें एक लाइन में MCP पर सर्व करें, या अपने एजेंटों को दें। देखें [टूल](./tools), [किसी भी चीज़ के लिए MCP सर्वर](./mcp-recipes) और [वेब पर शोध](./web-research)। |

## production में संचालन {#operating-in-production}

| शब्द | आसान भाषा में |
| --- | --- |
| **दोबारा प्रयास (Retry)** | विफल अनुरोध को थोड़े इंतज़ार के बाद फिर से आज़माना, जब विफलता अस्थायी हो। देखें [दोबारा प्रयास और फ़ॉलबैक](./resilience)। |
| **फ़ॉलबैक, फ़ेलओवर (Fallback, failover)** | जब पहला मॉडल या प्रदाता बार-बार विफल हो, तो दूसरे पर चले जाना। |
| **घटना (Incident)** | विफल run, रोकी गई कार्रवाई या फ़ेलओवर, जिसे एक अलर्ट में बदलकर ईमेल या वेबहुक से आपको भेजा जाता है। देखें [घटना अलर्ट](./incidents)। |
| **वेबहुक (Webhook)** | एक पता जो आपका चैट या निगरानी टूल आपको देता है, और जिस पर SDK अलर्ट भेजता है। |
