# Перевод документации

Документация написана на английском языке и переведена на десять языков: французский, испанский, немецкий, упрощённый китайский, бразильский португальский, японский, корейский, русский, арабский и хинди. Меню языков в верхней части каждой страницы переключает между ними.

::: tip Простыми словами
Эталон — английский. Каждый другой язык — это копия английских страниц, в которой переведён текст, а всё остальное сохранено без изменений: код, ссылки, таблицы и якоря заголовков. Проверка, которую запускает CI, отклоняет изменение, после которого перевод отстаёт от оригинала.
:::

## Где что находится {#where-things-are}

| Что | Где |
| --- | --- |
| Английские страницы | `docs/guide/`, `docs/reference/`, `docs/contributing/`, `docs/index.md` |
| Перевод | Те же файлы в `docs/<code>/`, например `docs/fr/guide/memory.md` |
| Меню, кнопки, тексты поиска | `docs/.vitepress/i18n/<code>.ts`, переведённые из `i18n/en.ts` |
| Языки и боковая панель | `docs/.vitepress/i18n/structure.ts` |
| Проверка | `docs/.vitepress/check-translations.ts`, запускается командой `npm run docs:check` |

## Правила перевода {#the-rules-of-a-translation}

1. **Переводите текст, остальное сохраняйте.** Блоки кода остаются идентичными английским, включая комментарии, чтобы читатель мог скопировать один и тот же код на любом языке. Имена параметров, имена функций, типы событий и значения вроде `committed` никогда не переводятся.
2. **Сохраняйте английский якорь каждого заголовка.** Другие страницы ссылаются на разделы по их якорю (`./memory#statuses`). Переведённый заголовок заканчивается английским якорем:

   ```md
   ## Statuts {#statuses}
   ```

3. **Сохраняйте ссылки.** Те же ссылки, на те же страницы, в той же папке. На главной странице ссылки во front matter получают префикс языка (`/fr/guide/introduction`).
4. **Сохраняйте структуру.** То же число таблиц и строк в таблицах, те же блоки-выноски (`::: tip`), те же изображения.
5. **Диаграммы можно переводить.** В диаграмме Mermaid переводите только метки; имена узлов и стрелки сохраняйте. Заключайте метку в кавычки, если в ней есть скобки, запятые или другие знаки препинания: `A["Tests (réels)"]`.
6. **Объясняйте каждую вещь.** Перевод пишется для человека, который тоже не знает предмета: сначала простые слова, те же объяснения, что и на английской странице.

## Проверка перевода {#check-a-translation}

```sh
npm run docs:check          # every language
npm run docs:check -- fr    # one language
npm run docs:build          # then build the site
```

`docs:check` сообщает по каждому языку и каждой странице: об отсутствующих или лишних страницах, о коде, который отличается от английского, о заголовке без нужного якоря, об отсутствующей или лишней ссылке, о ссылке на несуществующую страницу, о различиях в таблицах или блоках-выносках, о диаграмме, которая не является корректным Mermaid, а также о тексте или текстах интерфейса, оставшихся на английском. CI запускает эту проверку для каждого pull request.

## Когда вы меняете английскую страницу {#when-you-change-an-english-page}

CI не проходит, пока все языки не будут обновлены. При изменении формулировки обновите тот же фрагмент на каждом языке. Для нового кода, нового заголовка или новой ссылки проверка укажет, какие страницы и какие строки нужно обновить.

## Добавление языка {#add-a-language}

1. Добавьте его в `LANGUAGES` в `docs/.vitepress/i18n/structure.ts`: его код, его тег [BCP 47](https://www.rfc-editor.org/info/bcp47), его название на нём самом и `dir: 'rtl'` для языка, который пишется справа налево.
2. Скопируйте `i18n/en.ts` в `i18n/<code>.ts`, переведите тексты и импортируйте файл в `docs/.vitepress/config.mts`.
3. Переведите каждую страницу в `docs/<code>/`, затем запустите `npm run docs:check -- <code>`.

## Ограничения {#limits}

- **Иллюстрации** (изображения SVG) на всех языках остаются на английском.
- **Поиск** индексирует каждый язык отдельно; в китайском и японском поиск хуже находит целые слова, чем в языках с пробелами между словами.
- **Качество.** Переводы написаны ИИ-моделью и проверены CI на соответствие английской структуре, но не вычитаны носителями каждого языка. Исправления приветствуются: воспользуйтесь ссылкой «Редактировать эту страницу на GitHub» внизу каждой страницы.
