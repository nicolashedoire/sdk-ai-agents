# Выпуск версии

SDK публикуется в npm под именем `@sdk-ai-agents/core`. Никто не публикует его со своего компьютера: рабочий процесс GitHub Actions `Release` ([`release.yml`](https://github.com/nicolashedoire/sdk-ai-agents/blob/main/.github/workflows/release.yml)) проверяет и публикует версию, когда в репозиторий отправляется тег вида `v0.3.0`.

::: tip Простыми словами
Выпуск версии — это три шага: записать новый номер версии и что изменилось, слить это изменение, затем отправить тег с именем версии. GitHub заново запускает проверки и публикует пакет в npm вместе с подписанным заявлением о том, какой коммит и какой рабочий процесс его собрали.
:::

## Что делает рабочий процесс {#what-the-workflow-does}

| Job | Что делает |
| --- | --- |
| `version` | Отклоняет версию в `package.json`, которая не имеет вида `MAJOR.MINOR.PATCH` или `MAJOR.MINOR.PATCH-PRERELEASE`, тег, который не равен `v` плюс эта версия, и тег на коммите, которого нет в `main`. Для релиза (не предварительной версии) отклоняет также `CHANGELOG.md` без раздела `## [x.y.z]` или с чем-либо, оставшимся под `## [Unreleased]`. Выбирает dist-tag npm: `latest`, или `next` для предварительной версии вроде `0.4.0-beta.1`. |
| `verify` | На Node.js 20, 22 и 24 — проверки CI, кроме покрытия и сборки документации: `npm ci`, линтер, проверка форматирования, сборка, проверка типов тестов, тесты и проверка переводов. |
| `pack` | Устанавливает зависимости без их установочных скриптов, собирает `dist/` с нуля и упаковывает пакет. Отклоняет архив, в котором есть что-то кроме `dist/`, `package.json`, `README.md`, `LICENSE` и `CHANGELOG.md` или тестовый файл, а затем сохраняет его как артефакт запуска. |
| `publish` | Единственный job, который может аутентифицироваться в npm: он не извлекает код, ничего не устанавливает и не запускает скриптов. Он проверяет, что версия npm не ниже 11.5.1, и публикует архив из `pack` командой `npm publish --provenance --access public --ignore-scripts`. |

Если хотя бы один job завершается ошибкой, ничего не публикуется. Рабочий процесс запускается по тегу, а не по релизу GitHub, потому что `npm version` и `git tag` и так создают тег: достаточно одного push из терминала, а релиз GitHub можно потом написать на основе тега. Тег, отправленный в форк, запускает проверки и ничего не публикует. Исправление для более старой минорной версии (бэкпорт в другой ветке) так выпустить нельзя: его тег не находится в `main`, а опубликованное как `latest` оно заменило бы самую новую версию. Скрипт `prepublishOnly` (`npm run clean && npm run verify`) защищает ручной `npm publish`; рабочий процесс его не запускает.

## Перед первым выпуском {#before-the-first-release}

Эти шаги выполняет один раз владелец репозитория.

1. **Создать организацию в npm.** У имени пакета есть область (scope): `@sdk-ai-agents`. На npmjs.com под учётной записью, которой будет принадлежать пакет, создайте организацию `sdk-ai-agents` (для публичных пакетов хватает бесплатного тарифа). Пока её нет, npm отвечает «Scope not found», и опубликовать ничего нельзя.
2. **Создать токен для первой версии.** Доверенную публикацию (следующий раздел) можно настроить только для пакета, который уже есть в npm, поэтому первая версия публикуется с токеном. На npmjs.com откройте *Access Tokens* и создайте *granular access token*: право *Read and write* на область `@sdk-ai-agents`, отмеченный флажок *Bypass two-factor authentication* (рабочий процесс не может ввести код) и короткий срок действия, например неделю.
3. **Сохранить его в GitHub.** В настройках репозитория, *Secrets and variables* › *Actions*, создайте секрет репозитория `NPM_TOKEN` со значением токена.
4. После первого выпуска перейдите на доверенную публикацию и удалите токен (см. ниже).

## Выпустить версию {#release-a-version}

1. **Проверить публикуемую ветку.** На актуальной `main`:

   ```sh
   npm run clean && npm run verify   # lint, format, build, type-check, tests, translations
   npm pack --dry-run                # the files that would be published
   ```

   Пакет содержит только `dist/` (JavaScript, объявления типов и source maps, в которые включены исходники), `README.md`, `LICENSE`, `CHANGELOG.md` и `package.json`.

2. **Выбрать номер** по правилам [семантического версионирования](https://semver.org/). Пока версия начинается с `0.`, изменение, ломающее существующий код, увеличивает минорный номер (`0.2.0` → `0.3.0`), а всё остальное — номер патча (`0.3.0` → `0.3.1`): те, кто установил `^0.3.0`, автоматически получают только версии `0.3.x`.

3. **Обновить журнал изменений.** В новой ветке перенесите записи из `## [Unreleased]` в `CHANGELOG.md` под заголовок с версией и датой и оставьте над ним пустой `## [Unreleased]`:

   ```md
   ## [Unreleased]

   ## [0.3.0] - 2026-10-01

   ### Added
   - …
   ```

   Для релиза (не предварительной версии) job `version` отклоняет тег, если такого раздела нет или под `## [Unreleased]` что-то осталось, даже пустой заголовок `###`.

4. **Изменить версию**, пока не создавая тег (тег должен указывать на слитый коммит):

   ```sh
   npm version 0.3.0 --no-git-tag-version
   ```

   Команда обновляет `package.json` и `package-lock.json`. Измените также `const version` в `docs/.vitepress/config.mts` — версию, которую показывает меню сайта документации.

   **Только при первом выпуске:** в этом же коммите замените раздел *Install* в `README.md` текстом ниже. npm показывает README опубликованной версии, и в нём не должно быть «Not on npm yet».

   ````md
   ## Install

   ```sh
   npm install @sdk-ai-agents/core zod@^3.25.28
   npm install @modelcontextprotocol/sdk@^1.30.0   # only for MCP servers and clients
   ```

   Node.js 20+, TypeScript 5+ and zod 3 (≥ 3.25.28; zod 4 is not supported yet). The package is ESM only: `import` it (from CommonJS, use a dynamic `import()`). To try the unreleased `main` branch instead, install it from GitHub — it builds itself on install: `npm install github:nicolashedoire/sdk-ai-agents`.
   ````

5. **Слить.** Сделайте коммит (`chore(release): 0.3.0`), откройте pull request, дождитесь CI и слейте его.

6. **Отправить тег** на слитый коммит:

   ```sh
   git switch main
   git pull
   git tag -a v0.3.0 -m "v0.3.0"
   git push origin v0.3.0
   ```

7. **Следить за запуском** на вкладке *Actions* репозитория, рабочий процесс *Release*.

8. **После выпуска.** Укажите новую версию `@sdk-ai-agents/core` (`^0.3.0`) в `templates/starter-template/package.json`. Только после первого выпуска слейте также pull request ветки `docs/npm-install`: пока пакета нет в npm, инструкции по установке ставят его с GitHub.

Отправляйте теги по одному: GitHub не запускает ни одного рабочего процесса, если за раз отправлено больше трёх тегов, а `git push --tags` может так сделать. Предварительная версия (`npm version 0.4.0-beta.1 --no-git-tag-version`, тег `v0.4.0-beta.1`) публикуется под dist-tag `next`: она устанавливается через `@sdk-ai-agents/core@next`, а `npm install @sdk-ai-agents/core` по-прежнему даёт последнюю стабильную версию.

## Проверить опубликованный пакет {#check-the-published-package}

```sh
npm view @sdk-ai-agents/core version dist-tags
```

Страница пакета на npmjs.com показывает раздел *Provenance* со ссылками на коммит и на запуск рабочего процесса, которые его собрали. Чтобы попробовать пакет так, как это сделал бы пользователь, в пустой папке:

```sh
npm init -y
npm pkg set type=module
npm install @sdk-ai-agents/core zod@^3.25.28
node -e "import('@sdk-ai-agents/core').then((sdk) => console.log(typeof sdk.createSDK))"
npm audit signatures
```

`function` означает, что пакет загружается. `npm audit signatures` проверяет подписи реестра и аттестации происхождения установленных пакетов.

## Перейти на доверенную публикацию {#switch-to-trusted-publishing}

Когда первая версия уже есть в npm, рабочий процесс может публиковать вообще без секретов: npm доверяет OIDC-идентификатору, который GitHub выдаёт запуску рабочего процесса. Не остаётся долгоживущего секрета, который мог бы утечь, а сведения о происхождении добавляются всегда.

1. На npmjs.com откройте *Settings* пакета, раздел *Trusted publishing*, и добавьте издателя GitHub Actions: пользователь `nicolashedoire`, репозиторий `sdk-ai-agents`, файл рабочего процесса `release.yml`, без окружения. Разрешите ему публиковать через `npm publish` (рабочий процесс публикует напрямую и не откладывает версии на подтверждение). Все поля чувствительны к регистру.
2. В тех же настройках, в разделе *Publishing access*, выберите *Require two-factor authentication and disallow tokens*.
3. Удалите секрет `NPM_TOKEN` в GitHub и токен на npmjs.com.

Рабочий процесс не меняется: npm 11.5.1 или новее (это проверяет job `publish`) сначала пробует доверенную публикацию и использует `NPM_TOKEN`, только если она не настроена. npm объявил, что прямая публикация с granular access token перестанет работать в январе 2027 года, так что этот переход нужен в любом случае. См. документацию npm о [доверенной публикации](https://docs.npmjs.com/trusted-publishers) и о [происхождении пакетов](https://docs.npmjs.com/generating-provenance-statements).

## Если что-то пошло не так {#if-something-goes-wrong}

- **Job `version` или одна из проверок завершается ошибкой.** Ничего не опубликовано. Удалите тег, исправьте причину через pull request, затем поставьте тег на новый слитый коммит:

  ```sh
  git tag -d v0.3.0
  git push origin :refs/tags/v0.3.0
  ```

- **`publish` завершается ошибкой «Scope not found» или 404.** Организации в npm ещё нет, или токен не может в неё записывать.
- **`publish` завершается ошибкой 403 о том, что версия уже опубликована.** Номер версии в npm можно использовать только один раз: увеличьте его и выпустите версию снова.
- **Опубликованная версия сломана.** Пометьте её командой `npm deprecate @sdk-ai-agents/core@0.3.0 "Broken, use 0.3.1"` и выпустите исправление. npm позволяет удалить версию только на условиях своей [политики отмены публикации](https://docs.npmjs.com/policies/unpublish), а её номер больше никогда нельзя использовать.
- **`publish` завершился ошибкой по временной причине** (npm недоступен, сеть). Перезапустите упавшие jobs со страницы запуска: `publish` скачивает архив, который `pack` хранит как артефакт 7 дней. После этого срока перезапустите все jobs.
