# Ключевые термины простыми словами

Все термины, используемые в этой документации, объяснены без жаргона, со ссылкой на страницу с подробностями. Термины сгруппированы по темам; чтобы быстро перейти к нужному, воспользуйтесь полем поиска (<kbd>/</kbd>).

## Основы {#the-basics}

| Термин | Простыми словами |
| --- | --- |
| **SDK** (SDK) | Набор инструментов для разработчиков: код, который вы добавляете в своё приложение, вместо того чтобы писать всё самостоятельно. Этот SDK написан на TypeScript; его ещё нет в npm, и он устанавливается с GitHub (см. [Быстрый старт](./getting-started)). |
| **Языковая модель, LLM** (language model) | ИИ, который читает и пишет текст (GPT-4o, Claude…). Здесь это один компонент среди прочих: он предлагает, а SDK проверяет и решает, что разрешено. |
| **Промпт** (prompt) | Текстовые инструкции, отправляемые языковой модели с каждым запросом. |
| **Токен** (token) | Фрагмент слова. Провайдеры моделей выставляют счёт за каждый прочитанный и написанный токен, поэтому [затраты](./costs) считаются в токенах. |
| **Агент** (agent) | Программа, которая использует языковую модель, чтобы шаг за шагом достичь цели. В SDK есть два вида: [управляемые агенты](./governed-agents), которые действуют с помощью инструментов, и [когнитивные агенты](./cognitive-agents), которые рассуждают, прежде чем сделать вывод. |
| **Запуск** (run) | Одно выполнение агента над одной задачей, от начала до конца. У него есть идентификатор (`runId`), по которому его можно прочитать, воспроизвести или узнать его стоимость. |
| **Инструмент** (tool) | Функция, которую ваш код даёт агенту (прочитать базу данных, отправить письмо…). Агент может использовать только те инструменты, которые ему явно дали. См. [Основные понятия](./concepts#_2-tool). |
| **Возможность** (capability) | Именованная группа инструментов, которую можно дать сразу нескольким агентам. |
| **Политика** (policy) | Правило, проверяемое **перед** каждым действием: бюджет, тайм-аут, список разрешённых инструментов или ваша собственная проверка. |
| **Одобрение** (approval) | Пауза перед рискованным действием, пока человек не скажет «да». Его может потребовать политика или сам инструмент (`requiresApproval`); если вызывающая сторона сдаётся раньше, действие так и не выполняется. |
| **Намерение** (intention) | То, что модель управляемого агента *хочет* сделать (вызвать инструмент, ответить…), записанное, но не выполненное: сначала его проверяет SDK. |
| **Схема, Zod** (schema) | Точное описание формы, которую должны иметь данные. Вызовы инструментов и структурированные ответы шагов рассуждения проверяются по схеме; ответ, который ей не соответствует, отклоняется. |
| **JSON** (JSON) | Простой текстовый формат для структурированных данных. Профили, события и ответы модели хранятся в JSON. |

## Прослеживаемость {#traceability}

| Термин | Простыми словами |
| --- | --- |
| **Событие** (event) | Строка в журнале: «это произошло в такое-то время». Каждый шаг каждого запуска записывается как событие. См. [каталог событий](../reference/events). |
| **Хранилище событий** (event store) | Место, где хранится журнал: папка с файлами, SQLite или PostgreSQL. |
| **Event sourcing** (event sourcing) | Правило, по которому истиной служит журнал: состояние запуска, включая его ментальное состояние, восстанавливается повторным чтением его событий и никогда не хранится отдельно. Именно поэтому каждый запуск можно проверить и через несколько месяцев. Исключение — профиль мыслителя: события записывают только его идентификатор и версию, поэтому сохраняйте сам профиль. |
| **Трасса** (trace) | Все события одного запуска по порядку. |
| **Воспроизведение** (replay) | Повторное выполнение записанного запуска по его событиям: действия, которые он решил выполнить, выполняются снова через те же политики, без повторного обращения к языковой модели. Полезно, чтобы проверить запуск или проверить сценарий «а что если» после изменения политики. См. [Прослеживаемость и воспроизведение](./observability). |
| **Эталонная трасса** (golden trace) | Удачный запуск, который вы храните как эталон; новые запуски сверяются с ним, поэтому изменение поведения обнаруживается как упавший тест. |

## Как рассуждает когнитивный агент {#how-a-cognitive-agent-reasons}

| Термин | Простыми словами |
| --- | --- |
| **Ментальное состояние** (mental state) | Всё, что агент в данный момент «держит в голове» о задаче, записанное как данные: что он наблюдал, знает, допускает, чего не знает и какие варианты рассматривает. См. [ментальное состояние](./cognitive-agents#the-mental-state). |
| **Наблюдение** (observation, `O1`…) | Что-то увиденное: измерение или документ, которые вы передали вместе с задачей, результат инструмента или результат теста. |
| **Факт** (fact, `F1`…) | Утверждение, которое агент считает истинным, с указанием его источника. Факт никогда не удаляется: он *отзывается* (retracted) или *заменяется* (superseded) с указанием причины. |
| **Допущение** (assumption, `A1`…) | То, что рассуждение принимает как данность без доказательства. |
| **Ограничение** (constraint, `K1`…) | То, что должен соблюдать любой ответ («до Q4», «меньше 10k EUR»). |
| **Неизвестное** (unknown, `U1`…) | Открытый вопрос. Его можно *разрешить* (resolved — получить ответ) или *отбросить* (dropped — ответить на него невозможно). |
| **Гипотеза** (hypothesis, `H1`…) | Рассматриваемый вариант. Гипотеза бывает одного из трёх видов: **предложение** (proposal — выбор действия: «отказаться от работы»), **правило** (rule — закономерность: «время скатывания не зависит от массы») или **объяснение** (explanation — причина). |
| **Индукция, абдукция, дедукция** (induction, abduction, deduction) | Три способа прийти к гипотезе: от повторяющихся случаев к правилу; от неожиданности к её наиболее вероятной причине; от правила к тому, что из него должно следовать. Метка объявляется, но не делает утверждение истинным. |
| **Операция** (operation) | Один ход рассуждения: представить задачу, выдвинуть гипотезу, смоделировать, покритиковать, сравнить, решить… Всего их десять. См. [операции](./cognitive-agents#the-operations). |
| **Контроллер** (controller) | То, что выбирает следующую операцию. **Эвристический** контроллер следует фиксированному порядку, бесплатен и предсказуем; **типизированный** контроллер спрашивает Jev на каждом шаге. |
| **Патч мысли** (thought patch) | То, что одна операция изменила в ментальном состоянии, записанное как одно событие. Ментальное состояние — это все патчи, применённые по порядку. |
| **Симуляция** (simulation) | Представить, что произошло бы, если бы гипотеза была верна: сначала непосредственные последствия, затем косвенные. |
| **Критика** (critique) | Агент атакует собственный вариант: ищет самую серьёзную причину, по которой тот может не сработать. **Фатальная** критика без ответа отвергает вариант. |
| **Противоречие** (contradiction, `C1`…) | Две вещи, которые не могут быть истинными одновременно. Противоречие остаётся открытым, пока его не разрешат, сославшись на наблюдения или факты, которые его разрешают. |
| **Вариант** (variant) | Исправленная версия гипотезы, которой противоречат доказательства, — с более узкой областью или добавленным условием и фразой о том, что изменилось. |
| **Лимиты** (limits) | Бюджет запуска: число шагов, время, вызовы инструментов, тесты и пороги для вывода. См. [Лимиты](./cognitive-agents#limits). |

## Доказательства и выводы {#evidence-and-conclusions}

| Термин | Простыми словами |
| --- | --- |
| **Происхождение** (provenance) | Откуда взялось доказательство: передано вами, возвращено инструментом или измерено тестом, — вместе с событием, в котором хранится оригинал. |
| **Группа происхождения** (origin group, `originGroup`) | Метка «тот же источник». Два наблюдения из одного источника — это не два независимых подтверждения. |
| **Дубликат** (duplicate) | То же содержимое из того же источника, увиденное снова. Он не добавляет веса. |
| **Предсказание** (prediction, `P1`…) | То, что должно наблюдаться, если гипотеза верна, записанное **до** её проверки. |
| **Фальсификатор** (falsifier) | Наблюдение, которое доказало бы, что гипотеза неверна. Утверждение, неверность которого нельзя доказать, нельзя и проверить. |
| **Знание** (knowledge, `M1`…) | То, что предыдущие запуски установили с помощью реальных тестов и что вспоминается в начале запуска: *подтверждённое* (verified), *опровергнутое* (refuted) или *оспариваемое* (contested), если тесты расходятся. См. [Память между запусками](./memory). |
| **Область** (scope) | Граница памяти: запуски делятся тем, что узнали, только в пределах одной области, например одного испытательного стенда или одного продукта. |
| **Оценщик результатов** (outcome evaluator) | Ваш код, который сопоставляет предсказание с миром (измерение, симулятор, набор тестов) и отвечает *подтверждено* (confirmed), *опровергнуто* (refuted) или *не установлено* (inconclusive). Языковая модель никогда не оценивает собственные предсказания. См. [Предсказания](./evidence-and-verification#predictions-and-the-outcome-evaluator). |
| **Поддержка** (support) | Насколько хорошо доказательства подкрепляют гипотезу, от 0 (опровергнута) до 1 (установлена). Это суждение, а не измеренная вероятность. Код никогда не примешивает к ней предпочтения; при судье на основе языковой модели это держится на его инструкциях (см. [Доказательства — не предпочтения](./evidence-and-verification#evidence-is-not-preference)). |
| **Соответствие предпочтениям** (preference fit, `preferenceFit`) | Насколько выбор действия подходит мыслителю, от 0 (соответствует одному из его критериев отказа) до 1 (идеально). Эта оценка есть только у выборов действия. |
| **Ранжирование** (ranking) | Порядок вариантов. Утверждения ранжируются только по поддержке; выборы действия — по умолчанию на 60% по поддержке и на 40% по соответствию предпочтениям. |
| **Устаревшая оценка** (stale) | Оценка, сделанная до последнего изменения доказательств. Перед выводом её нужно сделать заново. |
| **Страж вывода** (conclusion guard) | Проверки, записанные в коде, которые ответ должен пройти, чтобы быть зафиксированным: он подвергся критике, оценён после последнего нового доказательства, нет открытого противоречия, которое его касается, нет непроверенного предсказания, пока в бюджете остаются тесты, и поддержки достаточно. См. [Страж вывода](./evidence-and-verification#the-conclusion-guard). |
| **Порог решения** (decision threshold) | Поддержка, необходимая для твёрдого ответа: по умолчанию 0,75, «сильная поддержка». Выбору действия, который мыслитель явно предпочитает, достаточно 0,35. |
| **Зафиксирован** (committed) | Твёрдый ответ, прошедший страж вывода. |
| **Предварительный** (provisional) | Лучший доступный ответ на момент исчерпания бюджета, со списком того, что ещё не установлено (`missing`). |
| **Воздержаться** (abstain) | «Я не могу сделать вывод» — с причинами. Допустимый результат, а не ошибка. |
| **Уверенность** (confidence) | Насколько решение надёжно; она никогда не превышает поддержку выбранного варианта доказательствами. |

## Подражание рассуждению человека {#imitating-a-person-s-reasoning}

| Термин | Простыми словами |
| --- | --- |
| **Профиль мыслителя** (thinker profile) | Описание того, **как** рассуждает конкретный человек: порядок, в котором он смотрит на задачу, его приоритеты, рефлексы, критерии отказа и отношение к риску. Профиль включается в инструкции каждого шага рассуждения — так агент и подражает рассуждению этого человека. См. [Профили мыслителя](./thinker-profiles). |
| **Образец** (sample) | Одна тема, которую человек объяснил своими словами: тема, как он рассуждал, к какому выводу пришёл. |
| **Выделить** (distill) | Извлечь профиль из образцов: найти то, что повторяется в том, как человек рассуждает на разные темы. |
| **Порядок внимания** (order of attention, `reasoningSequence`) | Шаги, которые человек проходит, по порядку. |
| **Эвристика** (heuristic) | Рефлекс, записанный в виде «когда …, то …». |
| **Критерий отказа** (rejection criterion) | Причина, по которой человек отбрасывает идею. |
| **Вердикт** (verdict) | Суждение человека о запуске: `match` (рассуждал как я), `partial` или `mismatch`. |
| **Согласие** (agreement) | Насколько человек согласен с запуском, от 0 до 1: `0.8` означает «верно на 80%». Так вы измеряете, насколько близко подходит имитация. |
| **Калибровочный пример** (calibration example) | Запуск, который человек одобрил и который показывается модели как образцовый ответ. |
| **Поправка** (correction) | Урок из запуска, с которым человек не согласился, показываемый модели как её высший приоритет. |

## Исследования {#studies}

| Термин | Простыми словами |
| --- | --- |
| **Исследование** (study) | ИИ-исследователь (`sdk.createStudy`): он понимает объект, затем предлагает, как перепроектировать его с помощью знаний и техник сегодняшнего дня, и проектирует эксперименты, которые позволили бы сделать выбор. Сам он ничего не строит и не измеряет. См. [Исследования](./studies). |
| **Этап** (passage) | Один из семи этапов исследования: наблюдать, разложить на части, понять решения своего времени, изучить, что изменилось, сопоставить прошлое и настоящее, спроектировать, подвергнуть проверке. Этап может вновь открыть более ранний. |
| **Устав** (charter) | Рамка исследования: объект, направляющий вопрос, цель, потребности, ваши направления, то, что лежит вне рамок. Он замораживается при создании исследования, и с него начинается каждый промпт. |
| **Направление** (lead) | Идея, которую вы даёте исследованию для изучения. Это пример для проверки, а не истина: исследование говорит, уместно ли оно, с причинами, и ищет дальше. |
| **Статус утверждения** (claim status) | Чего стоит высказывание исследования: **установлено** (подкреплено источником, который исследование действительно нашло), **гипотеза** (правдоподобно, но не задокументировано) или **новшество** (новая идея, которую нужно сверить с существующими работами). Его проверяет код, а не модель. См. [Установленное, гипотеза, новшество](./studies#established-hypothesis-novelty). |
| **Предшествующие работы** (prior art) | Существующие работы, наиболее близкие к идее, представленной как новая. Новшество остаётся «требующим проверки», пока исследование их не поищет. |
| **Страж** (guardian) | Отдельная проверка после каждого этапа исследования: она видит только устав и то, что произвёл этап, и удаляет всё, что уходит от цели. См. [Страж](./studies#the-guardian). |
| **Дрейф, журнал дрейфа** (drift, drift log) | Дрейф — это постепенный уход модели от темы. Журнал дрейфа перечисляет всё, что исследование удалило по этой причине, и почему. |
| **Дополнение** (amendment) | Инструкция, добавленная к исследованию после его создания. Оно принимается, только если уточняет цель; дополнение, которое противоречит уставу или меняет цель, отклоняется. |
| **Новая возможность** (new capability) | Что-то, что становится возможным, хотя сегодня трудно или невозможно, благодаря смене принципа, — в отличие от **улучшения** (improvement), которое лишь делает что-то быстрее или дешевле. |
| **Прорыв за счёт сборки** (breakthrough by assembly) | Прорыв, составленный из уже существовавших техник, соединённых по-новому. Таков Bitcoin: подписи, цепочки хешей, доказательство работы и одноранговая сеть были известны и раньше. |
| **Карточка механизма** (mechanism card) | Одиннадцать вопросов об одном механизме — от того, что наблюдалось, до того, какой сделан вывод. Исследование отвечает на первые девять; на последние два отвечаете вы, когда проведёте эксперимент. |

## Типизированные решения и коннекторы {#typed-decisions-and-connectors}

| Термин | Простыми словами |
| --- | --- |
| **Jev** (Jev) | Модель от TypeSafe, которая отвечает на узкие вопросы (да/нет, выбор, оценка) вероятностями, которые может использовать ваш код, — быстро и дёшево. См. [Типизированные решения](./typed-decisions). |
| **Noul, Choice, Score** (Noul, Choice, Score) | Три типа вопросов Jev: да или нет; один вариант из списка; уровень на шкале. Выбор нескольких вариантов задаёт по одному вопросу «да/нет» на каждый вариант. |
| **Откалиброванная** (calibrated) | Вероятность, которая в среднем соответствует реальности: из ответов, данных с уверенностью 80%, верны примерно 80%. |
| **AI Gateway** (AI Gateway) | Сервис Vercel, который даёт доступ к нескольким моделям, включая Jev, с одним ключом. |
| **MCP** (MCP) | Model Context Protocol: единый стандартный «разъём» между ИИ-приложениями (Claude Desktop, Claude Code, ассистенты в IDE, агенты) и вашими системами. SDK может превратить функцию, веб-API, папку, базу данных или агента в сервер MCP и использовать инструменты любого сервера MCP. См. [MCP простыми словами](./mcp). |
| **Сервер MCP** (MCP server) | Небольшая программа перед одной из ваших систем, которая сообщает ИИ-приложениям, что она предлагает, и выполняет работу по запросу. См. [Ваш первый сервер MCP](./mcp-first-server). |
| **Клиент MCP, хост** (MCP client, host) | Хост — это ИИ-приложение, с которым разговаривает пользователь; внутри него клиент MCP держит соединение с одним сервером. |
| **Ресурс** (resource) | Документ, который сервер MCP предлагает для чтения, например файл из общей папки. В отличие от инструмента, его выбирает пользователь или приложение, а не модель. |
| **Транспорт** (transport) | Способ, которым приложение MCP и сервер обмениваются сообщениями: **stdio** (приложение запускает сервер как программу на том же компьютере и общается через его ввод и вывод) или **Streamable HTTP** (сервер — это веб-сервис). См. [stdio или HTTP?](./mcp-deploy#stdio-or-http). |
| **OpenAPI** (OpenAPI) | Стандартное машиночитаемое описание веб-API: его адреса, параметры и ответы, часто публикуемое как `openapi.json`. По нему SDK создаёт по одному инструменту на каждую операцию. См. [Веб-API](./mcp-recipes#a-web-api-from-its-openapi-description). |
| **JSON Schema** (JSON Schema) | Описание формы данных — здесь аргументов инструмента, — которое читают модели и приложения MCP, чтобы правильно вызвать инструмент. SDK пишет его по вашей схеме Zod или по описанию OpenAPI. |
| **Только для чтения** (read-only) | Можно смотреть, нельзя изменять. Источники «папка» и «база данных» доступны только для чтения по своему устройству; веб-API по умолчанию только для чтения (только операции `GET`). |
| **Источник инструментов** (tool source) | Функция, которая создаёт готовые инструменты из системы: `openApiTools`, `folderTools`, `databaseTools`, `cognitiveAgentTool`, `webTools`. Отдайте их по MCP одной строкой или передайте своим агентам. См. [Сервер MCP для чего угодно](./mcp-recipes) и [Поиск в интернете](./web-research). |

## Эксплуатация в продакшене {#operating-in-production}

| Термин | Простыми словами |
| --- | --- |
| **Повторная попытка** (retry) | Повтор неудавшегося запроса после короткого ожидания, когда сбой временный. См. [Повторные попытки и резерв](./resilience). |
| **Резерв, переключение** (fallback, failover) | Переход на другую модель или другого провайдера, когда первые продолжают давать сбои. |
| **Инцидент** (incident) | Неудачный запуск, заблокированное действие или переключение на резерв, превращённые в оповещение, которое отправляется вам по электронной почте или через вебхук. См. [Оповещения об инцидентах](./incidents). |
| **Вебхук** (webhook) | Адрес, который даёт вам ваш чат или инструмент мониторинга и на который SDK отправляет оповещения. |
