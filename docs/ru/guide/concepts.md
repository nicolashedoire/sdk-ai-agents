# Основные понятия

## Обзор {#overview}

SDK AI Agents — это инфраструктура управления ИИ-агентами, которая отделяет рассуждение от действия и предоставляет встроенный event sourcing для воспроизведения и аудита. Поверх неё [когнитивные агенты](./cognitive-agents) добавляют явный слой рассуждения, а [типизированные решения](./typed-decisions) — откалиброванные структурированные ответы.

::: info Эта страница описывает основы
Агенты, инструменты, возможности, политики, намерения, хранилище событий, трассы и воспроизведение. Всё это одинаково относится и к управляемым, и к когнитивным агентам.
:::

## Фундаментальные понятия {#fundamental-concepts}

### 1. Агент {#_1-agent}

**Агент** — это управляемая система принятия решений, которая использует LLM для генерации намерений, но все действия которой проходят через контролируемый движок действий (Action Engine).

**Характеристики:**
- Минимальная конфигурация (имя, модель LLM)
- Явно объявленные инструменты
- Политики для управления
- Версионирование для отслеживания
- Возможности для организации инструментов

**Пример:**
```typescript
const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-4',
  tools: [calculatorTool],
  version: '1.0.0',
  capabilities: ['math']
})
```

### 2. Инструмент {#_2-tool}

**Инструмент** — это явно объявленная возможность, которую может использовать агент. Все инструменты должны быть зарегистрированы перед использованием (по умолчанию всё запрещено).

**Характеристики:**
- Обязательная схема валидации Zod
- Асинхронный обработчик
- Версионирование
- Привязка к возможности (необязательно)

**Пример:**
```typescript
const calculatorTool = sdk.defineTool({
  name: 'calculator',
  description: 'Performs basic arithmetic',
  schema: z.object({
    operation: z.enum(['add', 'subtract', 'multiply', 'divide']),
    a: z.number(),
    b: z.number()
  }),
  handler: async ({ operation, a, b }) => {
    // Implementation
  },
  version: '1.0.0',
  capability: 'math'
})
```

### 3. Возможность {#_3-capability}

**Возможность** (capability) — это логическая группа инструментов, которую можно повторно использовать в нескольких агентах.

**Характеристики:**
- Имя и описание
- Список связанных инструментов
- Версионирование
- Необязательные метаданные

**Пример (с именами инструментов):**
```typescript
const calculatorTool = sdk.defineTool({ /* ... */ });
const scientificTool = sdk.defineTool({ /* ... */ });

const mathCapability = sdk.defineCapability({
  name: 'math',
  description: 'Mathematical operations',
  tools: ['calculator', 'scientific-calculator'],
  version: '1.0.0'
})

const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-4',
  capabilities: ['math']
})
```

**Пример (непосредственно с объектами Tool):**
```typescript
const calculatorTool = defineTool({ /* ... */ });
const scientificTool = defineTool({ /* ... */ });

const mathCapability = sdk.defineCapability({
  name: 'math',
  description: 'Mathematical operations',
  tools: [calculatorTool, scientificTool],
  version: '1.0.0'
})

const agent = sdk.createAgent({
  name: 'math-assistant',
  model: 'gpt-4',
  capabilities: ['math']
})
```

### 4. Политика {#_4-policy}

**Политика** определяет правила управления, применяемые перед каждым действием.

**Типы политик:**
- **Бюджет** (budget): ограничение числа шагов или токенов
- **Тайм-аут** (timeout): максимальная длительность выполнения
- **Список разрешённых** (allowlist): список авторизованных инструментов
- **Пользовательская** (custom): собственный валидатор

**Пример:**
```typescript
sdk.defineGlobalPolicy({
  id: 'max-steps',
  type: 'budget',
  rules: [{
    condition: 'maxSteps',
    action: 'deny',
    metadata: { value: 10 }
  }],
  scope: 'global',
  enabled: true
})
```

### 5. Намерение {#_5-intention}

**Намерение** — это структура, сгенерированная LLM, которая описывает, что агент хочет сделать, не выполняя этого напрямую.

**Типы:**
- `tool_call`: вызов конкретного инструмента
- `final_answer`: окончательный ответ пользователю
- `continue`: продолжить рассуждение

**Безопасность:**
- Все намерения проверяются движком политик (Policy Engine)
- LLM не выполняет никаких действий напрямую
- Полная прослеживаемость

### 6. Хранилище событий {#_6-event-store}

**Хранилище событий** (Event Store) — единственный источник истины для всех выполнений.

**Характеристики:**
- Автоматическое сохранение (по умолчанию в файлах JSON)
- Пакетная запись для производительности
- Полный экспорт
- Фильтрация по типу, дате и т. д.

**Основные события:**
- `run.started`: начало выполнения
- `intention.generated`: намерение, сгенерированное LLM
- `policy.checked`: проверка политики
- `action.executed`: действие выполнено
- `tool.called`: инструмент вызван
- `run.completed`: выполнение завершено
- `run.failed`: выполнение завершилось ошибкой
- `run.cancelled`: выполнение отменено

### 7. Трасса {#_7-trace}

**Трасса** — это удобное для чтения человеком представление полного выполнения.

**Содержимое:**
- Хронология событий
- Статистическая сводка
- Итоговое состояние
- Метаданные

**Пример:**
```typescript
const trace = await sdk.getTrace(runId)
console.log(trace.summary)
// {
//   totalEvents: 15,
//   duration: 1234,
//   intentionsGenerated: 3,
//   actionsExecuted: 2,
//   policiesChecked: 2,
//   toolsCalled: 2
// }
```

### 8. Воспроизведение {#_8-replay}

**Воспроизведение** (replay) позволяет повторить полное выполнение без повторного обращения к LLM.

**Характеристики:**
- Детерминированность (та же последовательность действий)
- Возможны изменения (входные данные, политики, инструменты)
- Отладка инцидентов
- Регрессионные тесты

**Пример:**
```typescript
const replay = await sdk.replay(runId, {
  input: { message: 'Modified input' }
})
```

## Архитектурные принципы {#architectural-principles}

### 1. Разделение рассуждения и действия {#_1-reasoning-action-separation}

LLM генерирует намерения, но никогда не выполняет действия напрямую. Все действия проходят через движок действий.

### 2. По умолчанию всё запрещено {#_2-deny-by-default}

По умолчанию ничего не разрешено. Все инструменты должны быть явно объявлены (зарегистрированы), прежде чем что-либо сможет их запустить.

::: warning Область действия управляемого агента
Управляемый агент может выполнить **любой инструмент, зарегистрированный в SDK**, который назовёт модель: список `tools` агента определяет, что модели предлагается, а не то, что она может вызвать. Ограничьте его политикой `allowlist` — любой другой инструмент будет отклонён до выполнения:

```ts
const agent = sdk.createAgent({
  name: 'support',
  model: 'gpt-4o',
  tools: [lookupCustomer],
  policies: [
    {
      id: 'support-tools',
      type: 'allowlist',
      scope: 'agent',
      enabled: true,
      rules: [{ condition: 'allowedTools', action: 'deny', metadata: { tools: ['lookup_customer'] } }],
    },
  ],
});
```

Когнитивные агенты и серверы MCP ограничены своим списком инструментов автоматически.
:::

### 3. Встроенный event sourcing {#_3-native-event-sourcing}

Каждое выполнение можно проследить и воспроизвести благодаря event sourcing.

### 4. Встроенное управление {#_4-built-in-governance}

Политики применяются на уровне устройства системы, а не как опция.

### 5. Полное версионирование {#_5-full-versioning}

Агенты, инструменты и возможности версионируются для отслеживания и прослеживаемости.

## Типичный порядок работы {#typical-workflow}

1. **Инициализация**: создайте SDK с ключом API
2. **Определение**: определите инструменты и возможности
3. **Конфигурация**: создайте агента с инструментами и политиками
4. **Выполнение**: запустите агента с входными данными
5. **Наблюдение**: изучите трассу выполнения
6. **Воспроизведение**: воспроизведите для отладки или тестирования

## Рекомендации {#best-practices}

### Инструменты {#tools}
- Используйте строгие схемы Zod
- Чётко документируйте каждый инструмент
- Меняйте версию инструментов при их изменении

### Политики {#policies}
- Задавайте разумные бюджеты
- Используйте строгие списки разрешённых инструментов
- Проверяйте политики до выхода в продакшен

### Возможности {#capabilities}
- Группируйте инструменты логически
- Повторно используйте возможности в разных агентах
- Документируйте возможности
- **Рекомендуемый порядок работы:** в `defineCapability()` можно передавать как имена инструментов (строки), так и непосредственно объекты Tool. Если вы передаёте объекты Tool, они будут зарегистрированы автоматически.

### Версионирование {#versioning}
- Используйте семантическое версионирование
- Документируйте изменения версий
- Отслеживайте версии в событиях

## Безопасность {#security}

- **По умолчанию всё запрещено**: ни один необъявленный инструмент не может быть выполнен
- **Валидация**: все входные данные проверяются с помощью Zod
- **Политики**: проверяются перед каждым действием
- **Прослеживаемость**: все действия записываются в трассу
- **Аудит**: для полного аудита доступно воспроизведение
