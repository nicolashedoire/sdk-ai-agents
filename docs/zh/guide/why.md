# 为什么选择这个 SDK

**一句话概括：** 大多数智能体框架帮助语言模型去**行动**；这个 SDK 则让它在得出结论之前先**为自己相信的东西给出依据**，并且可以让它**像某个特定的人那样推理**。

本页刻意保持坦诚：它会说明这个 SDK 做了哪些你在别处不容易找到的事，其他框架同样做了哪些事，以及它们在哪些方面做得更好。这里的比较基于 2026 年年中各主流框架的文档（LangChain 和 LangGraph、OpenAI Agents SDK、Vercel AI SDK、CrewAI、AutoGen 及其后继者 Microsoft Agent Framework、Mastra、DSPy）；它们演进得很快，做决定之前请查阅它们当前的文档。

## 它的不同之处 {#what-it-does-differently}

### 1. 推理规则写在代码里，而不是 prompt 里 {#_1-reasoning-rules-written-in-code-not-in-the-prompt}

在通常的智能体中，“推理”就是模型写出来的任何东西：如果它说自己有 90% 的把握，除非你自己编写检查，否则没有任何东西会去核实。而在这里：

- [心智状态](./cognitive-agents#the-mental-state)（事实、假设、预测、矛盾）是有类型的数据，而不是自由文本；
- 模型无法抬高自己的置信度：一个决策的置信度以所选选项的证据支持度为上限，而证据支持度在一个独立的比较步骤中评判（由不带思考者画像的 Jev 评判，或者由遵循指令的语言模型评判）；
- 被否决的假设不能被选中、更新或重新提出；它只能以一个说明了改动之处的变体形式回来（换了措辞的重述不会被检测出来）；
- 只有通过[结论守卫](./evidence-and-verification#the-conclusion-guard)，答案才会被**确定**：经过批判，在最近一次出现新证据之后重新评估过，没有涉及它的矛盾，在预算允许的范围内检验过预测，并且有足够的支持度。否则，智能体会给出**暂定**的答案并说明缺少什么，或者**弃权**。

“我无法得出结论”本身就是一种正式的结果，由代码强制保证，而不是在 prompt 里请求。

### 2. 由世界检验预测，而不是由模型 {#_2-the-world-checks-the-predictions-not-the-model}

一种常见做法是让一个模型去评判另一个模型。在这里，智能体会在检验**之前**说明应该观测到什么、什么会证明它是错的，然后由**你的代码**来裁决：一次测量、一个模拟器、一套测试、一次查询。被驳倒的规则会被否决，之后只能以一个说明了差异的变体形式回来。参见[预测与结果评估器](./evidence-and-verification#predictions-and-the-outcome-evaluator)。

检验得到的结果会为同一作用域后续的运行保留下来：下一次运行会从那些经受住检验的规则开始，而且无法原封不动地重述一条失败过的规则。记忆类产品记住的是说过的话；这里的[跨运行记忆](./memory)只保留检验给出的答案。

### 3. 证据和偏好分开保存 {#_3-evidence-and-preferences-are-kept-apart}

思考者的偏好可以改变**选择哪个行动**，并让一个他们明显偏好的行动在证据看似合理时就被确定；但在代码中，偏好永远不会让一个**关于世界的论断**变得更可信。使用 Jev 时，关于证据的问题甚至是在不带思考者画像的情况下发送的；使用语言模型作裁判时，这种分离依靠的是它的指令。参见[证据不是偏好](./evidence-and-verification#evidence-is-not-preference)。

### 4. 像特定的人一样推理，并加以衡量 {#_4-reasoning-like-a-given-person-and-measuring-it}

记忆类产品大多存储关于用户的事实和偏好（有些也会根据反馈改写指令）；DSPy 这类 prompt 优化器则针对某个指标来调整 prompt 和示例。这个 SDK 提取的是一个人**如何**推理：他们审视问题的顺序、他们的思维习惯、让他们否决一个想法的原因。它为这份[思考者画像](./thinker-profiles)维护版本，把它写进每一个推理步骤，把这个人的纠正连同认同度百分比加入指令，并把智能体对下一步的选择——标注上这个人对每次运行的判定——导出为数据集，用来训练一个小型控制器。

### 5. 推理过程中的校准决策 {#_5-calibrated-decisions-inside-the-reasoning}

[Jev](./typed-decisions) 用由其厂商校准的概率来回答范围很窄的问题。它选出下一个推理步骤、给假设打分，花费都不到一美分；当它没有把握时，由一个确定性的控制器接手。

### 6. 推理与行动共用一份日志 {#_6-one-log-for-reasoning-and-actions}

受治理的工具、审批、成本、重试和 MCP 调用，都和每一个思维记录在同一份事件日志中。即使在几个月之后，你也能准确重建智能体在给出任何答案时“心里想的”是什么，并且在不调用模型的情况下回放它的动作。

## 其他框架同样做到的 {#what-other-frameworks-also-do}

- **受治理的工具和人工审批。** OpenAI Agents SDK 中的护栏（guardrails），LangGraph 中的人在回路（human-in-the-loop）。
- **持久化与回放。** LangGraph 的检查点让你可以恢复、检查过去的状态，并从中回放或分叉。
- **MCP**、成本追踪和重试都已广泛可用。

这里的区别在于，这些部件与一个显式的推理状态共用同一份事件日志。

## 其他框架做得更好的 {#what-other-frameworks-do-better}

- **生态。** 数以百计的集成、庞大的社区、应有尽有的示例。
- **成熟度。** 这个 SDK 还很年轻，只有一位维护者，仍处于 0.x 版本（次版本就可能破坏 API），而且只在有限的真实问题上试用过。
- **多智能体编排、流式输出和 UI 套件**在别处更丰富。
- **成本和延迟。** 一个认知式回答大约需要十个推理步骤，每步一到两次模型请求（在我们的试验中，使用 gpt-4o 和 Jev 时，每个问题需要几分钟、约 0.1 美元），而直接回答只需一次调用，使用工具的智能体也只需几次。
- **对模型的依赖。** 无论使用什么模型，这些规则都成立，但推理的质量不然：小模型很难遵循这套方法，即便是强大的模型，在难题上也常常以暂定或弃权告终。
- **记忆与检索。** 记忆类产品和检索管线提供对大型集合的语义搜索；这里的[跨运行记忆](./memory)是在一个狭窄的作用域内，通过词语匹配来召回经过检验的规则。

## 何时选择它 {#when-to-choose-it}

- **你必须说明理由或接受审计的决策**：科研、工业、内部治理，以及受监管领域（医疗、金融、法律）中由人来审查结论及其依据的决策支持。
- **当“我不知道”好过一个信心十足的编造**，并且你希望这一点得到强制保证时。
- **当论断可以被核实时**：你有一次测量、一个模拟器或一套测试，可以让智能体用它们来对照自己的预测。
- **推理分身**：捕捉一位专家或创始人处理问题的方式，并衡量模仿得有多接近。

如果你需要的是一个快速的聊天机器人、大量现成的集成，或者一次快速的调用，那么更轻量的框架更合适。
