# 关键术语通俗解释

本文档中用到的每个术语都在这里，不用行话来解释，并附有详细介绍它的页面链接。术语按主题分组；用搜索框（<kbd>/</kbd>）可以直接跳到某个术语。

## 基础 {#the-basics}

| 术语 | 通俗地说 |
| --- | --- |
| **软件开发工具包**（SDK） | 给开发者用的工具箱：你把这些代码加进自己的应用，而不必一切从头写起。这一个是用 TypeScript 写的；它还没有发布到 npm，需要从 GitHub 安装（参见[快速开始](./getting-started)）。 |
| **语言模型**（Language model，LLM） | 读写文本的 AI（GPT-4o、Claude……）。在这里它只是众多组件中的一个：它负责提议，由 SDK 检查并决定什么是允许的。 |
| **提示词**（Prompt） | 每次请求时发送给语言模型的文字指令。 |
| **词元**（Token） | 一个词的一部分。模型提供商按读入和写出的 token 数计费，所以[成本](./costs)以 token 计算。 |
| **智能体**（Agent） | 一个借助语言模型、一步一步达成目标的程序。SDK 有两类：用工具行动的[受治理智能体](./governed-agents)，以及在下结论前先推理的[认知智能体](./cognitive-agents)。 |
| **运行**（Run） | 智能体针对一个问题从头到尾的一次执行。它有一个 id（`runId`），你可以用它来读取、回放这次运行或计算其成本。 |
| **工具**（Tool） | 你的代码交给智能体的一个函数（读取数据库、发送邮件……）。智能体只能使用明确交给它的工具。参见[核心概念](./concepts#_2-tool)。 |
| **能力**（Capability） | 一组有名字的工具，可以一次性交给多个智能体。 |
| **策略**（Policy） | 在每个动作**之前**检查的规则：预算、超时、允许使用的工具列表，或者你自己的检查。 |
| **审批**（Approval） | 在有风险的动作之前暂停，直到有人说“可以”。可以由策略要求审批，也可以由工具本身要求（`requiresApproval`）；如果调用方先放弃了，这个动作就永远不会执行。 |
| **意图**（Intention） | 受治理智能体的模型*想要*做的事（调用工具、回答……），被写了下来但没有执行：SDK 会先验证它。 |
| **模式定义**（Schema，Zod） | 对数据必须具有的形状的精确描述。工具调用和推理步骤的结构化回复都要对照它来检查；不符合的回复会被拒绝。 |
| **JSON 格式**（JSON） | 一种用于结构化数据的纯文本格式。画像、事件和模型回复都是 JSON。 |

## 可追溯性 {#traceability}

| 术语 | 通俗地说 |
| --- | --- |
| **事件**（Event） | 日志本里的一行：“这件事在这个时间发生了”。每次运行的每一步都记录为一个事件。参见[事件目录](../reference/events)。 |
| **事件存储**（Event store） | 保存日志本的地方：一个文件夹、SQLite 或 PostgreSQL。 |
| **事件溯源**（Event sourcing） | 以日志本为准的原则：一次运行的状态（包括它的心智状态）是通过重读其事件重建出来的，从不单独存储。正因如此，每次运行在几个月后仍然可以审计。思考者画像是个例外：事件只记录它的 id 和版本，所以请自行保存画像本身。 |
| **追踪记录**（Trace） | 一次运行的全部事件，按顺序排列。 |
| **回放**（Replay） | 根据事件重新运行一次记录下来的运行：它决定的动作会再次执行，经过同样的策略，但不会再次询问语言模型。可用于审计一次运行，或者在修改策略后测试“如果……会怎样”。参见[可追溯性与回放](./observability)。 |
| **黄金追踪记录**（Golden trace） | 作为参照保留下来的一次良好运行；新的运行会与它对照检查，于是行为的变化会像一个失败的测试那样被发现。 |

## 认知智能体如何推理 {#how-a-cognitive-agent-reasons}

| 术语 | 通俗地说 |
| --- | --- |
| **心智状态**（Mental state） | 智能体当前对问题“心里想的”一切，以数据形式写下来：它观测到了什么、知道什么、假定什么、不知道什么，以及它考虑的选项。参见[心智状态](./cognitive-agents#the-mental-state)。 |
| **观测**（Observation，`O1`…） | 看到的东西：你随问题一起提供的测量值或文档、工具的结果，或者检验的结果。 |
| **事实**（Fact，`F1`…） | 智能体认为成立的陈述，并注明它从何而来。事实从不删除：它会被*撤回*（retracted），或被*取代*（superseded，即被替换），并附上原因。 |
| **假定**（Assumption，`A1`…） | 推理未经证明就当作成立的东西。 |
| **约束**（Constraint，`K1`…） | 任何答案都必须遵守的东西（“在第四季度之前”、“低于 1 万欧元”）。 |
| **未知项**（Unknown，`U1`…） | 一个悬而未决的问题。它可以被*解决*（resolved，得到回答），也可以被*放弃*（dropped，无从回答）。 |
| **假设**（Hypothesis，`H1`…） | 正在考虑的一个选项。它属于三类之一：**提议**（proposal，一种行动选择：“拒绝这份工作”）、**规则**（rule，一种规律：“滚动时间不取决于质量”）或**解释**（explanation，一个原因）。 |
| **归纳、溯因、演绎**（Induction, abduction, deduction） | 得出假设的三种方式：从反复出现的案例得出规则；从一个意外推出它最可能的原因；从一条规则推出必然随之而来的结果。这个标签是声明出来的，并不会让论断变成真的。 |
| **操作**（Operation） | 一个推理动作：表征问题、提出假设、模拟、批判、比较、决策……共有十种。参见[操作](./cognitive-agents#the-operations)。 |
| **控制器**（Controller） | 负责选择下一个操作的部件。**启发式**（heuristic）控制器按固定顺序进行，免费且可预测；**类型化**（typed）控制器每一步都询问 Jev。 |
| **思维补丁**（Thought patch） | 一个操作在心智状态中改变的内容，记录为一个事件。心智状态就是按顺序应用的所有补丁。 |
| **模拟**（Simulation） | 设想如果某个假设为真会发生什么：先是直接影响，再是间接影响。 |
| **批判**（Critique） | 智能体攻击自己的选项：它可能失败的最有力理由。一个没有得到回应的**致命**（fatal）批判会否决这个选项。 |
| **矛盾**（Contradiction，`C1`…） | 两件不可能同时为真的事。它会一直保持未决，直到有人引用能解决它的观测或事实把它解决。 |
| **变体**（Variant） | 被证据否定的假设的修正版，作用域更窄或附加了条件，并用一句话说明改了什么。 |
| **限制**（Limits） | 一次运行的预算：步数、时间、工具调用次数、检验次数，以及得出结论的阈值。参见[限制](./cognitive-agents#limits)。 |

## 证据与结论 {#evidence-and-conclusions}

| 术语 | 通俗地说 |
| --- | --- |
| **出处**（Provenance） | 一条证据从哪里来：由你提供、由工具返回，还是由检验测得，以及保存原始内容的那个事件。 |
| **来源组**（Origin group，`originGroup`） | 表示“同一来源”的标签。来自同一来源的两条观测，并不是两次相互独立的确认。 |
| **重复项**（Duplicate） | 再次看到的、来自同一来源的相同内容。它不会增加任何分量。 |
| **预测**（Prediction，`P1`…） | 如果一个假设正确就应该观测到的东西，在检验它**之前**记录下来。 |
| **证伪条件**（Falsifier） | 能够证明假设错误的那个观测。一个无法被证明为错的论断是无法检验的。 |
| **知识**（Knowledge，`M1`…） | 之前的运行通过真实检验确立下来的东西，在运行开始时被召回：*已证实*（verified）、*已驳倒*（refuted），或者在检验结果不一致时为*有争议*（contested）。参见[跨运行记忆](./memory)。 |
| **作用域**（Scope） | 一份记忆的边界：各次运行只在同一作用域内共享它们学到的东西，例如同一个试验台或同一个产品。 |
| **结果评估器**（Outcome evaluator） | 你的代码，它拿预测与世界对照（一次测量、一个模拟器、一套测试），给出*被证实*（confirmed）、*被驳倒*（refuted）或*不确定*（inconclusive）。语言模型从不给自己的预测打分。参见[预测](./evidence-and-verification#predictions-and-the-outcome-evaluator)。 |
| **支持度**（Support） | 证据对一个假设的支持程度，从 0（被驳倒）到 1（已确立）。它是一种判断，而不是测量出来的概率。代码从不把偏好混入其中；使用语言模型作裁判时，这一点依靠的是它的指令（参见[证据不是偏好](./evidence-and-verification#evidence-is-not-preference)）。 |
| **偏好契合度**（Preference fit，`preferenceFit`） | 一个行动选择有多适合思考者，从 0（触犯了他们的某条否决标准）到 1（理想）。只有行动选择才有这个分数。 |
| **排序**（Ranking） | 各选项的先后顺序。论断只按支持度排序；行动选择默认按 60% 支持度加 40% 偏好契合度排序。 |
| **过时**（Stale） | 在证据最近一次变化之前做出的评估。在得出结论之前必须重做。 |
| **结论守卫**（Conclusion guard） | 用代码写成的一组检查，答案必须全部通过才能被确定：经过批判，在最近一次出现新证据之后评估过，没有涉及它的未决矛盾，在预算还允许检验时没有未经检验的预测，并且有足够的支持度。参见[结论守卫](./evidence-and-verification#the-conclusion-guard)。 |
| **决策阈值**（Decision threshold） | 一个确定答案所需的支持度：默认是 0.75，即“有力支持”。思考者明显偏好的行动选择只需要 0.35。 |
| **确定**（Committed） | 通过了结论守卫的确定答案。 |
| **暂定**（Provisional） | 预算用完时能给出的最佳答案，附带尚未确立之处的清单（`missing`）。 |
| **弃权**（Abstain） | “我无法得出结论”，并说明原因。这是一种有效的结果，而不是错误。 |
| **置信度**（Confidence） | 决策有多大把握，永远不会高于所选选项的证据支持度。 |

## 模仿一个人的推理 {#imitating-a-person-s-reasoning}

| 术语 | 通俗地说 |
| --- | --- |
| **思考者画像**（Thinker profile） | 对某个特定的人**如何**推理的描述：他们审视问题的顺序、优先事项、思维习惯、否决标准和风险偏好。它被写进每个推理步骤的指令里，智能体正是这样来模仿这个人的推理的。参见[思考者画像](./thinker-profiles)。 |
| **样本**（Sample） | 这个人用自己的话讲解的一个话题：话题、他们如何推理、得出了什么结论。 |
| **提炼**（Distill） | 从样本中提取出画像：找出这个人在不同话题上的推理方式中反复出现的东西。 |
| **关注顺序**（Order of attention，`reasoningSequence`） | 这个人依次经历的步骤。 |
| **启发式规则**（Heuristic） | 一种思维习惯，写成“当……时，就……”。 |
| **否决标准**（Rejection criterion） | 让这个人放弃一个想法的理由。 |
| **判定**（Verdict） | 这个人对一次运行的评判：`match`（推理得和我一样）、`partial` 或 `mismatch`。 |
| **认同度**（Agreement） | 这个人对一次运行认同的程度，从 0 到 1：`0.8` 表示“对了 80%”。你正是用它来衡量模仿得有多接近。 |
| **校准示例**（Calibration example） | 这个人认可过的一次运行，作为范例答案展示给模型。 |
| **纠正**（Correction） | 来自一次这个人不认同的运行的教训，作为最高优先级展示给模型。 |

## 研究 {#studies}

| 术语 | 通俗地说 |
| --- | --- |
| **研究**（Study） | 一位 AI 研究员（`sdk.createStudy`）：它先理解一个对象，再提出如何用今天的知识和技术重新设计它，并设计能做出裁决的实验。它不构建也不测量任何东西。参见[研究](./studies)。 |
| **环节**（Passage） | 研究的七个阶段之一：观察、分解、理解当时的选择、考察此后的变化、交叉对照过去与现在、设计、对照检验。一个环节可以重开较早的环节。 |
| **章程**（Charter） | 研究的框架：对象、指导性问题、目标、需求、你的线索、超出范围的内容。它在研究创建时被冻结，每个 prompt 都以它开头。 |
| **线索**（Lead） | 你交给研究去调查的一个想法。它是有待核实的例子，而不是真理：研究会说明它是否相关并给出理由，还会在它之外继续寻找。 |
| **论断状态**（Claim status） | 研究中一个陈述的分量：**已确立**（established，有研究实际找到的来源支持）、**假设**（hypothesis，合理，但没有文献依据）或**创新点**（novelty，一个新想法，有待对照现有工作核查）。检查它的是代码，而不是模型。参见[已确立、假设、创新点](./studies#established-hypothesis-novelty)。 |
| **现有技术**（Prior art） | 与一个被说成是新的想法最接近的现有工作。在研究搜索过它之前，一个创新点一直处于“有待核查”的状态。 |
| **守护者**（Guardian） | 研究每个环节之后的一次独立检查：它只看到章程和该环节产出的内容，并移除偏离目标的东西。参见[守护者](./studies#the-guardian)。 |
| **偏离、偏离日志**（Drift, drift log） | 偏离是指模型慢慢离开自己的主题。偏离日志列出研究因此移除的一切，以及原因。 |
| **修正案**（Amendment） | 研究创建之后添加的一条指令。只有当它细化目标时才会被接受；与章程相矛盾或改变目标的修正案会被拒绝。 |
| **新能力**（New capability） | 通过原理上的改变而成为可能、在今天很难做到或无法做到的东西——与之相对的是**改进**（improvement），改进只是让某件事更快或更便宜。 |
| **组装式突破**（Breakthrough by assembly） | 由早已存在的技术以新的方式组合而成的突破。比特币就是一个例子：签名、哈希链、工作量证明和点对点网络此前都已为人所知。 |
| **机制卡片**（Mechanism card） | 关于一个机制的十一个问题，从观察到了什么到得出了什么结论。研究回答前九个；你在运行实验之后回答最后两个。 |

## 类型化决策与连接器 {#typed-decisions-and-connectors}

| 术语 | 通俗地说 |
| --- | --- |
| **Jev 模型**（Jev） | TypeSafe 推出的一个模型，用你的代码可以直接使用的概率，快速而低成本地回答范围很窄的问题（是/否、一个选择、一个评分）。参见[类型化决策](./typed-decisions)。 |
| **是非题、单选题、评分题**（Noul, Choice, Score） | Jev 的三种问题类型：是或否；从列表中选一个选项；在一个量表上给出等级。选择多个选项时，会为每个选项各问一个是/否问题。 |
| **经过校准的**（Calibrated） | 平均而言与现实相符的概率：在以 80% 置信度给出的答案中，大约 80% 是对的。 |
| **AI 网关**（AI Gateway） | Vercel 的一项服务，只用一个密钥就能访问多个模型，其中包括 Jev。 |
| **模型上下文协议**（MCP） | Model Context Protocol：AI 应用（Claude Desktop、Claude Code、IDE 助手、智能体）与你的系统之间的一种标准“插头”。SDK 可以把一个函数、一个 Web API、一个文件夹、一个数据库或一个智能体变成 MCP 服务器，也可以使用任何 MCP 服务器的工具。参见 [MCP 通俗解释](./mcp)。 |
| **MCP 服务器**（MCP server） | 放在你某个系统前面的一个小程序，它告诉 AI 应用自己能提供什么，并在被请求时完成工作。参见[你的第一个 MCP 服务器](./mcp-first-server)。 |
| **MCP 客户端、宿主**（MCP client, host） | 宿主是用户与之对话的 AI 应用；在宿主内部，一个 MCP 客户端维持着与某一个服务器的连接。 |
| **资源**（Resource） | MCP 服务器提供给人阅读的文档，比如共享文件夹里的一个文件。与工具不同，它由用户或应用来挑选，而不是由模型。 |
| **传输方式**（Transport） | MCP 应用与服务器交换消息的方式：**stdio**（应用在同一台电脑上把服务器作为一个程序启动，并通过它的输入和输出对话）或 **Streamable HTTP**（服务器是一个 Web 服务）。参见 [stdio 还是 HTTP？](./mcp-deploy#stdio-or-http)。 |
| **OpenAPI 描述**（OpenAPI） | 对 Web API 的一种标准的、机器可读的描述：它的地址、参数和响应，通常以 `openapi.json` 的形式发布。SDK 根据它为每个操作生成一个工具。参见[一个 Web API](./mcp-recipes#a-web-api-from-its-openapi-description)。 |
| **JSON 模式**（JSON Schema） | 对某些数据（这里是工具参数）形状的描述，模型和 MCP 应用读取它来正确调用工具。SDK 会根据你的 Zod schema 或 OpenAPI 描述来编写它。 |
| **只读**（Read-only） | 可以看，不能改。文件夹和数据库这两种来源在构造上就是只读的；Web API 默认只读（只包含 `GET` 操作）。 |
| **工具源**（Tool source） | 从一个系统构建现成工具的函数：`openApiTools`、`folderTools`、`databaseTools`、`cognitiveAgentTool`、`webTools`。一行代码就能通过 MCP 提供它们，也可以把它们交给你自己的智能体。参见[把任何系统变成 MCP 服务器](./mcp-recipes)和 [Web 调研](./web-research)。 |

## 在生产环境中运维 {#operating-in-production}

| 术语 | 通俗地说 |
| --- | --- |
| **重试**（Retry） | 当失败只是暂时的，稍等片刻后再次尝试失败的请求。参见[重试与回退](./resilience)。 |
| **回退、故障转移**（Fallback, failover） | 当第一个模型或提供商持续失败时，切换到另一个。 |
| **事故**（Incident） | 一次失败的运行、一个被拦截的动作或一次故障转移，被转换成通过邮件或 webhook 发送给你的告警。参见[事故告警](./incidents)。 |
| **网络钩子**（Webhook） | 由你的聊天工具或监控工具提供给你的一个地址，SDK 会把告警发送到这里。 |
