# 쉽게 풀어 쓴 핵심 용어

이 문서에서 쓰는 모든 용어를 전문 용어 없이 설명하고, 자세히 다루는 페이지로 가는 링크를 달았습니다. 용어는 주제별로 묶여 있습니다. 검색 상자(<kbd>/</kbd>)로 원하는 용어로 바로 이동할 수 있습니다.

## 기본 {#the-basics}

| 용어 | 쉽게 말하면 |
| --- | --- |
| **SDK** | 개발자를 위한 도구 상자입니다. 모든 것을 직접 작성하는 대신 여러분의 애플리케이션에 추가하는 코드입니다. 이 SDK는 TypeScript로 작성되었고, 아직 npm에 없어서 GitHub에서 설치합니다([시작하기](./getting-started) 참고). |
| **언어 모델** (Language model, LLM) | 텍스트를 읽고 쓰는 AI입니다(GPT-4o, Claude…). 여기서는 여러 구성 요소 중 하나일 뿐입니다. 모델이 제안하면, SDK가 검사하고 무엇이 허용되는지 결정합니다. |
| **프롬프트** (Prompt) | 요청할 때마다 언어 모델에 보내는 텍스트 지시문입니다. |
| **토큰** (Token) | 단어의 조각입니다. 모델 제공업체는 읽고 쓴 토큰 수에 따라 요금을 매기며, 그래서 [비용](./costs)을 토큰 단위로 셉니다. |
| **에이전트** (Agent) | 언어 모델을 이용해 한 단계씩 목표에 도달하는 프로그램입니다. SDK에는 두 종류가 있습니다. 도구로 행동하는 [통제형 에이전트](./governed-agents)와, 결론을 내리기 전에 추론하는 [인지 에이전트](./cognitive-agents)입니다. |
| **실행** (Run) | 하나의 문제에 대한 에이전트의 한 번의 실행으로, 시작부터 끝까지를 말합니다. 실행에는 id(`runId`)가 있으며, 이 id로 실행을 읽고, 리플레이하고, 비용을 계산합니다. |
| **도구** (Tool) | 여러분의 코드가 에이전트에게 주는 함수입니다(데이터베이스 읽기, 이메일 보내기…). 에이전트는 명시적으로 받은 도구만 쓸 수 있습니다. [핵심 개념](./concepts#_2-tool)을 보세요. |
| **역량** (Capability) | 여러 에이전트에게 한꺼번에 줄 수 있는, 이름이 붙은 도구 묶음입니다. |
| **정책** (Policy) | 모든 행동 **전에** 검사되는 규칙입니다. 예산, 타임아웃, 허용된 도구 목록, 또는 직접 만든 검사가 될 수 있습니다. |
| **승인** (Approval) | 위험한 행동 전에 사람이 허락할 때까지 멈추는 것입니다. 정책이 요구할 수도 있고, 도구 자체가 요구할 수도 있습니다(`requiresApproval`). 호출한 쪽이 먼저 포기하면 그 행동은 절대 실행되지 않습니다. |
| **의도** (Intention) | 통제형 에이전트의 모델이 하고 *싶어 하는* 것(도구 호출, 답변…)을 적어 둔 것으로, 아직 실행되지 않은 상태입니다. SDK가 먼저 검증합니다. |
| **스키마** (Schema, Zod) | 데이터가 가져야 할 형태를 정확히 기술한 것입니다. 도구 호출과 추론 단계의 구조화된 응답은 스키마에 대해 검사되며, 맞지 않는 응답은 거부됩니다. |
| **JSON** | 구조화된 데이터를 위한 평범한 텍스트 형식입니다. 프로필, 이벤트, 모델 응답이 JSON입니다. |

## 추적성 {#traceability}

| 용어 | 쉽게 말하면 |
| --- | --- |
| **이벤트** (Event) | 기록부의 한 줄입니다. "이 일이 이 시각에 일어났다"는 뜻입니다. 모든 실행의 모든 단계가 이벤트로 기록됩니다. [이벤트 카탈로그](../reference/events)를 보세요. |
| **이벤트 저장소** (Event store) | 기록부를 보관하는 곳입니다. 파일 폴더, SQLite 또는 PostgreSQL입니다. |
| **이벤트 소싱** (Event sourcing) | 기록부가 곧 진실이라는 규칙입니다. 실행의 상태는 심적 상태를 포함해 그 이벤트를 다시 읽어 재구성되며, 따로 저장되지 않습니다. 그래서 모든 실행을 몇 달 뒤에도 감사할 수 있습니다. 사고자 프로필은 예외입니다. 이벤트에는 프로필의 id와 버전만 기록되므로, 프로필 자체는 따로 저장하세요. |
| **트레이스** (Trace) | 한 실행의 모든 이벤트를 순서대로 모은 것입니다. |
| **리플레이** (Replay) | 기록된 실행을 그 이벤트로부터 다시 실행하는 것입니다. 실행이 결정했던 행동이 같은 정책을 거쳐 다시 실행되며, 언어 모델에 다시 묻지 않습니다. 실행을 감사하거나, 정책을 바꾼 뒤 "만약 이랬다면"을 테스트할 때 유용합니다. [추적성과 리플레이](./observability)를 보세요. |
| **골든 트레이스** (Golden trace) | 기준으로 보관해 두는 좋은 실행입니다. 새 실행을 이것과 대조하므로, 동작이 바뀌면 실패하는 테스트처럼 탐지됩니다. |

## 인지 에이전트가 추론하는 방식 {#how-a-cognitive-agent-reasons}

| 용어 | 쉽게 말하면 |
| --- | --- |
| **심적 상태** (Mental state) | 에이전트가 지금 문제에 대해 "염두에 두고" 있는 모든 것을 데이터로 적어 둔 것입니다. 관찰한 것, 아는 것, 가정하는 것, 모르는 것, 고려 중인 선택지가 들어 있습니다. [심적 상태](./cognitive-agents#the-mental-state)를 보세요. |
| **관찰** (Observation, `O1`…) | 본 것입니다. 문제와 함께 준 측정값이나 문서, 도구 결과, 또는 테스트 결과입니다. |
| **사실** (Fact, `F1`…) | 에이전트가 참이라고 여기는 진술로, 어디서 왔는지가 함께 붙습니다. 사실은 절대 삭제되지 않습니다. 이유와 함께 *철회*(retracted, 거둬들임)되거나 *대체*(superseded, 교체)됩니다. |
| **가정** (Assumption, `A1`…) | 추론이 증명 없이 당연하게 받아들이는 것입니다. |
| **제약** (Constraint, `K1`…) | 모든 답이 지켜야 하는 것입니다("4분기 전", "1만 EUR 미만"). |
| **미지수** (Unknown, `U1`…) | 열려 있는 질문입니다. *해결*(resolved, 답을 얻음)되거나 *포기*(dropped, 답할 방법이 없음)될 수 있습니다. |
| **가설** (Hypothesis, `H1`…) | 검토 중인 선택지입니다. 세 종류 중 하나입니다. **제안**(proposal, 행동 선택: "그 일자리를 거절한다"), **규칙**(rule, 규칙성: "굴러가는 시간은 질량에 좌우되지 않는다"), 또는 **설명**(explanation, 원인)입니다. |
| **귀납, 가추, 연역** (Induction, abduction, deduction) | 가설에 이르는 세 가지 방법입니다. 반복되는 사례에서 규칙으로, 놀라운 현상에서 가장 그럴듯한 원인으로, 규칙에서 반드시 따라 나오는 것으로 갑니다. 이 레이블은 선언된 것일 뿐, 주장을 참으로 만들지는 않습니다. |
| **연산** (Operation) | 추론의 한 수입니다. 문제 표현하기, 가설 세우기, 시뮬레이션하기, 비판하기, 비교하기, 결정하기… 모두 열 가지입니다. [연산](./cognitive-agents#the-operations)을 보세요. |
| **컨트롤러** (Controller) | 다음 연산을 고르는 것입니다. **휴리스틱** 컨트롤러는 고정된 순서를 따르며 무료이고 예측 가능합니다. **타입 지정** 컨트롤러는 단계마다 Jev에 묻습니다. |
| **사고 패치** (Thought patch) | 연산 하나가 심적 상태에서 바꾼 것으로, 이벤트 하나로 기록됩니다. 심적 상태는 모든 패치를 순서대로 적용한 결과입니다. |
| **시뮬레이션** (Simulation) | 가설이 참이라면 무슨 일이 일어날지 상상하는 것입니다. 직접적인 효과를 먼저, 그다음 간접적인 효과를 봅니다. |
| **비판** (Critique) | 에이전트가 자신의 선택지를 공격하는 것입니다. 그 선택지가 실패할 수 있는 가장 강력한 이유를 찾습니다. 반박되지 않은 **치명적**(fatal) 비판은 그 선택지를 기각합니다. |
| **모순** (Contradiction, `C1`…) | 동시에 참일 수 없는 두 가지입니다. 이를 해소하는 관찰이나 사실을 인용해 정리할 때까지 열린 상태로 남습니다. |
| **변형** (Variant) | 증거와 모순된 가설을 고친 버전입니다. 범위를 좁히거나 조건을 추가하고, 무엇이 바뀌었는지 한 문장으로 밝힙니다. |
| **한도** (Limits) | 실행의 예산입니다. 단계 수, 시간, 도구 호출, 테스트, 그리고 결론을 내리기 위한 임계값입니다. [한도](./cognitive-agents#limits)를 보세요. |

## 증거와 결론 {#evidence-and-conclusions}

| 용어 | 쉽게 말하면 |
| --- | --- |
| **출처** (Provenance) | 증거 하나가 어디서 왔는지입니다. 여러분이 준 것인지, 도구가 반환한 것인지, 테스트로 측정된 것인지, 그리고 원본을 담고 있는 이벤트가 무엇인지를 말합니다. |
| **출처 그룹** (Origin group, `originGroup`) | "같은 출처"를 나타내는 레이블입니다. 같은 출처에서 온 두 관찰은 서로 독립적인 두 번의 확인이 아닙니다. |
| **중복** (Duplicate) | 같은 출처에서 온 같은 내용을 다시 본 것입니다. 무게를 더하지 않습니다. |
| **예측** (Prediction, `P1`…) | 가설이 맞다면 관찰되어야 하는 것으로, 테스트하기 **전에** 기록됩니다. |
| **반증 조건** (Falsifier) | 가설이 틀렸음을 증명할 관찰입니다. 틀렸음을 증명할 수 없는 주장은 테스트할 수 없습니다. |
| **지식** (Knowledge, `M1`…) | 이전 실행들이 실제 테스트로 확립한 것으로, 실행을 시작할 때 불러옵니다. *검증됨*(verified), *반증됨*(refuted), 또는 테스트 결과가 엇갈릴 때 *논란 중*(contested)입니다. [실행 간 기억](./memory)을 보세요. |
| **범위** (Scope) | 기억의 경계입니다. 실행들은 같은 범위 안에서만 배운 것을 공유합니다. 예를 들어 테스트 벤치 하나나 제품 하나가 범위가 됩니다. |
| **결과 평가기** (Outcome evaluator) | 예측을 세상과 대조하는(측정, 시뮬레이터, 테스트 스위트) 여러분의 코드로, *확인됨*(confirmed), *반증됨*(refuted), *결론 없음*(inconclusive)으로 답합니다. 언어 모델은 자신의 예측을 절대 스스로 채점하지 않습니다. [예측](./evidence-and-verification#predictions-and-the-outcome-evaluator)을 보세요. |
| **지지도** (Support) | 증거가 가설을 얼마나 잘 뒷받침하는지로, 0(반증됨)부터 1(확립됨)까지입니다. 측정된 확률이 아니라 판단입니다. 코드는 여기에 선호를 절대 섞지 않습니다. 언어 모델 판정자를 쓸 때는 이것이 그 지시문에 달려 있습니다([증거는 선호가 아닙니다](./evidence-and-verification#evidence-is-not-preference) 참고). |
| **선호 적합도** (Preference fit, `preferenceFit`) | 행동 선택이 사고자에게 얼마나 잘 맞는지로, 0(사고자의 기각 기준 중 하나에 해당)부터 1(이상적)까지입니다. 행동 선택에만 매겨집니다. |
| **순위** (Ranking) | 선택지들의 순서입니다. 주장은 지지도만으로 순위를 매깁니다. 행동 선택은 기본적으로 지지도 60%와 선호 적합도 40%로 순위를 매깁니다. |
| **낡은 평가** (Stale) | 증거가 마지막으로 바뀌기 전에 이루어진 평가입니다. 결론을 내리기 전에 다시 해야 합니다. |
| **결론 가드** (Conclusion guard) | 답이 확정되기 위해 통과해야 하는, 코드로 작성된 검사들입니다. 비판을 거쳤고, 마지막 새 증거 이후에 평가되었고, 그 답에 관한 열린 모순이 없고, 예산에 테스트가 남아 있는 동안 테스트되지 않은 예측이 없고, 지지도가 충분해야 합니다. [결론 가드](./evidence-and-verification#the-conclusion-guard)를 보세요. |
| **결정 임계값** (Decision threshold) | 확고한 답에 필요한 지지도로, 기본값은 0.75("강하게 뒷받침됨")입니다. 사고자가 분명히 선호하는 행동 선택은 0.35만 있으면 됩니다. |
| **확정** (Committed) | 결론 가드를 통과한 확고한 답입니다. |
| **잠정** (Provisional) | 예산이 바닥났을 때 얻을 수 있는 가장 좋은 답으로, 아직 확립되지 않은 것의 목록(`missing`)이 함께 붙습니다. |
| **판단 유보** (Abstain) | 이유와 함께 "결론을 내릴 수 없습니다"라고 하는 것입니다. 오류가 아니라 유효한 결과입니다. |
| **신뢰도** (Confidence) | 결정이 얼마나 확실한지로, 선택된 선택지의 증거 지지도보다 높아질 수 없습니다. |

## 한 사람의 추론을 흉내 내기 {#imitating-a-person-s-reasoning}

| 용어 | 쉽게 말하면 |
| --- | --- |
| **사고자 프로필** (Thinker profile) | 특정 인물이 **어떻게** 추론하는지를 기술한 것입니다. 문제를 바라보는 순서, 우선순위, 반사적 판단, 기각 기준, 위험 선호도가 담깁니다. 각 추론 단계의 지시문에 들어가며, 이것이 에이전트가 그 사람의 추론을 흉내 내는 방법입니다. [사고자 프로필](./thinker-profiles)을 보세요. |
| **샘플** (Sample) | 그 사람이 자신의 말로 설명한 주제 하나입니다. 주제, 어떻게 추론했는지, 무엇을 결론 내렸는지가 들어 있습니다. |
| **추출** (Distill) | 샘플에서 프로필을 뽑아내는 것입니다. 여러 주제에 걸쳐 그 사람의 추론 방식에서 반복되는 것을 찾습니다. |
| **주의 순서** (Order of attention, `reasoningSequence`) | 그 사람이 거치는 단계들을 순서대로 나열한 것입니다. |
| **휴리스틱** (Heuristic) | "…이면, …한다" 형태로 적은 반사적 판단입니다. |
| **기각 기준** (Rejection criterion) | 그 사람이 아이디어를 버리는 이유입니다. |
| **판정** (Verdict) | 실행에 대한 그 사람의 판단입니다. `match`(나처럼 추론했다), `partial`, 또는 `mismatch`입니다. |
| **동의율** (Agreement) | 그 사람이 실행의 어느 정도에 동의하는지로, 0부터 1까지입니다. `0.8`은 "80% 맞았다"는 뜻입니다. 흉내가 얼마나 가까워졌는지 측정하는 방법입니다. |
| **보정 예시** (Calibration example) | 그 사람이 인정한 실행으로, 모범 답안으로 모델에게 보여 줍니다. |
| **교정** (Correction) | 그 사람이 동의하지 않은 실행에서 얻은 교훈으로, 최우선 사항으로 모델에게 보여 줍니다. |

## 연구 {#studies}

| 용어 | 쉽게 말하면 |
| --- | --- |
| **연구** (Study) | AI 연구자입니다(`sdk.createStudy`). 대상을 이해한 다음, 오늘날의 지식과 기술로 그것을 어떻게 다시 설계할지 제안하고, 결정을 내려 줄 실험을 설계합니다. 아무것도 만들거나 측정하지 않습니다. [연구](./studies)를 보세요. |
| **과정** (Passage) | 연구 방법을 이루는 일곱 부분 중 하나입니다. 관찰하기, 분해하기, 당시의 선택 이해하기, 무엇이 바뀌었는지 살펴보기, 과거와 현재 교차시키기, 설계하기, 대조하기입니다. 과정은 앞선 과정을 다시 열 수 있습니다. |
| **헌장** (Charter) | 연구의 틀입니다. 대상, 길잡이 질문, 목표, 필요 사항, 여러분의 단서, 범위 밖인 것이 담깁니다. 연구를 만들 때 고정되며, 모든 프롬프트가 헌장으로 시작합니다. |
| **단서** (Lead) | 연구에게 살펴보라고 주는 아이디어입니다. 진실이 아니라 검증할 예시입니다. 연구는 그것이 관련 있는지를 이유와 함께 밝히고, 그 너머까지 찾아봅니다. |
| **주장 상태** (Claim status) | 연구의 진술이 얼마나 믿을 만한지입니다. **확립**(established, 연구가 실제로 찾은 소스가 뒷받침함), **가설**(hypothesis, 그럴듯하지만 문서화되지 않음), 또는 **신규**(novelty, 기존 연구와 대조해야 할 새로운 아이디어)입니다. 모델이 아니라 코드가 검사합니다. [확립, 가설, 신규](./studies#established-hypothesis-novelty)를 보세요. |
| **선행 기술** (Prior art) | 새것으로 제시된 아이디어에 가장 가까운 기존 작업입니다. 신규 주장은 연구가 선행 기술을 검색할 때까지 "검증 대상"으로 남습니다. |
| **감시자** (Guardian) | 연구의 각 과정 뒤에 이루어지는 별도의 검사입니다. 헌장과 그 과정이 만든 것만 보고, 목표에서 벗어난 것을 제거합니다. [감시자](./studies#the-guardian)를 보세요. |
| **이탈, 이탈 기록** (Drift, drift log) | 이탈은 모델이 서서히 주제에서 벗어나는 것입니다. 이탈 기록은 연구가 그 때문에 제거한 모든 것과 그 이유를 나열합니다. |
| **개정안** (Amendment) | 연구를 만든 뒤에 추가한 지시입니다. 목표를 구체화할 때만 수락되며, 헌장과 모순되거나 목표를 바꾸는 개정안은 거부됩니다. |
| **새로운 역량** (New capability) | 원리의 변화를 통해, 오늘날 어렵거나 불가능한 무언가가 가능해지는 것입니다. 단지 무언가를 더 빠르거나 더 싸게 만들 뿐인 **개선**(improvement)과 대비됩니다. |
| **결합에 의한 혁신** (Breakthrough by assembly) | 이미 존재하던 기술들을 새로운 방식으로 결합해 만든 혁신입니다. 비트코인이 그 예입니다. 서명, 해시 체인, 작업 증명, 피어 투 피어 네트워크는 모두 그 전부터 알려져 있었습니다. |
| **메커니즘 카드** (Mechanism card) | 관찰한 것부터 결론 내린 것까지, 하나의 메커니즘에 관한 열한 가지 질문입니다. 연구가 처음 아홉 개에 답하고, 여러분은 실험을 실행한 뒤에 마지막 두 개에 답합니다. |

## 타입 지정 결정과 커넥터 {#typed-decisions-and-connectors}

| 용어 | 쉽게 말하면 |
| --- | --- |
| **Jev** | 좁은 질문(예/아니요, 선택, 등급)에 여러분의 코드가 쓸 수 있는 확률로, 빠르고 저렴하게 답하는 TypeSafe의 모델입니다. [타입 지정 결정](./typed-decisions)을 보세요. |
| **Noul, Choice, Score** | Jev의 세 가지 질문 유형입니다. 예 또는 아니요, 목록 중 하나의 선택지, 척도 위의 한 수준입니다. 여러 선택지를 고를 때는 선택지마다 예/아니요 질문을 하나씩 던집니다. |
| **보정된** (Calibrated) | 평균적으로 현실과 맞아떨어지는 확률입니다. 80% 신뢰도로 내놓은 답 가운데 약 80%가 맞습니다. |
| **AI Gateway** | 하나의 키로 Jev를 포함한 여러 모델에 접근할 수 있게 해 주는 Vercel 서비스입니다. |
| **MCP** | Model Context Protocol입니다. AI 애플리케이션(Claude Desktop, Claude Code, IDE 어시스턴트, 에이전트)과 여러분의 시스템을 잇는 하나의 표준 "플러그"입니다. SDK는 함수, 웹 API, 폴더, 데이터베이스, 에이전트를 MCP 서버로 만들 수 있고, 어떤 MCP 서버의 도구든 사용할 수 있습니다. [쉽게 풀어 쓴 MCP](./mcp)를 보세요. |
| **MCP 서버** (MCP server) | 여러분의 시스템 앞에 놓이는 작은 프로그램으로, 자신이 무엇을 제공하는지 AI 애플리케이션에 알려 주고, 요청을 받으면 작업을 수행합니다. [첫 번째 MCP 서버](./mcp-first-server)를 보세요. |
| **MCP 클라이언트, 호스트** (MCP client, host) | 호스트는 사용자가 대화하는 AI 애플리케이션이고, 그 안에서 MCP 클라이언트가 서버 하나와의 연결을 유지합니다. |
| **리소스** (Resource) | 공유 폴더의 파일처럼, MCP 서버가 읽을 수 있도록 제공하는 문서입니다. 도구와 달리 모델이 아니라 사용자나 애플리케이션이 고릅니다. |
| **전송 방식** (Transport) | MCP 애플리케이션과 서버가 메시지를 주고받는 방법입니다. **stdio**(애플리케이션이 같은 컴퓨터에서 서버를 프로그램으로 시작하고 그 입력과 출력으로 대화함) 또는 **Streamable HTTP**(서버가 웹 서비스임)입니다. [stdio 또는 HTTP?](./mcp-deploy#stdio-or-http)를 보세요. |
| **OpenAPI** | 웹 API를 기계가 읽을 수 있게 기술하는 표준으로, 주소, 매개변수, 응답을 담으며 흔히 `openapi.json`으로 게시됩니다. SDK는 이것으로부터 오퍼레이션마다 도구를 하나씩 만듭니다. [웹 API](./mcp-recipes#a-web-api-from-its-openapi-description)를 보세요. |
| **JSON Schema** | 어떤 데이터(여기서는 도구의 인자)의 형태를 기술한 것으로, 모델과 MCP 애플리케이션이 도구를 올바르게 호출하기 위해 읽습니다. SDK가 여러분의 Zod 스키마나 OpenAPI 기술로부터 작성해 줍니다. |
| **읽기 전용** (Read-only) | 볼 수는 있지만 바꿀 수는 없습니다. 폴더와 데이터베이스 소스는 구조상 읽기 전용이고, 웹 API는 기본적으로 읽기 전용입니다(`GET` 오퍼레이션만). |
| **도구 소스** (Tool source) | 시스템으로부터 바로 쓸 수 있는 도구를 만들어 주는 함수입니다. `openApiTools`, `folderTools`, `databaseTools`, `cognitiveAgentTool`이 있습니다. 한 줄로 MCP를 통해 제공하거나, 여러분의 에이전트에게 줄 수 있습니다. [무엇이든 MCP 서버로](./mcp-recipes)를 보세요. |

## 프로덕션 운영 {#operating-in-production}

| 용어 | 쉽게 말하면 |
| --- | --- |
| **재시도** (Retry) | 실패가 일시적일 때, 실패한 요청을 잠시 기다렸다가 다시 시도하는 것입니다. [재시도와 폴백](./resilience)을 보세요. |
| **폴백, 페일오버** (Fallback, failover) | 첫 번째 모델이나 프로바이더가 계속 실패할 때 다른 것으로 전환하는 것입니다. |
| **인시던트** (Incident) | 실패한 실행, 차단된 행동, 페일오버가 알림으로 바뀌어 이메일이나 웹훅으로 여러분에게 전송되는 것입니다. [인시던트 알림](./incidents)을 보세요. |
| **웹훅** (Webhook) | 채팅 도구나 모니터링 도구가 여러분에게 주는 주소로, SDK가 이 주소로 알림을 보냅니다. |
