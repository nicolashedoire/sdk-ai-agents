# この SDK を選ぶ理由

**ひとことで言えば**、ほとんどのエージェントフレームワークは言語モデルが **行動する** のを助けます。この SDK は、結論を出す前に言語モデルに **自分が信じることを正当化** させ、さらに **特定の人物と同じように推論** させることもできます。

このページは、あえて率直に書いています。この SDK が、ほかではなかなか見つからないどんなことをするのか、ほかのフレームワークも同じようにしていることは何か、そしてほかのフレームワークのほうが上手にこなすことは何かを説明します。比較は、2026 年半ば時点で広く使われているフレームワーク（LangChain と LangGraph、OpenAI Agents SDK、Vercel AI SDK、CrewAI、AutoGen とその後継の Microsoft Agent Framework、Mastra、DSPy）のドキュメントにもとづいています。これらは急速に進化しているので、判断する前に最新のドキュメントを確認してください。

## 何が違うのか {#what-it-does-differently}

### 1. プロンプトではなく、コードで書かれた推論のルール {#_1-reasoning-rules-written-in-code-not-in-the-prompt}

一般的なエージェントでは、「推論」とはモデルが書いたものそのものです。モデルが 90% 確かだと言っても、あなたがそのチェックを書かない限り、それを確かめるものは何もありません。この SDK では次のようになります。

- [心的状態](./cognitive-agents#the-mental-state)（事実、仮説、予測、矛盾）は、自由記述のテキストではなく、型付きのデータです。
- モデルは自分の確信度を引き上げられません。決定の確信度は、選ばれた選択肢の証拠による支持度で頭打ちになり、その支持度は別の比較ステップで判定されます（思考者のプロファイルなしで Jev が判定するか、指示のもとで言語モデルが判定します）。
- 却下された仮説は、選択も更新も再提示もできません。何が変わったかを述べるバリアントとしてのみ戻ってこられます（言い換えただけの再提示は検出されません）。
- 回答が **確定** されるのは、[結論ガード](./evidence-and-verification#the-conclusion-guard) を通過したときだけです。批判を受けていること、最後に新しい証拠が加わった後に評価されていること、関係する矛盾がないこと、予算が許す範囲で予測が検証されていること、十分な支持度があること。そうでなければ、エージェントは足りないものを添えて **暫定** と答えるか、**判断を保留** します。

「結論を出せません」はれっきとした正式な結果であり、プロンプトで頼むのではなく、コードで強制されます。

### 2. 予測をチェックするのはモデルではなく、現実の世界 {#_2-the-world-checks-the-predictions-not-the-model}

よくあるパターンは、あるモデルに別のモデルを判定させることです。この SDK では、エージェントがテストの **前に**、何が観測されるはずか、何が観測されれば誤りだと証明されるかを述べ、判定は **あなたのコード** が行います。測定、シミュレーター、テストスイート、クエリなどです。反証された規則は却下され、違いを明示したバリアントとしてのみ戻ってこられます。[予測と結果評価器](./evidence-and-verification#predictions-and-the-outcome-evaluator) を参照してください。

テストが答えたことは、同じスコープのその後の実行のために保存されます。次の実行は持ちこたえた規則を手にして始まり、失敗した規則を一字一句そのまま再提示することはできません。記憶系の製品は語られたことを記憶しますが、この [実行をまたぐ記憶](./memory) はテストが答えたことだけを保持します。

### 3. 証拠と選好は切り離される {#_3-evidence-and-preferences-are-kept-apart}

思考者の選好は、**どの行動が選ばれるか** を変えることができ、思考者が明らかに好む行動を、もっともらしい程度の証拠で確定させることもできます。しかしコードの中では、選好が **世界についての主張** をより信頼できるものにすることは決してありません。Jev を使う場合、証拠についての質問は思考者のプロファイルなしで送られます。言語モデルが判定する場合、この分離はモデルへの指示にかかっています。[証拠は選好ではない](./evidence-and-verification#evidence-is-not-preference) を参照してください。

### 4. 特定の人物のように推論し、それを測定する {#_4-reasoning-like-a-given-person-and-measuring-it}

記憶系の製品が主に保存するのは、ユーザーについての事実や好みです（フィードバックから指示を書き換えるものもあります）。DSPy のようなプロンプト最適化ツールは、指標に照らしてプロンプトや例を調整します。この SDK は、人が **どのように** 推論するかを抽出します。問題を検討する順序、反射的な判断、アイデアを却下する理由です。その [思考者プロファイル](./thinker-profiles) をバージョン管理し、推論のすべてのステップに書き込み、その人の修正を一致度の割合とともに指示に加えます。さらに、エージェントが次のステップとして選んだものに、各実行に対するその人の判定をラベルとして付け、小さなコントローラーを学習させるためのデータセットとしてエクスポートします。

### 5. 推論の中での較正された決定 {#_5-calibrated-decisions-inside-the-reasoning}

[Jev](./typed-decisions) は、範囲の限られた質問に、提供元が較正した確率で答えます。1 セントにも満たないコストで次の推論ステップを選び、仮説を採点します。Jev に確信がないときは、決定論的なコントローラーが代わりを務めます。

### 6. 推論とアクションのための 1 つのログ {#_6-one-log-for-reasoning-and-actions}

ガバナンス付きツール、承認、コスト、リトライ、MCP 呼び出しは、すべての思考と同じイベントログに記録されます。どの回答についても、その背後でエージェントが「考えていた」ことを数か月後に正確に再構築でき、モデルを呼び出さずにそのアクションをリプレイできます。

## ほかのフレームワークにもあるもの {#what-other-frameworks-also-do}

- **ガバナンス付きツールと人による承認。** OpenAI Agents SDK のガードレール、LangGraph のヒューマン・イン・ザ・ループ。
- **永続化とリプレイ。** LangGraph のチェックポイントを使えば、過去の状態から再開、確認、リプレイ、分岐ができます。
- **MCP**、コストの追跡、リトライは広く提供されています。

この SDK の違いは、これらの要素が、明示的な推論状態とともに 1 つのイベントログを共有している点です。

## ほかのフレームワークのほうが優れている点 {#what-other-frameworks-do-better}

- **エコシステム。** 数百の統合、大きなコミュニティ、あらゆる用途のサンプル。
- **成熟度。** この SDK はまだ新しく、メンテナーは 1 人だけで、npm にもまだ公開されておらず、実際の問題で試された数も限られています。
- **マルチエージェントのオーケストレーション、ストリーミング、UI キット** は、ほかのフレームワークのほうが充実しています。
- **コストとレイテンシー。** 認知エージェントの回答には約 10 の推論ステップが必要で、それぞれに 1〜2 回のモデルリクエストがかかります（私たちの試行では、gpt-4o と Jev を使って、1 問あたり数分、約 0.1 USD）。直接の回答なら 1 回の呼び出し、ツールを使うエージェントでも数回で済みます。
- **モデルへの依存。** ルールはどのモデルでも守られますが、推論の質はそうではありません。小さなモデルは手法にうまく従えず、強力なモデルでも、難しい問題では暫定や判断保留で終わることがよくあります。
- **記憶と検索。** 記憶系の製品や検索パイプラインは、大規模なコレクションに対するセマンティック検索を提供します。この SDK の [実行をまたぐ記憶](./memory) は、狭いスコープの中で、単語の一致によって検証済みの規則を呼び出します。

## どんなときに選ぶべきか {#when-to-choose-it}

- **正当化や監査が必要な決定**：研究、産業、社内ガバナンス、そして人が結論とその根拠をレビューする規制分野（医療、金融、法務）での意思決定支援。
- **自信たっぷりの作り話よりも「わかりません」のほうがよく**、それを強制したいとき。
- **主張をチェックできるとき**：エージェントが予測を突き合わせられる測定、シミュレーター、テストスイートがある場合。
- **推論の分身**：専門家や創業者が問題にどう取り組むかを捉え、模倣がどこまで近づいたかを測定する。

手早く作れるチャットボット、既製の統合の豊富なカタログ、あるいは 1 回の高速な呼び出しが必要なら、より軽量なフレームワークのほうが適しています。
