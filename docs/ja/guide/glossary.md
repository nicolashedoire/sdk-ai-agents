# 用語をやさしく解説

このドキュメントで使われるすべての用語を、専門用語を使わずに説明し、詳しく解説しているページへのリンクを添えています。用語はテーマごとにまとめてあります。特定の用語にすぐ移動するには、検索ボックス（<kbd>/</kbd>）を使ってください。

## 基本 {#the-basics}

| 用語 | やさしく言うと |
| --- | --- |
| **SDK** | 開発者のための道具箱です。すべてを自分で書く代わりに、自分のアプリケーションに組み込むコードです。この SDK は TypeScript で書かれており、npm から `@sdk-ai-agents/core` という名前でインストールします（[はじめよう](./getting-started) を参照）。 |
| **言語モデル（Language model、LLM）** | テキストを読み書きする AI です（GPT-4o、Claude など）。この SDK では、いくつかある構成要素の 1 つにすぎません。モデルが提案し、何が許されるかは SDK がチェックして決めます。 |
| **プロンプト（Prompt）** | リクエストのたびに言語モデルへ送られる、テキストの指示です。 |
| **トークン（Token）** | 単語の断片です。モデルのプロバイダーは読み書きしたトークンの数に応じて課金するため、[コスト](./costs) はトークン単位で数えます。 |
| **エージェント（Agent）** | 言語モデルを使って、一歩ずつ目標に向かうプログラムです。この SDK には 2 種類あります。ツールを使って行動する [ガバナンス付きエージェント](./governed-agents) と、結論を出す前に推論する [認知エージェント](./cognitive-agents) です。 |
| **実行（Run）** | 1 つの問題に対するエージェントの 1 回の実行で、開始から終了までを指します。ID（`runId`）を持ち、それを使って実行を読んだり、リプレイしたり、料金を算出したりします。 |
| **ツール（Tool）** | あなたのコードがエージェントに渡す関数です（データベースを読む、メールを送る、など）。エージェントは、明示的に渡されたツールしか使えません。[基本概念](./concepts#_2-tool) を参照してください。 |
| **ケイパビリティ（Capability）** | 複数のエージェントにまとめて渡せる、名前付きのツールのグループです。 |
| **ポリシー（Policy）** | すべてのアクションの **前に** チェックされるルールです。予算、タイムアウト、許可するツールのリスト、あるいは独自のチェックがあります。 |
| **承認（Approval）** | リスクのあるアクションの前で、人が「はい」と言うまで一時停止することです。ポリシーが求めることも、ツール自体が求めること（`requiresApproval`）もあります。それより先に呼び出し元が待つのをやめた場合、アクションは実行されません。 |
| **意図（Intention）** | ガバナンス付きエージェントのモデルが「やりたい」こと（ツールを呼び出す、回答する、など）を書き出したもので、まだ実行はされません。SDK がまず検証します。 |
| **スキーマ（Schema、Zod）** | データが持つべき形を正確に記述したものです。ツール呼び出しや、推論ステップの構造化された応答はスキーマと照合され、合わない応答は拒否されます。 |
| **JSON** | 構造化データのためのプレーンテキスト形式です。プロファイル、イベント、モデルの応答は JSON です。 |

## トレーサビリティ {#traceability}

| 用語 | やさしく言うと |
| --- | --- |
| **イベント（Event）** | 記録簿の 1 行です。「この時刻に、これが起きた」。すべての実行のすべてのステップが、イベントとして記録されます。[イベントカタログ](../reference/events) を参照してください。 |
| **イベントストア（Event store）** | 記録簿を保管する場所です。ファイルのフォルダー、SQLite、PostgreSQL のいずれかです。 |
| **イベントソーシング（Event sourcing）** | 記録簿こそが真実である、という原則です。実行の状態は、心的状態も含めて、イベントを読み直すことで再構築され、別に保存されることはありません。だからこそ、どの実行も数か月後に監査できます。例外は思考者プロファイルです。イベントにはその ID とバージョンしか記録されないため、プロファイル自体を保存しておいてください。 |
| **トレース（Trace）** | 1 回の実行のすべてのイベントを、順番に並べたものです。 |
| **リプレイ（Replay）** | 記録された実行を、そのイベントからもう一度実行することです。その実行で決められたアクションが同じポリシーを通して再び実行されますが、言語モデルに再び問い合わせることはありません。実行を監査したり、ポリシーを変更した後に「もしこうだったら」を試したりするのに役立ちます。[トレーサビリティとリプレイ](./observability) を参照してください。 |
| **ゴールデントレース（Golden trace）** | 基準として残しておく、よい実行です。新しい実行はこれと照合されるので、振る舞いの変化を、失敗したテストのように検出できます。 |

## 認知エージェントの推論の仕方 {#how-a-cognitive-agent-reasons}

| 用語 | やさしく言うと |
| --- | --- |
| **心的状態（Mental state）** | エージェントがその問題について今「頭の中に持っている」すべてを、データとして書き出したものです。観測したこと、知っていること、仮定していること、知らないこと、検討中の選択肢が含まれます。[心的状態](./cognitive-agents#the-mental-state) を参照してください。 |
| **観測（Observation）**（`O1`…） | 見たものです。問題と一緒に渡された測定値や文書、ツールの結果、テストの結果などがあります。 |
| **事実（Fact）**（`F1`…） | エージェントが真だとみなす言明で、その出所が付いています。事実が削除されることはなく、理由を添えて「撤回」（retracted）されるか、「置換」（superseded）されます。 |
| **仮定（Assumption）**（`A1`…） | 推論が証明なしに当然のこととしているものです。 |
| **制約（Constraint）**（`K1`…） | どの回答も守らなければならない条件です（「第 4 四半期より前」、「1 万ユーロ未満」など）。 |
| **未知事項（Unknown）**（`U1`…） | 未解決の問いです。「解決」（resolved、答えが出た）または「断念」（dropped、答える手段がない）になることがあります。 |
| **仮説（Hypothesis）**（`H1`…） | 検討中の選択肢です。3 種類のいずれかです。**提案**（行動の選択。例：「その仕事を断る」）、**規則**（規則性。例：「転がる時間は質量に依存しない」）、**説明**（原因）。 |
| **帰納、アブダクション、演繹（Induction, abduction, deduction）** | 仮説にたどり着く 3 つの方法で、それぞれ、繰り返し現れる事例から規則へ、意外な出来事からそのもっともありそうな原因へ、規則から必然的に導かれることへ、と進みます。このラベルは申告されたものであり、主張を真にするわけではありません。 |
| **オペレーション（Operation）** | 推論の一手です。問題を表現する、仮説を立てる、シミュレーションする、批判する、比較する、決定する……など、全部で 10 種類あります。[オペレーション](./cognitive-agents#the-operations) を参照してください。 |
| **コントローラー（Controller）** | 次のオペレーションを選ぶものです。**ヒューリスティック**コントローラーは固定の順序に従い、無料で予測可能です。**型付き**コントローラーは各ステップで Jev に問い合わせます。 |
| **思考パッチ（Thought patch）** | 1 つのオペレーションが心的状態に加えた変更で、1 つのイベントとして記録されます。心的状態とは、すべてのパッチを順番に適用したものです。 |
| **シミュレーション（Simulation）** | 仮説が正しいとしたら何が起きるかを想像することです。まず直接の影響を、次に間接的な影響を考えます。 |
| **批判（Critique）** | エージェントが自分の選択肢を攻撃すること、つまり、それが失敗しうる最も強い理由を探すことです。反論のない **致命的な**（fatal）批判は、その選択肢を却下します。 |
| **矛盾（Contradiction）**（`C1`…） | 両方が同時に真ではありえない 2 つの事柄です。決着をつける観測や事実を引用して解決されるまで、未解決のまま残ります。 |
| **バリアント（Variant）** | 証拠と矛盾した仮説を修正したものです。スコープを狭めるか条件を加え、何が変わったかを述べる一文を添えます。 |
| **制限（Limits）** | 実行の予算です。ステップ数、時間、ツール呼び出しとテストの回数、結論を出すためのしきい値が含まれます。[制限](./cognitive-agents#limits) を参照してください。 |

## 証拠と結論 {#evidence-and-conclusions}

| 用語 | やさしく言うと |
| --- | --- |
| **出所（Provenance）** | ある証拠がどこから来たかです。あなたが渡したもの、ツールが返したもの、テストで測定したもののいずれかで、元のデータを保持するイベントも添えられます。 |
| **出所グループ（Origin group）**（`originGroup`） | 「同じ情報源」を示すラベルです。同じ出所からの 2 つの観測は、2 つの独立した裏付けにはなりません。 |
| **重複（Duplicate）** | 同じ出所からの同じ内容を、もう一度見たものです。重みは増えません。 |
| **予測（Prediction）**（`P1`…） | 仮説が正しければ観測されるはずのことで、検証する **前に** 記録されます。 |
| **反証条件（Falsifier）** | 観測されれば仮説が誤りだと証明される観測です。誤りだと証明しようのない主張は、検証できません。 |
| **知識（Knowledge）**（`M1`…） | 以前の実行が実際のテストで確立したことで、実行の開始時に呼び出されます。「検証済み」（verified）、「反証済み」（refuted）、テスト結果が食い違うときは「係争中」（contested）のいずれかです。[実行をまたぐ記憶](./memory) を参照してください。 |
| **スコープ（Scope）** | 記憶の境界です。実行は、学んだことを同じスコープの中でだけ共有します。たとえば 1 つのテストベンチや 1 つの製品がスコープになります。 |
| **結果評価器（Outcome evaluator）** | 予測を現実の世界（測定、シミュレーター、テストスイート）と突き合わせ、「確認」（confirmed）、「反証」（refuted）、「判定不能」（inconclusive）のいずれかを答える、あなたのコードです。言語モデルが自分の予測を採点することはありません。[予測](./evidence-and-verification#predictions-and-the-outcome-evaluator) を参照してください。 |
| **支持度（Support）** | 証拠が仮説をどれだけ裏付けているかで、0（反証済み）から 1（確立）までの値です。測定された確率ではなく、判断です。コードが選好をこの値に混ぜることはありません。言語モデルが判定する場合、それはモデルへの指示にかかっています（[証拠は選好ではない](./evidence-and-verification#evidence-is-not-preference) を参照）。 |
| **選好適合度（Preference fit）**（`preferenceFit`） | 行動の選択が思考者にどれだけ合っているかで、0（その人の却下基準のいずれかに該当する）から 1（理想的）までの値です。この値が付くのは行動の選択だけです。 |
| **順位付け（Ranking）** | 選択肢の順序です。主張は支持度だけで順位付けされます。行動の選択は、デフォルトでは支持度 60%、選好適合度 40% で順位付けされます。 |
| **古くなった評価（Stale）** | 証拠が最後に変わる前に行われた評価です。結論を出す前にやり直す必要があります。 |
| **結論ガード（Conclusion guard）** | 回答が確定されるために通過しなければならない、コードで書かれたチェックです。批判を受けていること、最後に新しい証拠が加わった後に評価されていること、関係する未解決の矛盾がないこと、予算にテストが残っている間は未検証の予測がないこと、十分な支持度があること。[結論ガード](./evidence-and-verification#the-conclusion-guard) を参照してください。 |
| **決定しきい値（Decision threshold）** | 確かな回答に必要な支持度です。デフォルトは 0.75 で、「強く支持されている」に相当します。思考者が明らかに好む行動の選択なら、0.35 で足ります。 |
| **確定（Committed）** | 結論ガードを通過した、確かな回答です。 |
| **暫定（Provisional）** | 予算が尽きた時点で得られている最良の回答で、まだ確立されていないことのリスト（`missing`）が付きます。 |
| **判断保留（Abstain）** | 理由を添えた「結論を出せません」という答えです。エラーではなく、正当な結果です。 |
| **確信度（Confidence）** | 決定がどれだけ確かかを表します。選ばれた選択肢の、証拠による支持度を超えることはありません。 |

## 人の推論を模倣する {#imitating-a-person-s-reasoning}

| 用語 | やさしく言うと |
| --- | --- |
| **思考者プロファイル（Thinker profile）** | ある人物が **どのように** 推論するかを記述したものです。問題を見る順序、優先事項、反射的な判断、却下基準、リスクへの許容度が含まれます。推論の各ステップの指示に書き込まれ、それによってエージェントはその人の推論を模倣します。[思考者プロファイル](./thinker-profiles) を参照してください。 |
| **サンプル（Sample）** | その人が自分の言葉で説明した 1 つのテーマです。テーマ、どう推論したか、何を結論としたかからなります。 |
| **抽出（Distill）** | サンプルからプロファイルを取り出すことです。テーマをまたいで、その人の推論の仕方に繰り返し現れるものを見つけます。 |
| **注意の順序（Order of attention）**（`reasoningSequence`） | その人がたどるステップを、順番に並べたものです。 |
| **ヒューリスティック（Heuristic）** | 「…のときは、…する」と書かれた、反射的な判断です。 |
| **却下基準（Rejection criterion）** | その人がアイデアを捨てる理由です。 |
| **判定（Verdict）** | 実行に対するその人の判断です。`match`（自分と同じように推論した）、`partial`、`mismatch` のいずれかです。 |
| **一致度（Agreement）** | その人が実行のどれだけに同意するかで、0 から 1 までの値です。`0.8` は「80% 正しい」という意味です。模倣がどこまで近づいたかは、これで測ります。 |
| **較正用の例（Calibration example）** | その人が認めた実行で、模範解答としてモデルに示されます。 |
| **修正（Correction）** | その人が同意しなかった実行から得た教訓で、最優先事項としてモデルに示されます。 |

## 型付き決定とコネクター {#typed-decisions-and-connectors}

| 用語 | やさしく言うと |
| --- | --- |
| **Jev** | TypeSafe のモデルで、範囲の限られた質問（はい／いいえ、選択、評価）に、コードで使える確率で、速く安く答えます。[型付き決定](./typed-decisions) を参照してください。 |
| **Noul、Choice、Score** | Jev の 3 種類の質問形式で、それぞれ、はいかいいえ、リストの中の 1 つの選択肢、尺度上のレベルを答えます。複数の選択肢を選ぶ場合は、選択肢ごとに 1 つのはい／いいえの質問をします。 |
| **較正された（Calibrated）** | 平均すると現実と一致する確率のことです。確信度 80% で出された回答のうち、およそ 80% が正しい、という状態です。 |
| **AI Gateway** | 1 つのキーで、Jev を含む複数のモデルを利用できる Vercel のサービスです。 |
| **MCP** | Model Context Protocol の略で、AI アプリケーション（Claude Desktop、Claude Code、IDE のアシスタント、エージェント）とあなたのシステムをつなぐ、標準の「差し込み口」です。この SDK は、関数、Web API、フォルダー、データベース、エージェントを MCP サーバーにでき、任意の MCP サーバーのツールを使うこともできます。[MCP をやさしく解説](./mcp) を参照してください。 |
| **MCP サーバー（MCP server）** | あなたのシステムの手前に置く小さなプログラムで、何を提供しているかを AI アプリケーションに伝え、頼まれたら処理を行います。[はじめての MCP サーバー](./mcp-first-server) を参照してください。 |
| **MCP クライアント、ホスト（MCP client, host）** | ホストは、ユーザーが対話する AI アプリケーションです。その中で、MCP クライアントが 1 つのサーバーとの接続を保持します。 |
| **リソース（Resource）** | MCP サーバーが読み取り用に提供する文書で、共有フォルダーのファイルなどです。ツールとは違い、選ぶのはモデルではなく、ユーザーやアプリケーションです。 |
| **トランスポート（Transport）** | MCP アプリケーションとサーバーがメッセージをやり取りする方法です。**stdio**（アプリケーションが同じコンピューター上でサーバーをプログラムとして起動し、その入力と出力を通じて対話する）か、**Streamable HTTP**（サーバーが Web サービスである）のどちらかです。[stdio か HTTP か](./mcp-deploy#stdio-or-http) を参照してください。 |
| **OpenAPI** | Web API を機械が読める形で記述する標準で、アドレス、パラメーター、応答を記述します。`openapi.json` として公開されていることがよくあります。SDK はこの記述から、オペレーションごとに 1 つのツールを作ります。[Web API](./mcp-recipes#a-web-api-from-its-openapi-description) を参照してください。 |
| **JSON Schema** | データの形（ここではツールの引数の形）を記述したもので、モデルや MCP アプリケーションはこれを読んでツールを正しく呼び出します。SDK は、あなたの Zod スキーマや OpenAPI の記述からこれを書き出します。 |
| **読み取り専用（Read-only）** | 見ることはできても、変更はできないことです。フォルダーとデータベースのソースは、構造上、読み取り専用です。Web API はデフォルトで読み取り専用です（`GET` オペレーションのみ）。 |
| **ツールソース（Tool source）** | あるシステムから、すぐに使えるツールを組み立てる関数です。`openApiTools`、`folderTools`、`databaseTools`、`cognitiveAgentTool` があります。1 行で MCP 経由で提供することも、自分のエージェントに渡すこともできます。[なんでも MCP サーバーにする](./mcp-recipes) を参照してください。 |

## 本番環境での運用 {#operating-in-production}

| 用語 | やさしく言うと |
| --- | --- |
| **リトライ（Retry）** | 失敗が一時的なものであるとき、少し待ってから、失敗したリクエストをもう一度試すことです。[リトライとフォールバック](./resilience) を参照してください。 |
| **フォールバック、フェイルオーバー（Fallback, failover）** | 最初のモデルやプロバイダーが失敗し続けるときに、別のものに切り替えることです。 |
| **インシデント（Incident）** | 失敗した実行、ブロックされたアクション、フェイルオーバーを、メールや Webhook で送られるアラートにしたものです。[インシデントアラート](./incidents) を参照してください。 |
| **Webhook** | チャットツールや監視ツールが発行するアドレスで、SDK はそこにアラートを送ります。 |
