### Changed
- **Policies are checked when they are applied.** `createSDK({ defaultPolicies })`, `defineGlobalPolicy`, an agent's `policies` (`createAgent`, `createCognitiveAgent`) and `agent.setPolicy` throw a `ValidationError` naming the field (`Validation failed: policy 'caps' rules[0].metadata.budgetLimit.maxToolCalls - must be a finite number >= 0, got NaN`) before anything is registered, when a limit cannot be checked: a `maxSteps`, `maxTokens` or `maxDuration` `value` that is not a finite number above 0 (`NaN`, `0` or a missing value turned the limit off, `Infinity` meant no limit and a negative value refused every call; a numeric string such as `'10'` worked only by coercion); a limit in a policy type that never reads it (`maxDuration` outside a `timeout` policy, `maxSteps`, `maxTokens` or `budgetLimit` outside a `budget` one), which did nothing; a `budgetLimit` without a known `period`, without any cap, with a non-string `agentId` or `toolName`, or with a cap that is not a finite number ≥ 0 (`NaN` turned it off, `Infinity` meant no cap, `null` acted as 0, a string such as `'2'` lost the protection against concurrent calls); a policy that is not an object, or `rules` that are not a list of objects. Disabled policies are not checked, and the rules of `custom` and `allowlist` policies are not read as limits. A limit changed after its policy was applied, and no longer checkable, refuses the calls it covers; a `budgetLimit` removed from its rule, or whose `agentId` or `toolName` is no longer a string, refuses every tool call its policy is checked for. **Migration:** convert values read from the environment (`Number(process.env.MAX_STEPS)`), and remove a rule or set `enabled: false` instead of a value of `0` or `Infinity`.
- SQL event stores refuse a table name that is not an SQL identifier (ASCII letters, digits and `_`, at most 63 per part, optionally after a schema: `app.events`), since it is written into the SQL; quoted names such as `"my-events"` are refused. Indexes are named `idx_<table>_…` without the schema: with a schema-qualified table they could not be created before (SQLite ignored the failure, PostgreSQL's failure stopped the process). For subclasses: `initializeSchema(connection)` receives the connection to create the schema with; an override written for the old hook still works (queries made through `this.connection` during schema creation do not wait for it).
- The default Anthropic model is `claude-opus-5` (`claude-3-5-sonnet-20241022` is retired).
- **The default OpenAI model is `gpt-5.4`** instead of `gpt-4`, a legacy model that OpenAI shuts down on 2026-10-23. It is the model of an OpenAI fallback that does not serve the agent's model (failing over from Claude, for instance) and of a request that names none. `gpt-5.4` is current, on OpenAI and Azure OpenAI alike, and a reasoning model: it gets no `temperature`, and `maxTokens` as `max_completion_tokens` (see *OpenAI reasoning models get the parameters they accept*). It calls tools through Chat Completions, which the SDK uses, only with its default effort, `none`: a `reasoningEffort` other than `none` makes OpenAI refuse the requests of agents with tools. Set `providerConfig.openai.defaultModel` (or a fallback's `config.defaultModel`) to keep another model; `DEFAULT_OPENAI_MODEL` is exported. A `ReasoningEngine` created without a model lets its provider use its own default model instead of asking any vendor for `gpt-4`.
- Public types: `SDKConfig.fallbackProviders` items are a union on `provider` (an OpenAI fallback's `config` also takes the OpenAI options); `providerConfig.openai` is an `OpenAIVendorConfig` and `providerConfig.anthropic` a `VendorConfig`; `providerSettings.openai` (agents, runs, cognitive agents, `ReasoningContext`) is an `OpenAIProviderSettings`; `LLMRequest`, `CognitiveAgentConfig` and `LLMThoughtGeneratorOptions` have an optional `reasoningEffort`; `OpenAIProvider.nativeToolMessages` is a `boolean` set by its options (it was the literal `true`).
- `createSDK` refuses a fallback of another vendor that has no API key (`ValidationError` naming `fallbackProviders[i]`) instead of sending it the primary key.
- A policy refusal carries the violated policy's own reason for every policy type (a custom policy's reason included) instead of "Violated policies: <ids>".
- With fallbacks configured, `intention.generated` metadata names the provider that answered (`anthropic`) instead of "openai (fallback: anthropic)".
- `OpenAIProvider.supportsModel` also accepts `o3`, `o4-mini`, `chatgpt-*` and fine-tuned `ft:` models.
- Public types: `LLMRequest.messages` is `LLMMessage[]`, with assistant `toolCalls`/`vendorContent` and a `tool` role (only sent to providers that declare `nativeToolMessages`); `LLMResponse.toolCalls` items may have an `id`, and `LLMResponse` may carry `vendorContent`; `ActionContext` has an optional `run` (`RunProgress`: step, tokens used, start time); `LLMMessage` and `LLMToolCall` are exported.
- Tests: no suite mocks a module or a function any more. The OpenAI and Anthropic adapters, the SDK and the reasoning engine run against a local server answering in the vendor's format, event stores are real, and `no-mocks.test.ts` refuses `vi.mock`, `vi.fn` and `vi.spyOn`.
- `metadata.requiresApproval: true` on a tool is now **enforced**: every call waits for `sdk.approveAction` (policy id `tool-requires-approval`) even when every policy allows it. It was only descriptive before, so a tool marked this way ran without any approval. A replay repeats without asking only the calls a human approved in the original run (same tool, same parameters); any other such call — rejected, cancelled or never approved — is refused (policy approvals still apply).
- Pending approvals no longer wait forever. A pending approval is cancelled — the action refused, recorded as `approval.rejected` with a `reason` — when the caller's `signal` aborts (a stopped run, an MCP client that cancelled, a stdio client that exited, an HTTP connection that closed) or after `approvalTimeoutMs` without a decision (`executeTool` option; **50 000 ms by default for MCP servers**). A stateless HTTP server cannot see a client's cancellation: there, an approval lasts until the connection closes or `approvalTimeoutMs`, and a "yes" given before that still runs the tool. The call is checked again after the approval, before the tool runs. A cancelled approval fails the call with a `PolicyViolationError` instead of a raw error.
- The order of the checks of a tool call is now: allowlist, **arguments** (the tool's schema), policies, approval, budget, then the tool. Invalid arguments were checked last, after policies and approvals.
- **Call budgets are counted when a call is admitted**, checked and counted in one synchronous step, so concurrent calls cannot all get under a limit (10 of 10 simultaneous calls ran with a limit of 2). A call counts whatever its outcome, failures included; calls were counted after success only.
- Budget limits that name only an agent (or only a tool) now deny calls beyond their limit: they never counted any call before (see Fixed).
- **A governed agent only runs its own tools** (`tools`, `capabilities`): a tool registered in the SDK for someone else (an MCP server, another agent) is refused as `allowed-tools`, even if the model names it. It could run before.
- `createSDK()` without any model key no longer throws: tools and MCP servers work, and the first call that needs a model fails with "no language model is configured".
- `GovernedToolHost` (what `createMcpServer` needs from the SDK) also requires `defineTool` and `traceResourceRead`; `createSDK()` implements them. Existing `createMcpServer`/`serveMcpOverStdio` options are unchanged; `serveMcpOverStdio` writes one "ready" line to stderr and closes when stdin ends.
- Public types: the new event type `resource.read` (an exhaustive `switch` over `EventType` needs a new case); `ToolRegistry.executeTool` takes a fourth argument, the call context; `ToolDefinition.handler` a second one.
- The file event store's flush timer no longer keeps the process alive; pending events are written just before the process exits, in one attempt (a store that cannot write — its folder cannot be created — no longer keeps the process spinning). A script or a stdio MCP server can now end without `process.exit()`.
- `ApprovalManager` forgets decided requests beyond the last 1 000 (they stayed in memory forever), and keeps them out of the pending list.
- The golden-trace, regression-suite, assertion and impact-analysis folders are created when first used, not when the SDK starts: an MCP server started from any working directory no longer creates (or fails to create) them there.
- CI runs on Node.js 20.x, 22.x and 24.x; the SQLite suite runs where `node:sqlite` exists and says why it is skipped on Node 20.
- The conclusion guard can commit a **choice of action** the thinker clearly prefers (`preferenceFit` ≥ `decisionThreshold`) when its evidence support reaches `limits.minProposalSupport` (0.35): with a real thinker profile, questions such as "would you take this job?" always ended in an abstention because they have little evidence to weigh. Claims about the world (rules, explanations) still need evidence support ≥ `decisionThreshold`. The rule is recorded in `cognition.started` (`commitRules.minProposalSupport`); runs recorded before keep the evidence-only rule.
  - Public types: `CognitiveLimits` has a new field `minProposalSupport`, and `DecisionBlocker` a new variant `low_fit` (an exhaustive `switch` over blocker kinds needs a new case).
  - `minProposalSupport` may not exceed `decisionThreshold` (`ValidationError`); set it equal to switch the path off. Lowering `decisionThreshold` without setting it lowers the default floor with it.
  - The model is told that a statement about what is true is never a `proposal`, since the kind now decides which commitment rule applies, and, first of all, that when the goal asks what to do, how to react or which action to take, the hypotheses are the candidate courses of action and must cover the answer the thinker would give. With a real model and a real thinker profile, the hypotheses for "would you take this job?" were statements ("the systems could be modernized"), so no answer could be committed even when the rationale said "I decline"; with this instruction, two of three such questions ended committed instead of none.
- The documentation says plainly that a cognitive agent can imitate the way a given person reasons, and what that covers: the thinker profiles guide explains each step, where the profile weighs and where it never does, and how to measure how close the imitation gets. A new page, *Key terms in plain words*, explains every term used in the documentation.
- Public types, for the run cost fixes (see Fixed): `DecisionResponse.usage` and `DecisionEvaluationRecord.usage` are optional — absent when the backend reported no token counts, where `JevClient` returned 0 input and 0 output tokens (**migration:** read `response.usage?.inputTokens`); `EventType` has a new member, `provider.answer_discarded` (an exhaustive `switch` over `EventType` needs a new case). New fields: `RunCostReport.unpricedCalls`, `unmeteredCalls` and `unmeteredModels`; new optional fields: `ModelCostLine.unmeteredCalls`, `ModelUsage.unmeteredCalls`, `DecisionEvaluationRecord.error`, `DecisionClientError.billed` (`BilledDecisionCall`), `LLMRequest.onDiscardedAnswer` (`DiscardedAnswer`) and `ReasoningContext.onModelUsage` (`ModelCallUsage`). A governed agent counts a model call in its budgets and its run's tokens as soon as the vendor has answered, before the answer is read, through `onModelUsage`.

### Fixed
- **OpenAI reasoning models get the parameters they accept.** The o-series (`o1`, `o3`, `o4-mini`…) and GPT-5 and later refuse `max_tokens`, and `temperature` unless their reasoning effort is `none`, with a 400, and the SDK sent both on every call (a governed agent sends a temperature of 0.7 by default, a cognitive agent 0.4): agents failed on these models, except GPT-5.1 to GPT-5.4 without `maxTokens`, whose default effort is `none`. The OpenAI provider now recognizes them by name, whatever the letter case, dated or fine-tuned (`ft:o4-mini-…`) included, and sends them `maxTokens` as `max_completion_tokens` (which also counts their reasoning tokens). As the default effort varies by model, it never sends them a temperature: the temperature of the agent or of the engine is ignored for them. Other models keep `temperature` and `max_tokens`: OpenAI accepts `max_tokens` for them, and it is the parameter every OpenAI-compatible server (Azure OpenAI, local model servers, gateways) knows, where `max_completion_tokens` could be ignored and the limit silently lost. A name that says nothing, such as an Azure deployment, is declared with `reasoningModels` (see Added). A limit remains, which the SDK does not work around: on Chat Completions, which it uses, GPT-5.4 and later call tools only with the effort `none`, so an agent with tools on GPT-5.5, GPT-5.6 or GPT-6 Sol and Luna (default effort `medium`) needs `reasoningEffort: 'none'`, and GPT-6 Astra cannot call tools through the SDK. The effort set is always sent unchanged.
- **Security: ids can no longer name files outside their folder.** A run id given to the file event store (`getEvents`, `append`, a replay) and the ids of golden traces, regression suites, impact analyses and assertions were joined to a path as they were: `../x` read, wrote or deleted files next to those folders (`deleteGoldenTrace('../victim')` deleted `victim.json`). An id may now only use letters, digits, `.`, `_` and `-`, and not start with a dot; the event store refuses others with a `ValidationError` (`checkRunId`, also used by `sdk.decisions` before the paid call), and the managers find nothing to read or delete. `getRunIds` skips a file whose name is not such an id (a copy, or a run recorded by an older version under an id with a space or `:`); rename those files to keep reading them.
- **SQL event stores wait for their schema.** `SQLEventStore` (and `PostgreSQLEventStore`, `SQLiteEventStore`) created its table without waiting: on a new database the first write could run before the table existed, and a database unreachable at start-up left an unhandled rejection that stops a Node process. Every query now waits for the schema; if its creation fails (database not reachable yet), the operations waiting for it report the error and the next operation tries again. `close()` lets a schema creation in progress finish, for PostgreSQL too. With a schema-qualified table on SQLite (`app.events` in an attached database), the indexes are now created (`app.idx_events_…` on `events`); they never were.
- **`maxCost` budgets apply.** `BudgetLimit.maxCost` was never read: a cost cap never refused anything. Each model call of a governed agent now adds its cost (from `SDKConfig.pricing`, on the model that answered, else the one requested) to the agent's budgets per period and to limits that name no agent, which therefore sum every governed agent. A `budgetLimit` with `maxCost` refuses tool calls once the spend is over it; a model call itself is never refused. With `toolName`, that tool is refused on its agent's (or everyone's) spend, since model calls are not attributable to one tool. When a call's cost is unknown (a model without a price, or no input/output token counts), the cap cannot be checked and tool calls are refused, with that reason. A `maxCost` that is not a finite number ≥ 0 (a string such as `'0.5'` read from a config file, `NaN`, a negative amount, `Infinity`, `null`) is refused when the policy is applied (see *Policies are checked when they are applied*). Cognitive agents' and `sdk.decisions` calls are not counted. `sdk.getBudgetUsage` reports `costUsd`, `unpricedCalls` and `unmeteredCalls`.
- **Run costs no longer report $0 for calls whose cost is unknown.** `sdk.getRunCost` (and `computeRunCost`) skipped a model call recorded without token counts (no `usage`, or a total alone) or without a model name, and a cognitive thought or a Jev decision whose vendor reported no token counts was recorded as 0 tokens: a run could report `totalUsd: 0` and `complete: true` for calls it could not price. Such a call is now counted as unmetered, as budgets count it: the report has `unmeteredCalls` and `unmeteredModels`, a line its `unmeteredCalls`, `unpricedCalls` counts the calls of models without a price, `complete` is `false` whenever the cost of a call is unknown, and `totalUsd` only adds up the known costs. A call that recorded no model name is listed as `unknown` and never priced. The final answer of a cognitive run (`intention.generated` with `source: 'cognition'`) is not a model call and is not counted.
- **Billed calls whose step fails are counted.** A model call the vendor answered is now recorded and counted — in the run's events, in `getRunCost` and, for governed agents, in budgets per period and the run's `maxTokens` — even when the SDK then fails the step on its answer:
  - a governed agent's tool call whose arguments are not valid JSON was in the run's events but not in the agent's budgets, so a `maxCost` or `maxTokens` budget missed it;
  - an OpenAI answer without any choice, billed with its usage, was dropped when it failed the call or a fallback took over (also when a custom `retryOn` retried it): it is recorded as a `provider.answer_discarded` event and counted, and a replay counts its tokens in the run's progress, as the original run did;
  - a cognitive operation cut short by `stop()` or the run's timeout lost the attempts already billed (an invalid reply whose repair was interrupted): they are recorded in `cognition.operation_failed` with their `usage`; a hypothesis comparison interrupted during its second request keeps the first one's `decision.evaluated`;
  - a typed decision whose answer does not match its questions (a choice that is not one of the options, a missing or mistyped answer) was billed but never recorded: `sdk.decisions` records it as `decision.evaluated` with the `error` and empty `answers` before throwing, and the typed-decision controller and hypothesis assessor record it before falling back; a body that is not a valid answer is recorded when it reports its usage.

  Retries and failovers after an HTTP error, a timeout or a lost connection are not counted: no answer, no usage.
- **Budget and timeout policies now apply.** They were checked with step 0, 0 tokens and a start time of "now", so `maxSteps`, `maxTokens` and `maxDuration` never denied a call, and token budgets per period counted nothing. A governed agent now passes its run's step, tokens and start time with each tool call, and records the tokens of each model call for the agent's token budgets (limits that name no agent count them too). A refusal gives the policy's own reason ("Max steps (10) exceeded"), and a replay applies these limits as the original run did, so a call they refused is refused again.
- **Failover between vendors.** A fallback received the agent's model, so failing over from OpenAI to Anthropic sent `gpt-4` to Anthropic, which refuses it. A fallback now gets the requested model only if it serves it, and its own default model otherwise. `intention.generated` names the provider that answered and the model actually requested; when every provider fails, the error names each attempt with its own message.
- **The primary API key is never sent to another vendor.** A fallback without a key of its own got the SDK-wide `apiKey` (an OpenAI key sent to Anthropic, or to its `baseURL`). It now takes its key, model and address from its `config`; a fallback of another vendor then from its vendor's `providerConfig`, and one of the primary's vendor from nothing but the SDK-wide `apiKey` (it never inherits the primary's `providerConfig`, whose address may be the failing gateway).
- The Anthropic provider reports the model the API answered with, not the requested one, so costs are priced on the model that served the call.
- **Cancellation reaches the vendor.** An already cancelled call is no longer sent (nor billed), and an aborted call cuts the HTTP request instead of waiting for the full answer; a fallback chain stops at once. The reasoning engine also honours `ReasoningContext.abortSignal`.
- Provider settings follow the documented priority, field by field: run provider-specific > run default > agent provider-specific > agent default (an agent's provider-specific value used to beat a run default).
- **Recent Claude models work.** Claude Opus 4.7 and later, Sonnet 5 and the Fable and Mythos models refuse `temperature` with a 400, which the SDK always sent: it is no longer sent to them. Without a `maxTokens` setting, Claude 4 and later get 16 000 output tokens (thinking, on by default for Opus 5, Sonnet 5 and Fable, counts in it), Opus 4 and 4.1 8 192, Claude 3 4 096. Model ids behind a platform prefix or suffix (`anthropic.claude-…`, `…@date`) follow the same rules.
- `FileEventStore.destroy()` waits for the creation of the store's folder: a caller deleting the folder right after could race with it.
- The file event store could write a run before its folder existed (the folder is created in the background at start-up); writes now wait for it. Seen as a rare `ENOENT` under load.
- Budget limits that name only an agent (or only a tool) never counted tool calls, so they never stopped anything: calls are now counted for every scope a limit can name (agent and tool, agent, tool, all).
- Tool parameter schemas sent to LLMs and MCP clients kept only property types: enum values, descriptions, nested objects and array items were lost, so models invented arguments (seen with a real model inventing a metric name). They are now converted with `zod-to-json-schema` (new dependency).
- `seek_information` no longer spends two attempts on a question no available tool can answer: the unknown is dropped at once with the reason, so the other open questions get their turn. A step that brings no observation is recorded as failed.
- The minimum zod version is 3.25.28 (required by `zod-to-json-schema`).
- The model sees the experiments already run and their results, and is asked for untested, discriminating tests: with a real model, runs stopped repeating the same experiment.
- Jev reached through Vercel AI Gateway (`typesafe-ai/jev`) is priced by default; the typed decisions guide and the cognitive example show how to use an AI Gateway key.
- A 429 meaning the account is out of credit or quota (`insufficient_quota`, `credit_balance_exhausted`, billing limits) is no longer retried: it failed only after useless waits. Found with a real OpenAI key.
- `LLMProviderError` messages include the vendor's message (`LLM provider error: openai: 429 You have no credits remaining…`), with any API key fragment masked (`redactApiKeys`), and a cognitive run that stops after consecutive failures says what the last one was.

### Added
- **OpenAI options** in `providerConfig.openai`, in the `config` of an OpenAI fallback (a fallback of another vendor takes each option its `config` does not set from `providerConfig.openai`) and in the options of `OpenAIProvider`: `reasoningModels` (`true` or `false` for every model, or the list of names that are reasoning models, for names the SDK cannot recognize such as Azure deployments or gateway aliases), `reasoningEffort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh` or `max`, sent as given to reasoning models only; the API refuses the values a model does not accept) and `nativeToolMessages` (`false` for an OpenAI-compatible server that does not accept assistant `tool_calls` and `tool` messages in the conversation: earlier tool calls and results then go as plain text, while tools are still offered and the tool calls of replies still read; `false` on the primary or on any fallback applies to the whole chain). `createSDK` and `OpenAIProvider` refuse a value of the wrong type with a `ValidationError` naming the option (`providerConfig.openai.reasoningModels`, `fallbackProviders[1].config.reasoningEffort`…): a string given as `reasoningModels` would have matched every model name it contains. An agent or a run sets its own effort with `providerSettings.openai.reasoningEffort`: the run's wins, then the agent's, then the provider's. A cognitive agent applies it to tool selection only; its thoughts, which offer no tools and can therefore reason on GPT-5.4 and later, take the new `reasoningEffort` option of `createCognitiveAgent`. Types `OpenAIProviderOptions`, `OpenAIRequestOptions`, `OpenAIReasoningEffort`, `OpenAIProviderSettings`, `VendorConfig` and `OpenAIVendorConfig` are exported.
- A `LICENSE` file (MIT, as `package.json` and the README already said), included in the published package.
- **The built-in providers are exported.** `OpenAIProvider`, `AnthropicProvider` (and `DEFAULT_ANTHROPIC_MODEL`) and `FallbackProvider` (and its `FallbackResult` type) can be imported from the package, so a fallback chain can be composed by hand and given as `llmProvider`: its failovers are recorded as `provider.fallback` events, as with `fallbackProviders`. `retry` does not apply to the providers of such a chain: wrap one in `RetryingLLMProvider` (with `maxRetryAfterMs` set to `maxDelayMs`) and give its client `maxRetries: 0` to retry it before failing over (those retries are not recorded as `provider.retry` events). `VendorClientOptions` (`maxRetries`, `baseURL`) is exported with them.
- **Tool results in each vendor's native format.** The OpenAI and Anthropic providers get the assistant's tool call and a tool result tied to it by id (`tool` message, `tool_result` block) instead of plain-text lines. A turn Claude returned is sent back unchanged, thinking blocks included, and Claude is asked for one tool call per turn, as the SDK runs one tool per step; when a model still makes several, the others get a "not run" result, so every call is answered. A custom `llmProvider` keeps the plain-text lines unless it declares `nativeToolMessages`.
- **`baseURL` for the built-in providers.** `providerConfig.<primary>.baseURL` and `fallbackProviders[].config.baseURL` point the OpenAI or Anthropic provider at a compatible endpoint (the Azure OpenAI v1 API, a local model server, a gateway) or a proxy. The Anthropic provider no longer sends the `ANTHROPIC_AUTH_TOKEN` environment variable as a bearer token besides its key.
- **Memory across runs.** `createCognitiveAgent({ knowledge: { store, scope } })`: at the end of a run, every rule or explanation with a prediction the outcome evaluator confirmed or refuted is recorded in the scope's journal; at the start of the next run, the most relevant items are recalled as `knowledge` (`M1`…), recorded in `cognition.started` so a rebuild never reads the store. A hypothesis restating a refuted item word for word (same kind, statement and scope) is refused; one restating a verified or contested item is linked to its earlier tests. Stores: `FileKnowledgeStore` (JSONL journal per scope) and `InMemoryKnowledgeStore`, or your own `KnowledgeStore`. New event `cognition.knowledge_recorded`; `MentalState` has a new field `knowledge`. Scopes are lowercase. A failing or silent store (bounded by `limits.timeoutMs`) never stops a run, and never replaces its result. Guide: *Memory across runs*; `examples/rule-discovery.ts` uses it.
- **An MCP server for anything, in one line.** New tool sources in the core package, usable by agents and by MCP servers alike:
  - `openApiTools({ spec })` turns the operations of an OpenAPI 3 description (URL, file or parsed object) into tools: local `$ref`s resolved with a cycle guard and an expansion budget per operation and per spec, one flat JSON Schema per operation (path, query and header parameters, JSON body; bounded in size; parameters that would share an argument name are refused), arguments checked by the tool's schema before policies and approvals, base URL from the option or `servers[0]`, `headers` for authentication that the model never sees and cannot override (with them, `baseUrl` is required unless the spec comes from the API's own origin, and `http:` — for the API and for downloading the spec — only on loopback), path values that cannot contain `/`, `\` or dot segments even percent-encoded (malformed escapes included), injectable `fetch`, timeout, responses cut at `maxResponseBytes`, redirects refused (also when a custom `fetch` followed one), non-2xx statuses as tool errors. **Read-only by default**: only `GET` operations, unless others are listed in `include` — they are then `riskLevel: 'high'` and `requiresApproval: true` unless `metadata` sets a field explicitly. `retry` applies to read-only operations, on 5xx, 429, timeouts and network failures only. Filters by `operationId` and tag; tool names from `operationId`, valid and unique.
  - `folderTools({ root })` (`list_files`, `read_file`, `search_files`) and `folderResources({ root })`: text files of one folder, real paths checked so `..` and symbolic links cannot leave it, hidden names never offered, include/exclude globs (an excluded folder hides everything inside it), unreadable sub-folders skipped, bounded reads, listings and searches (`truncated` when a walk stopped early).
  - `databaseTools({ database })` (`list_tables`, `describe_table`, `query`) with `sqliteReadOnly(db)` (`node:sqlite` or better-sqlite3: `PRAGMA query_only`, writing statements refused, rows read and converted one at a time) and `postgresReadOnly({ pool } | { client })` (`BEGIN READ ONLY` only on a connection not already inside a transaction — detected with `transaction_timestamp() = statement_timestamp()`, `SET LOCAL statement_timeout`, `ROLLBACK` then `pg_advisory_unlock_all()`, one statement enforced by the server, transactions never interleaved on one client, a pool refused as a client; only SQL errors — by SQLSTATE — are shown to the model). A lexical check (`assertSingleQuery`, SQLite and PostgreSQL syntax, `E'…'` strings and their continuations included) accepts one `SELECT`/`WITH`/`VALUES` statement without bind parameters and with balanced parentheses; rows are capped (`maxRows`, fetched as limit + 1 to report truncation) and made JSON-safe (arrays keep 100 items; long values are cut into copies, so the originals can be freed).
  - `cognitiveAgentTool(agent)` and `governedAgentTool(agent)`: an agent as one tool (for example a reasoning twin built from a thinker profile), returning a compact result; the run is cancelled when the caller gives up; `context` is bounded (`maxContextLength`); a failed run's message stays in the event log unless `exposeErrors`.
- MCP servers accept tool definitions in `tools` (defined on the SDK for you; still nothing exposed unless listed), serve **resources** (`resources: ResourceProvider | ResourceProvider[]`, every read traced as a run with a `resource.read` event holding the URI, size and SHA-256; listing failures keep their cause on the server), send the `readOnlyHint` annotation for tools with `metadata.readOnly`, pass the client's cancellation to the call, cancel approvals nobody decides within `approvalTimeoutMs`, and explain input refusals (`ValidationError`) to clients while other causes stay hidden unless `exposeErrorDetails`.
- `ToolMetadata.readOnly`, `ToolCallContext` (`{ runId, agentId, signal }`, second argument of tool handlers), `ToolRetryPolicy.retryOn` (invalid arguments are never retried), `sdk.traceResourceRead()`, `executeTool(…, { signal, approvalTimeoutMs })`, `ThinkInput.signal`, `RunInput.signal` (cancels a governed run).
- **Evidence loop** (observe → compare → deduce → verify → revise) in cognitive agents, with three new operations:
  - `compare_observations` records similarities, differences, evolutions, incompatibilities and counterexamples;
  - `test_prediction` runs your `OutcomeEvaluator` (no LLM call) and records a `cognition.evaluated` event;
  - `revise` turns a refuted or contradicted hypothesis into a variant with `parentId`, scope and a required `difference`.
- **Observations with provenance**: `think({ observations })`, tool results and test results become observations (`O1…`) with source, event id, time, context, fingerprint and origin group; repeated evidence is marked as a duplicate and adds no weight; facts cite the observations they come from, are not added twice, and can be retracted or superseded.
- **Hypotheses** state their `kind` (proposal, rule, explanation), inference, premises and scope; **predictions** (`P1…`) carry an expected result, a falsifier and test parameters, are recorded before they are tested and tested once. A refuted prediction rejects its hypothesis and is logged as a resolved `refuted_prediction` contradiction; an inconclusive or failed test, or a refutation that reports no observation, never rejects anything.
- **Evidence kept apart from preferences**: `support` (evidence) and `preferenceFit` (thinker fit, proposals only) are separate scores; only proposals are ranked with preferences (`limits.preferenceWeight`); the state's confidence is the evidence support of the best-ranked hypothesis.
- **Stale assessments**: an `evidenceRevision` counter makes earlier assessments stale when the evidence changes; a comparison must reassess every hypothesis in play (the LLM is asked to repair an incomplete one), and one that fails or skips a hypothesis does not count.
- **Conclusion guard**: `decide` is offered only when a hypothesis is critiqued, freshly assessed, free of unresolved contradictions in its scope, has no untested prediction while tests are possible, and reaches `decisionThreshold`. A decision that is not ready, or selects no hypothesis, is deferred while the budget lasts; a forced decision becomes `provisional` with `missing`, or an `abstain` (confidence 0) — also when the model cannot produce a decision at all. Decision confidence is capped by evidence support.
- Contradictions have a category and are resolved once, only with cited observations or facts; the resolution and its action are kept. Engine-found contradictions are not duplicated.
- Thinker feedback accepts `agreement` (share the thinker agreed with) and `wrongAbout` (where the reasoning went wrong); both are kept with corrections and `agreement` is exported with the controller dataset.
- Options `evaluator`, `generator` and a custom `HypothesisAssessor` for `assessment`; limits `maxPredictionTests` and `preferenceWeight`.
- Building blocks exported: `assembleThought`, `admitProposal`, `settleDecision`, `assessReadiness`, `rankHypotheses`, `PredictionTester`, observation builders and their types.
- Documentation: *Evidence & verification* guide, new evidence-loop illustration, updated loop and architecture illustrations, `examples/rule-discovery.ts`.

### Changed
- Every thought enters the state through `assembleThought`: fields are restricted per operation, engine-only fields (observations, test results, failures, decision status) are stripped from proposals, and an invalid thought from a custom component is recorded as a failed operation instead of stopping the run. Components receive a copy of the state.
- A step that changed nothing it was meant to change (no new hypothesis, nothing newly simulated or critiqued, no comparison recorded), an incomplete comparison and a deferred decision count as failed attempts of their operation; `compare_observations`, `hypothesize`, `simulate`, `revise`, `critique`, `compare` and `decide` are no longer offered after two failed attempts in a row, until another step brings new evidence (a step that succeeded, or a tool or test result recorded by the engine). Deferrals and steps without effect are recorded as failed (`cognition.thought.failed`, `cognition.operation_failed`) but do not count toward `maxConsecutiveFailures`, which counts failures of the model or its tools (an incomplete comparison after repair included).
- A repeated observation counts as the same evidence as its original (facts and test results reference the original), and the same model contradiction is not recorded twice.
- Proposals that restate an existing hypothesis (rejected or still in play) or a variant without `difference` are removed before the `maxHypotheses` cap, so they cannot take a valid proposal's place; a known fact read again gains the new source instead of being duplicated.
- `TypedHypothesisAssessor` asks evidence questions without the thinker's profile and fit questions in a second request, proposals only (the `evidenceWeight` option is removed); a missing evidence answer makes it fall back to the LLM comparison.
- `cognition.started` records `schemaVersion: 2`, initial observations and commit rules; runs without a version are rebuilt with their original rules (decision on a rejected hypothesis kept without its reference, patch confidence used, no evidence rules).
- `ActionEngine.executeIntention` returns the `tool.called` and `action.executed` events it recorded (the `events` field used to be empty).
- Public types gained required fields: `CognitiveLimits` (`maxPredictionTests`, `preferenceWeight`), `MentalState` (`schemaVersion`, `observations`, `comparisons`, `predictions`, `evidenceRevision`, `observationsCompared`, `commitRules`), `Hypothesis` (`kind`, `premiseRefs`, `evidenceRefs`, `counterEvidenceRefs`), `Fact` (`observationRefs`, `status`) and profile corrections (`wrongAbout`). `ThoughtRequest.observation` is a `ToolObservation` with an `observationId`. The patch `confidence` is only used by legacy runs, and `ALLOWED_FIELDS` no longer lists it.
- `describeMentalState` omits empty collections and adds readiness and ranking, so the `state` of exported controller datasets changes shape, for older runs too.
- `ReasoningFeedback` is the schema's input type (`wrongAbout` optional) and `refineProfile` validates it; `thoughtPatchSchema` and patch types live in `thought-patch.ts`, `describeMentalState` in `mental-state-view.ts` (both still exported from the package entry).

### Changed
- `defineTool` infers the handler parameters from the Zod schema; typed Choice answers are typed with the offered options.
- Costs include failed thought attempts and model calls per repair, and prices are looked up by the returned model id and by the requested model name.
- The run status is the last lifecycle event, so events appended after the end of a run do not reopen it.
- `FileEventStore` serializes flushes per run, takes the buffer before writing and writes atomically (temporary file + rename): overlapping flushes no longer duplicate or drop events. `getRunIds()` flushes buffered events first; `destroy()` returns a promise that resolves after the final flush. Mental-state rebuild, costs and datasets ignore events repeated with the same id.
- SQLite and PostgreSQL event stores are exported from the package entry.
- `apiKey` is optional when `llmProvider` is given; `pg` and `@modelcontextprotocol/sdk` are optional peer dependencies; `zod` (^3.25, zod 4 not supported yet) is a peer dependency. `createMcpServer` requires the explicit list of tools to expose. The Jev API key is kept in a private field.
- All documentation, planning artifacts and code comments are in English.

### Fixed
- Policy engine: built-in rules (`maxSteps`, `maxTokens`, `budgetLimit`, `maxDuration`, `allowedTools`) were read as missing fields by the generic condition evaluator and never applied — budget, timeout and allowlist policies now deny as documented.
- Regression detector: an event that became a failure (e.g. `action.executed` → `action.failed`) is now a critical regression.
- Trace validator: with `compareStructureOnly`, value differences are reported and give a `partial` status instead of a silent `pass`.
- Golden trace YAML export always quotes strings, so values like `true`, `null` or `123` keep their type.
- The package-level `defineTool` builds a tool without registering it in a hidden module-wide SDK (which also opened an event store on `./events`); the SDK registers it when an agent uses it.
- Approval workflow tests now drive a real agent run through an injected LLM provider instead of calling the OpenAI API with a fake key.
- Lint: 177 Biome errors in older modules fixed (`noStaticOnlyClass` turned off: the static utility classes are part of the tested API); sources formatted; CI uses a valid `npm run format:check`.
